# 文档治理规则

> 状态：当前
> 所有者：仓库级文档体系
> 最近核对：2026-09-23

## 单一文档根

维护文档统一位于 `docs/`。源码旁的 README 只作为用户说明或邻近入口，链接到这里的完整体系；不得在子项目中维护另一套架构、计划和历史目录。

## 文档类型

| 类型 | 内容 | 易变状态 |
| --- | --- | --- |
| `architecture/` | 当前所有权、数据流、不变量和扩展边界 | 不记录阶段进度 |
| `guides/` | 可执行的构建、诊断、导入和验收工作流 | 命令必须可复核 |
| `reference/` | 格式、协议、资产合同、来源和固定标准 | 精确、可检索 |
| `plans/` | 尚未完成的工作、顺序、完成门槛和决策点 | 必须有唯一活动入口 |
| `archive/` | 已完成、撤销、替代或仅代表一次现场的记录 | 不作为当前规范 |

同一事实只能有一个所有者。入口页负责路由，不复制模块正文；指南可以链接 CLI，但不复制完整且易变的 `--help` 输出；计划不能重述稳定架构。

## 文档状态

“最近核对”表示正文确实与源码、脚本或 CLI 对照过，不是普通编辑日期。归档文档应说明归档原因和当前替代入口。Git 提交号只在解释兼容边界时记录。

## 更新规则

- 所有权、主数据流、公共接口职责改变：更新 architecture 和相应入口。
- 命令、脚本、构建或验收流程改变：更新 guide。
- 格式、协议或资产合同改变：更新 reference 及所有生产者、消费者说明。
- 当前执行顺序改变：只更新 `plans/README.md` 和它指向的活动计划。
- 阶段完成、实验撤销或方案被替代：将现场记录移入 archive，并留下当前入口。

## 检查

运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_docs.ps1` 检查 Markdown 相对链接、旧文档根引用和 UTF-8 可读性。文档迁移提交不得夹带运行代码行为变化。
