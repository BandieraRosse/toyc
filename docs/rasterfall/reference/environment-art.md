# 环境资产艺术约束

> 状态：当前
> 所有者：环境资产美术合同
> 最近核对：2026-09-13

本文是首批十件工业 / 军事 static prop 的 **V2 light upgrade** 生产规范。目标是在不重做资产的
前提下，把双色纯色 blockout 提升到可用于正式场景的简洁低模资产。组件清单、尺寸与碰撞建议见
[industrial-props.md](../industrial-props.md)，技术导入流程见 [资产导入与诊断](../guides/asset-pipeline.md)。

## 整体约束

建筑、连接和墙地大面的生产规范补充于
[Architectural Environment V1](../architectural-environment-v1.md)。它沿用本文 palette/轮廓语言，
但建筑件允许低于旧道具的三角形下限；禁止为填预算增加细节。墙地不沿用道具的全表面纹理候选。

- 风格为 **stylized industrial / military**：形体结实、分区清楚、略带使用痕迹。环境负责建立场所
  语义、掩体和路径边界，应衬托动漫角色、敌人与战斗反馈，不以高频细节或高对比花纹抢主体。
- 保留已有外轮廓、实际尺寸、朝向、bottom-center pivot、用途和碰撞预期；V2 不是重新设计。新增
  几何以少量中尺度结构为限，优先选择在游戏距离仍能形成轮廓、凹凸或稳定阴影的部件。
- 不做微小螺丝、密集格栅、细线缆、薄片堆叠和只能在特写中识别的倒角。小于画面数个像素的
  信息优先画进 albedo，完全不可辨认的信息直接省略。
- V2 默认采用 **geometry + flat materials + very limited decal texture**，不依赖复杂 PBR。
  大面分区、主体、框架和功能色使用无纹理材质；纹理只提供局部编号、箭头、安全符号等信息。
  不再使用大面积纹理磨损、油迹、噪声或面板边线，也不做细密条纹。
- 颜色统一在低饱和工业范围内，但按资产用途分组：灰绿、蓝灰、暗灰、土黄可作主体色，深灰用于
  底座、框架、把手和连接件；黄色、橙色、红色、白色只作少量功能点缀。单件通常采用一个主体色、
  一个结构色和一个点缀色，不再全部套用“军绿 + 黄色边条”。同场重复件可用编号、面板色或污迹
  做低成本变化，不改变资产身份。
- 标识保持粗大、简短、可远读：两位编号、方向箭头、危险条或单一功能符号即可。避免细字、品牌
  文案和大面积黑黄条纹；警示色面积应明显小于主体色面积。

## 几何与纹理预算

预算是上限与取舍工具，不是填充目标；资产在实际游戏距离已经成立时应停止加细节。
下表纹理尺寸是历史 full-albedo 上限；Hybrid decal 优先 32×32 或 64×64，确有必要才提高。
不需要标识的组件可完全无纹理，不为了统一而添加编号或伪纹理。

| 级别 | 适用组件 | 建议三角形 | 建议 albedo | 使用原则 |
| --- | --- | ---: | ---: | --- |
| S | ammo_container、crate、barrier | 200–700 | 128×128 | 小体积或大量重复；依靠清楚分区和少数结构件 |
| M | short_wall、railing、workbench、industrial_pillar | 300–900 | 256×256 | 中型遮挡与场景骨架；只保留近中距离可读结构 |
| L | lamp_post、vent_unit、pipe_module | 400–1200 | 256×256 | 轮廓较高或设备层次较多；仍避免细碎曲面与密集切分 |

纹理可按有效表面积与复用需求降一级；纯色小结构件可继续使用材质色。优先共用紧凑图集或重复
色块，控制 primitive/material 数；不要为每个标识拆材质。Rasterfall 使用 CPU 软件光栅化，评估时
同时关注可见实例数、屏幕覆盖、过度绘制、材质/primitive 数和纹理采样，不能只看三角形数量。

## 十件组件的 V2 light-upgrade

下表保留候选设计方向，每项不要求全部做到。若现有轮廓已足够，应优先完成
flat 材质分区而不是填满几何预算；表中的磨损/污迹候选不进入当前 Hybrid 生产。

| 组件 | 建议主体倾向 | 最值得增加的中尺度结构 / 表面信息 |
| --- | --- | --- |
| `rf_crate` | 灰绿或土黄 | 加深两道粗箍与角部护板层次；正面做大铭牌/两位编号；盖板加入一块清楚的压槽面；底缘少量搬运磨损 |
| `rf_barrier` | 土黄或混凝土灰 | 肩部形成两段式护角；正面增加宽浅凹槽或可替换面板；一侧放方向箭头/红白警示块；底脚做轻微泥污 |
| `rf_short_wall` | 蓝灰或暗灰 | 强化压顶与墙身接缝；三条竖筋间加入两块大面板分区；端部做清楚的拼接盖板；下缘积尘而非全表面噪点 |
| `rf_railing` | 暗灰 | 立柱顶部增加粗端帽；横杆与立柱连接处做可读套筒；脚板增加大安装片；局部使用白/黄安全色，不铺满全部横杆 |
| `rf_lamp_post` | 蓝灰或暗灰 | 灯头增加外框与遮檐层次；杆身加入一个中尺度检修盒；底座形成阶梯式基座；灯面用偏白/暖橙 albedo 表示，不暗示真实光源 |
| `rf_vent_unit` | 蓝灰 | 百叶外围增加厚检修框；侧面加入一块大检修门和粗把手；顶部做单一风道/盖板层次；用编号与下缘污迹区分正侧面 |
| `rf_workbench` | 暗灰框架、土黄或灰绿台体 | 台面增加厚包边/后挡条；抽屉侧形成两到三块大柜门分区；底架增加一根清楚横撑或搁板；用工具区色块和编号表现用途，不摆细小工具 |
| `rf_ammo_container` | 灰绿或暗灰 | 强化盖沿与箱体搭接；双锁扣做更清楚的块状层次；侧面加入粗提手座；用白色编号、弹药符号或窄红色封签点缀 |
| `rf_industrial_pillar` | 暗灰或蓝灰 | 柱头/柱脚增加一级承压板；双套环改成不同宽度节奏；柱身加入一块竖向检修面板；低位做方向色带或编号，避免整圈黄色边条 |
| `rf_pipe_module` | 暗灰管体、灰绿或蓝灰底座 | 法兰增加粗厚分段轮廓；双管之间加入一块中尺度连接歧管/支架；底座增加检修盖板；用橙/红流向标记区分管路，不增加细线缆和小阀阵列 |

## 不可变资产契约

V2 必须保持源文件真实米制、Blender Z-up / -Y-forward、导出 GLB Y-up / +Z-forward，以及占地
包围盒底面中心 `(0,0,0)` pivot。对象变换应用后仍为 location/rotation 零、scale 一；稳定 asset ID、
文件名、用途、默认尺寸、`512 RFU/m ÷ 232 RMESH units/m` 展示换算及 profile 驱动碰撞盒均不变。
视觉凹槽、栏杆空隙和台下空间不改变现有碰撞预期。V2 只更新源几何、材质与 albedo 内容，不修改
manifest schema、RMESH/TTEX 格式、importer、runtime 或地图语义。

## 验收标准

V2 通过验收需同时满足：整体观感不再是双色纯色 blockout；近中距离能读出至少一层中尺度结构
和明确表面分区；十件资产共享色彩与标识语言但不会只靠相同军绿和黄边区分；远距离 silhouette、
角色/敌人/交互提示和战斗反馈可读性不明显下降；尺寸、pivot、朝向、碰撞及导入检查保持通过；
同等场景中的帧时间、primitive 数、纹理占用和过度绘制无明显退化。

游戏内验收使用相同光照、近中远距离及多实例条件；离屏取景不替代地图视距验证。
整套生成与安装流程见 [industrial-props.md](../industrial-props.md)。已完成的试点和逐件落地记录见
[环境资产 V2 试点归档](../archive/environment-art-v2-pilot.md)。
