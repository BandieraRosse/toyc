# 环境资产艺术约束

> 状态：当前
> 所有者：环境资产美术合同
> 最近核对：2026-10-05

本文拥有环境静态资产的共同创作风格、表面分区与材质美术约束，沿用首批工业道具的
**V2 light upgrade** 语言，并覆盖建筑、家具、设备与边缘站点套件。组件尺寸与碰撞建议见
[工业组件资产规格](industrial-props.md)，技术导入流程见[资产导入与诊断](../guides/asset-pipeline.md)。
角色造型由[角色美术指南](../guides/character-art-acceptance.md)与各角色设计稿拥有；
武器尺寸与握点由[武器适配规范](weapon-model-adapter.md)拥有。

## 整体约束

建筑、连接和墙地大面的生产规范补充于
[Architectural Environment V1](architectural-environment-v1.md)。它沿用本文 palette/轮廓语言，
但建筑件允许低于旧道具的三角形下限；禁止为填预算增加细节。墙地不沿用道具的全表面纹理候选。

- 风格为 **stylized industrial / military**：形体结实、分区清楚、略带使用痕迹。环境负责建立场所
  语义、掩体和路径边界，应衬托动漫角色、敌人与战斗反馈，不以高频细节或高对比花纹抢主体。
- 保留已有外轮廓、实际尺寸、朝向、bottom-center pivot、用途和碰撞预期；V2 不是重新设计。新增
  几何以少量中尺度结构为限，优先选择在游戏距离仍能形成轮廓、凹凸或稳定阴影的部件。
- 不做微小螺丝、密集格栅、细线缆、薄片堆叠和只能在特写中识别的倒角。小于画面数个像素的
  信息优先画进 albedo，完全不可辨认的信息直接省略。
- 默认采用 **几何 + 纯色常量 PBR 材质 + 少量局部标牌纹理**。旧文中的 flat materials 指
  纯色表面分区，仍参与光照与 PBR；材质分区、平面法线和 unlit 是不同概念。
  大面分区、主体、框架和功能色使用无纹理材质；纹理只提供局部编号、箭头、安全符号等信息。
  不再使用大面积纹理磨损、油迹、噪声或面板边线，也不做细密条纹。
- 颜色统一在低饱和工业范围内，但按资产用途分组：灰绿、蓝灰、暗灰、土黄可作主体色，深灰用于
  底座、框架、把手和连接件；黄色、橙色、红色、白色只作少量功能点缀。单件通常采用一个主体色、
  一个结构色和一个点缀色，不再全部套用“军绿 + 黄色边条”。同场重复件可用编号、面板色或污迹
  做低成本变化，不改变资产身份。
- 标识保持粗大、简短、可远读：两位编号、方向箭头、危险条或单一功能符号即可。避免细字、品牌
  文案和大面积黑黄条纹；警示色面积应明显小于主体色面积。

## 材质创作与当前能力

工业、建筑、设施家具与实验电脑的显式表面绑定由
[`prop_surface_profiles.py`](../../../tools/assets/prop_surface_profiles.py) 同时供生成器与离线刷新
工具使用；边缘站点套件的参数由其生成器持有。具体数值以生产者为准，其他系列保留其作者参数，
不能把渲染器支持 PBR 理解为全库已经完成材质创作。刷新流程见[资产管线](../guides/asset-pipeline.md)。

| 表面 | 创作重点 |
| --- | --- |
| 涂漆、塑料、木面、PCB、陶瓷、标牌 | 非金属；底色表达用途和涂层，粗糙度按表面光泽区分 |
| 橡胶、织物、矿物 | 非金属、高粗糙度；保留大形体和低频分区，避免用噪点填满表面 |
| 裸钢、铝、铜 | 使用相应金属反射底色和金属度；铜保留暖色反射，钢与铝保持中性倾向 |
| 屏幕、灯罩及名为 glass 的静态表面 | 当前常量材质表达低粗糙度的不透明表面；透明板、动态像素和真实灯光由各自表现模块持有 |

- 金属物体上的喷漆区域按非金属涂层处理。需要暗灰框架时先明确它是涂漆还是裸金属，
  不把同一深灰底色直接改成高金属度；裸金属底色表示反射颜色，应使用对应表面预设。
- 光泽与底色分开创作。用粗糙度区分漆面、塑料、橡胶和矿物，不用白色高光或黑色阴影
  烘进大面底色。少量局部标识保持粗大可读，不靠额外材质拆分每个字符。
- GPU 当前消费底色、金属度与粗糙度常量及已有基础色图；普通静态 GLB 导入未贯通
  normal、ORM/AO、emissive 贴图或通用透明材质。材质命名和 Blender 节点效果不等于运行时能力。
  色彩空间、纹理调制及导出限制由[资产管线](../guides/asset-pipeline.md)拥有。
- 金属主要反射直接光，当前环境填充不提供金属环境反射；遮阴处的裸金属可能明显变暗。
  不为补偿这一限制随意改变金属分类或加假自发光。先在正常 GPU 场景检查受光方向、
  法线和镜头，再决定美术调整；光照能力边界见[GPU 光照架构](../architecture/gpu-lighting.md)。
- 新资产仍遵守本套件的 primitive、纹理与几何预算；只补材质时保留现有分区、资源身份和空间合同。

## 几何与纹理预算

预算是上限与取舍工具，不是填充目标；资产在实际游戏距离已经成立时应停止加细节。
下表纹理尺寸是历史 full-albedo 上限；Hybrid decal 优先 32×32 或 64×64，确有必要才提高。
不需要标识的组件可完全无纹理，不为了统一而添加编号或伪纹理。

| 级别 | 适用组件 | 建议三角形 | 建议 albedo | 使用原则 |
| --- | --- | ---: | ---: | --- |
| S | ammo_container、crate、barrier | 200–700 | 128×128 | 小体积或大量重复；依靠清楚分区和少数结构件 |
| M | short_wall、railing、workbench、industrial_pillar | 300–900 | 256×256 | 中型遮挡与场景骨架；只保留近中距离可读结构 |
| L | lamp_post、vent_unit、pipe_module | 400–1200 | 256×256 | 轮廓较高或设备层次较多；仍避免细碎曲面与密集切分 |

纹理可按有效表面积与复用需求降一级；纯色小结构件可继续使用材质色。优先共用紧凑图集或重复
色块，控制 primitive/material 数；不要为每个标识拆材质。当前美术实机验收使用 Windows
原生 GPU Scene，CPU 保留已有软件光栅路径。评估时同时关注可见实例数、屏幕覆盖、过度绘制、
材质/primitive 数、纹理采样和实际帧时间，不能只看三角形数量。

## Research V1 detail tier

[Research Renovation V1](research-renovation-v1.md) 允许独立的冷灰、蓝灰、深灰设备族与少量青白
标识，保持几何、纯色表面分区与少量局部标牌；不使用霓虹、大面积发光或高频材质噪声。
常规设备建议 400–1200 tris；Terminal、Core Analysis Station、Prototype Bench 三件 hero
建议 1200–1800 tris，只有中尺度结构确有需要时允许接近 2200。预算不是下限：形体已成立时
允许更少，壁挂状态与 service 组件尤其不为填预算增加细节。每件 3–4 个 material/primitive。
局部 decal 优先 32×32 / 64×64；也可使用合并到共享 ink 材质的粗几何标识，不按字拆材质。
hero 更高纹理分辨率需要实际画面价值；米制、pivot 和展示换算沿用当前资产合同。

## 十件组件的 V2 light-upgrade

下表保留候选设计方向，每项不要求全部做到。若现有轮廓已足够，应优先完成
flat 材质分区而不是填满几何预算；表中的磨损/污迹候选不进入当前 Hybrid 生产。

| 组件 | 建议主体倾向 | 最值得增加的中尺度结构 / 表面信息 |
| --- | --- | --- |
| `rf_crate` | 灰绿或土黄 | 加深两道粗箍与角部护板层次；正面做大铭牌/两位编号；盖板加入一块清楚的压槽面；底缘少量搬运磨损 |
| `rf_barrier` | 土黄或混凝土灰 | 肩部形成两段式护角；正面增加宽浅凹槽或可替换面板；一侧放方向箭头/红白警示块；底脚做轻微泥污 |
| `rf_short_wall` | 蓝灰或暗灰 | 强化压顶与墙身接缝；三条竖筋间加入两块大面板分区；端部做清楚的拼接盖板；下缘积尘而非全表面噪点 |
| `rf_railing` | 暗灰 | 立柱顶部增加粗端帽；横杆与立柱连接处做可读套筒；脚板增加大安装片；局部使用白/黄安全色，不铺满全部横杆 |
| `rf_lamp_post` | 蓝灰或暗灰 | 灯头增加外框与遮檐层次；杆身加入一个中尺度检修盒；底座形成阶梯式基座；灯面用偏白/暖橙 albedo 表示，不暗示真实光源 |
| `rf_vent_unit` | 蓝灰 | 百叶外围增加厚检修框；侧面加入一块大检修门和粗把手；顶部做单一风道/盖板层次；用编号与下缘污迹区分正侧面 |
| `rf_workbench` | 暗灰框架、土黄或灰绿台体 | 台面增加厚包边/后挡条；抽屉侧形成两到三块大柜门分区；底架增加一根清楚横撑或搁板；用工具区色块和编号表现用途，不摆细小工具 |
| `rf_ammo_container` | 灰绿或暗灰 | 强化盖沿与箱体搭接；双锁扣做更清楚的块状层次；侧面加入粗提手座；用白色编号、弹药符号或窄红色封签点缀 |
| `rf_industrial_pillar` | 暗灰或蓝灰 | 柱头/柱脚增加一级承压板；双套环改成不同宽度节奏；柱身加入一块竖向检修面板；低位做方向色带或编号，避免整圈黄色边条 |
| `rf_pipe_module` | 暗灰管体、灰绿或蓝灰底座 | 法兰增加粗厚分段轮廓；双管之间加入一块中尺度连接歧管/支架；底座增加检修盖板；用橙/红流向标记区分管路，不增加细线缆和小阀阵列 |

## 不可变资产契约

V2 必须保持源文件真实米制、Blender Z-up / -Y-forward、导出 GLB Y-up / +Z-forward，以及占地
包围盒底面中心 `(0,0,0)` pivot。对象变换应用后仍为 location/rotation 零、scale 一；稳定 asset ID、
文件名、用途、默认尺寸、`512 RFU/m ÷ 232 RMESH units/m` 展示换算及 profile 驱动碰撞盒均不变。
视觉凹槽、栏杆空隙和台下空间不改变现有碰撞预期。V2 只更新源几何、材质与 albedo 内容，不修改
manifest schema、RMESH/TTEX 格式、importer、runtime 或地图语义。

## 验收标准

V2 通过验收需同时满足：整体观感不再是双色纯色 blockout；近中距离能读出至少一层中尺度结构
和明确表面分区；十件资产共享色彩与标识语言但不会只靠相同军绿和黄边区分；远距离 silhouette、
角色/敌人/交互提示和战斗反馈可读性不明显下降；尺寸、pivot、朝向、碰撞及导入检查保持通过；
同等场景中的帧时间、primitive 数、纹理占用和过度绘制无明显退化。

游戏内验收使用相同光照、近中远距离及多实例条件；离屏取景不替代地图视距验证。
整套生成与安装流程见[工业组件指南](../guides/industrial-props.md)。已完成的试点和逐件落地记录见
[环境资产 V2 试点归档](../archive/environment-art-v2-pilot.md)。

## 边缘站点工业套件

首个边缘站点使用现有墙、门洞、梁、机器、计算设备与箱组，补充六件原创静态组件。
生成入口见[资产管线](../guides/asset-pipeline.md#边缘站点工业套件)。这批组件沿用真实米制、
底面中心 pivot、GLB +Z-forward、232 RMESH units/m 和 registry 的 512 RFU/m 展示换算。
全部使用 2～4 个不透明常量 PBR material，不新增纹理或灯光语义。涂漆板面、金属框架、
货物涂层与安全色分别声明金属度和粗糙度；岩石保持非金属与高粗糙度。参数由生成器持有，
沿 GLB → RFM2 v2 → Scene 静态道具提交传递，不以颜色推测材质类型。

| 稳定 registry 名称 | 设计尺寸 X/深度/高度（米） | 空间用途 |
| --- | --- | --- |
| `frontier_canopy` | 6 / 3 / 0.4 | 有底梁的屋面单元；显式放在墙顶，组成周边屋顶和入口雨棚 |
| `frontier_cargo_rack` | 4 / 1.8 / 3.2 | 宽货架与整块物资，放在墙边，保持门口和中央搬运道畅通 |
| `frontier_fence` | 6 / 0.32 / 2.5 | 低实体板加开放上栏，替代围界巨墙；三条增援入口留真实缺口 |
| `frontier_collector` | 4.8 / 3.4 / 4.5 | 有双塔和集能顶冠的能源设备，与独立接管柜配合 |
| `frontier_rock` | 4 / 3 / 1.8 | 稀疏外围轮廓与接近区遮挡 |
| `frontier_bollard` | 0.32 / 0.32 / 1.2 | 装卸口防撞柱；少量土黄功能色 |

registry ID 72～77 为表现身份，全部不提供隐式 profile AABB；独立组件碰撞由
`rasterfall_map_components.c` 定义。顶棚以实例高度保留架空通行，围栏分低板、立柱和上栏，
能源设备分底座、机箱、塔体和顶冠。货架所装物资占据其下层，通道安排在货架外侧。
门洞继续使用既有两肩加架空梁的模板，不以屋顶或视觉模型替代地面查询。

仓库和车间采用周边有顶的工作边廊与中央开放搬运/采光带；机器保持现有真实尺寸，
中央地板和单位可以在 RTS 视角直接选择，不引入依赖相机模式的碰撞或任务状态。
