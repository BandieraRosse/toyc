## 结论

这个新地图现在可行，但应按“现实骨架 + 独立玩法覆盖层”推进，第一阶段目标是验证空间节奏和战斗路线，不是宣称还原了武汉大学现场。

可行部分：

- 17舍、18舍、信息科学分馆可以用现有 `rf_campus_wall_plain`、`rf_campus_wall_window`、`rf_campus_window_strip`、`rf_campus_entrance`、`rf_campus_roof_edge` 和 `rf_campus_column` 组成外部体量。
- 广场、道路、操场、草地、屋面与平台可以继续使用现有 surface/primitive，不需要新增铺地模型。
- `rf_campus_stair_short/long`、`rf_campus_retaining_wall`、`rf_campus_curb`、`rf_campus_sidewalk`、`rf_campus_tree_proxy` 足以表达入口高差、边缘、通道和远景识别点。
- 工业/维修类资产可以作为明确的“战时覆盖层”：补给点、临时检查站、维修站和供电设备，不应被解释为校园原生设施。

暂不可行的部分：

- 不能把所有地面设为同一高度后称为现实地形；JSON 中除 A18 约定零点外，高程均未知。
- 不能从 OSM `lanes` 或线宽推导道路净宽；道路宽度、坡度、广场硬质边界和操场跑道细部均未核实。
- 图书馆高度仍未知；17舍的 OSM 18层与工程资料17层存在冲突，正式外壳应先保留可替换层数参数。
- 校园 kit 的 registry 碰撞尺寸为零。玩法碰撞必须在 `.map` 的显式 collision/surface 中单独表达，不能从可见 prop 自动生成。
- 当前不建议直接创建正式 `.map`、spawn、AI 或波次配置；先做独立白盒和路线测试。

## 建议的第一张可玩白盒

地图以 A18（18舍南侧入口）为叙事起点，使用约 `340 × 370 m` 的参考调查范围；这个范围是资料覆盖框，不是最终可玩边界。第一轮只开放中央核心路线，外围保持为不可进入的现实背景或低细节遮挡。

| 区域 | 现实锚点 | 游戏空间职责 | 第一轮实现 |
|---|---|---|---|
| A 18舍入口 | 18舍南入口 A18 | 安全出生、整备、任务接收 | 入口外壳 + 小平台；出生点另用显式 collision/region |
| B 西侧广场 | 18舍西侧广场 | 第一处开阔交战、视线分叉、队伍重组 | 广场 surface、边缘路缘、人行道、少量树代理 |
| C 17舍侧路 | 17舍与广场/北侧道路 | 狭长侧翼、绕行、近距离遭遇 | 17舍低细节体量 + 侧路墙边，不开放室内 |
| D 分馆前场 | 信息科学分馆西/南侧 | 中段目标、半开阔掩体、东西向转场 | 图书馆低细节外壳 + 入口代理 + 临时 relay/control cabinet |
| E 操场北缘 | 操场北侧道路/连接点 ATN | 长距离压迫、最终集结、撤离方向 | 操场 surface + 栏杆/路缘；跑道仅作视觉区域 |
| F 操场内部 | 操场/足球场范围 | 大尺度终局空间或后续扩展 | 第一轮只作为可见背景，暂不配置复杂 AI 波次 |

推荐主循环：`A18出生 → B广场第一次接触 → D分馆前场目标 → E操场北缘集结/撤离`。C区作为可选侧翼，F区作为终局扩展。这样既利用了 18舍—分馆约71 m、18舍—17舍约117 m、分馆南门—操场北缘约71 m 的空间节奏，又不把这些直线距离误当成完整步行路径。

## 设计覆盖层

现实层只负责建筑体量、道路中心线、开敞空间、台阶/挡墙候选位置和远景识别。玩法层单独加入：

- `RF_OVERLAY` 临时 barrier、crate、railing 和 short wall，用来收窄射界、保护施工/维修节点；不移动现实建筑。
- 2—3 个 `control_cabinet` / `power_unit` 组成任务对象链：B区接触、D区主目标、E区撤离确认。
- C区或D区边缘使用 `gate_frame` / `arch_service_panel` 表达临时封控和维修语义，避免把校园原生建筑改造成工业设施。
- 敌人入口只放在已经验证的可走空间；不把建筑 footprint、操场围栏或可见树代理自动当作碰撞。

## 空间节奏与风险

```text
安全出生       半开阔分叉             侧翼压迫       中段目标              长距离终局
A18 ───────→ B 西侧广场 ───────→ D 分馆前场 ───────→ E 操场北缘 ───────→ F 操场
  ╲                ╲
   ╲                → C 17舍侧路（可选绕行/近战）
```

- B区不能只做一块空平面，否则会失去校园空间识别；至少需要广场边缘、台阶/平台候选、树代理和一条明确的人行切线。
- D区不能用工业 doorway 代替真实图书馆入口；入口资产只做白盒识别，真实入口关系待现场核实。
- E/F区的长距离视线适合做压迫和撤离，但会放大高程、道路宽度和 AI 生成点的不确定性。
- 17舍、18舍建筑高度的高置信度只来自工程设计文本；平面 footprint 仍是 LOW，因此建筑应允许整体替换，不把细部窗格当现实证据。

## 实现顺序

1. 仅在独立实验场景中搭建 5 个 surface 区域和 4 个建筑体量，所有地面高度暂标为“设计占位”，不要写入正式现实高程。
2. 用现有 campus kit 生成外壳、台阶、挡墙、路缘和树代理；用 `campus-corner` 组图检查模块拼接，不增加新的纹理体系。
3. 另建玩法覆盖清单，再为可走面和阻挡面写显式 collision；校园 prop 保持 `collision=none` 的语义。
4. 用可视化布局查询检查 A/B/C/D/E/F 的相对位置，再用无窗口逻辑测试验证出生点、目标链和撤离状态。
5. 只有在补齐高程闭合链、道路宽度、广场硬边界和图书馆高度后，才把实验布局收敛为正式 `.map`。

## 进入正式地图前的门槛

必须补齐：

- A18—广场—17舍—分馆前道路—操场北缘的闭合高程链；
- 主要道路的车行净宽、人行带、路缘和入口瓶颈；
- 广场硬质铺装边界、台阶数量/踏步高度和挡墙位置；
- 图书馆现状高度、三栋建筑外轮廓的现场控制点；
- 操场跑道/足球场边线与北侧连接口的可复用尺寸。

在这些资料到位前，建议把本 V0 当作“玩法空间设计稿”和“可撤回白盒”，不当作武汉大学的工程复刻，也不提交为正式地图事实。
