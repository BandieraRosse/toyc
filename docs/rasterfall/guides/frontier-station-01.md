# 边缘站点 01：玩家操作与验证入口

> 状态：当前
> 所有者：Rasterfall 行动地图
> 事实入口：`rf_frontier_session.inc`、`rf_frontier_mission.c`、`rf_player_commands.c`

## 进入与编队

在前哨站靠近中央指挥桌南侧，面向桌子按 E，再选择“边缘站点 01”部署。
本图只接受离线模式。南门右侧返回终端沿用 E 交互；暂停菜单也可返回前哨站。
重试会重新建立守军、小队、设施权限、有限供给及任务阶段。失败后可按 R 重试，或按 Esc 打开菜单返回前哨站。

开发时可直接加载正式地图：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows/NativeCodex.ps1 run --renderer gpu-scene --map rasterfall/assets/maps/frontier_station_01.map
```

玩家与五名队友均为二级。玩家带 AK 和手枪；队友分别携带三把 AK、一把 AWP 和一把霰弹枪。
按 M 切换 FPS/RTS，数字 1 选择两名突击队员，2 选择支援、侦察和近战队员，3 选择全部五名队友。
编组不包含玩家，玩家仍可单独选择。右键指定目标、停止及重新编组遵循现有[RTS 操作](player-ui-v2.md#rts-核心指挥)。

未下达移动命令时，五名队友自主跟随玩家，保持分散落点，受阻时沿领队走过的路线收成纵列。
领队失去行动能力后由存活成员接替，队友仍可自动救援。显式移动或停止命令持续保留指定岗位，
优先于自动队形；Y 的“跟随单位”控制俯视镜头。反击枪手按两支三人小队推进，接敌后各自追击和射击。

## 行动与设备

先肃清南门、仓库、车间和能源区的十三名守军，包含车间二楼新增的一名 AK 枪手。进攻阶段每二十秒有一波感染者从北、东入口交替进入，
感染者也攻击枪手。任务提示中的守军数只统计本次初始守军，不使用全局击杀数。

初始守军清空后进入四十五秒整备。靠近三处设施终端并面向设备按 E 接管：车间开放网格编织机，
仓库开放 CPU 和存储，能源开放供电与 X1。接管状态保留；再次按 E 不补充储能或其他库存。
三设施都接管后，车间终端可按 E 打开正常制造界面，选择蓝图、开始制造并领取真实成品。
供给有限，设备开关也不重置资源。普通弹药补给交互同时补充附近两米内队友的对应库存。

整备结束后，三批感染者累计三十六名，西侧两批枪手累计六名。枪手和感染者互相敌对。
预定增援全部成功入场、任务敌人清空、三处设施已接管后胜利。胜利后可继续使用地图和设备，
不会开始无限波次。玩家倒地时队友仍能救援；所有可行动友军失去战斗能力才判任务失败。

倒地后可在 RTS 选择存活队友，右键玩家附近同层、无遮挡的地面，保持游戏运行并停止重复下令。
队友到位后约三秒自然救援；新移动或停止指令会取消正在进行的救援。胜利后仍可救回玩家并继续行动。

工厂转移到庭院迎击枪手时，先让五名队友靠拢，再与玩家共同推进；玩家单独先到会暂时失去
小队火力。注意队友换弹状态，利用建筑和门口遮挡等待支援。本轮普通路线既出现胜利也出现
全队倒地，不把同一移动路线视为保证获胜的策略。

NULL 通讯显示身份与字幕，随任务事件自动推进，不接管玩家输入。当前远程视频明确不可用，
首图没有额外的 NULL 实体或并行前哨世界。

## 车间楼层 V1

车间有一层、二层及可走屋顶。东北角为内部折返楼梯间，从车间内朝北的入口进入，
沿西侧踏步上到半层平台，再折返沿东侧到上层；同一结构继续连接屋顶。外侧大斜坡已移除，
外墙、层间楼板与独立楼梯顶盖闭合。两层使用稀疏吸顶灯，楼梯间每段梯段保留一盏前下向壁灯，平台不另加灯。
二楼南窗有一名驻守枪手，使用真实高度射击并计入守军清零条件。楼板保留厚度和遮挡，楼下仍可通行。

按 M 进入 RTS，顶部点击“车间一层”“车间二层”“车间屋顶”切层。选中队员后在当前层地面右键，
队员通过真实楼梯到达指定高度；切层保留选择和编组。“全貌”恢复完整屋顶及原镜头，
“聚焦单位”靠近主选队员并跟随其所在楼层，Y 切换跟随主选单位（没有主选时跟随玩家）。
点击建筑可查看屋顶，滚轮拉近自动进入楼内，拉远回到全貌；显式楼层按钮适合精确下令。
CPU 也提供即时楼层切换，GPU 提供渐隐剖切。剖切不移除光照遮挡，灯面自发光与照亮空间的光源
遵循同一模型绑定；GPU 自然光说明见[光照指南](gpu-lighting.md#天空太阳反弹与车间自然光)。

原生定向检查：`python tools/rts_floors_check.py`；三层固定 GPU 取景使用
`--gpu-normal-scene frontier-floor-1|frontier-floor-2|frontier-roof 0`。
外墙与内部楼梯 FPS 检视可使用 `frontier-exterior`、`frontier-stairs`、`frontier-stairs-upper`；
`tools/frontier_station_capture.py --views exterior stairs stairs-upper --output-dir tmp/workshop-views` 保存定向证据。
跨层移动回归不替代升级后完整任务重跑或性能签收，验证结果记录在当前计划中。

## 行动验证

稳定计时、实体身份、成功配额、接管和清理合同进入原生逻辑回归。地图位置与镜头布局以实机操作验证，
不冻结为固定坐标测试。美术取景工具为 `tools/frontier_station_capture.py`；诊断取景不能替代普通玩家行动路线。
`tools/frontier_station_playcheck.py` 通过正常 Win32 输入与只读审计记录行动，检查结果须与实际日志、退出码和截图一起复核。

`RF_FRONTIER_AUDIT=1` 输出任务、设备、角色身份与位置的只读 JSON，供本地验证使用。
它不修改 Game，不是普通 HUD 的敌方定位来源。性能采样须另外关闭逐帧审计和截图，并记录同一 executable、
分辨率、设置、行动阶段和存活规模；Game 隔离移动基准不能作为实际 FPS 结论。
