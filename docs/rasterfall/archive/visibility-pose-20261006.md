# 建筑查询、动态裁剪与姿态准备优化

> 状态：历史现场，2026-10-06
> 归档原因：记录本轮实现、实机证据和收益范围，不作为稳定架构合同
> 当前入口：[GPU 光照架构](../architecture/gpu-lighting.md)、[GPU 渲染架构](../architecture/gpu-rendering-architecture.md)、[动画架构](../architecture/animation-architecture.md)、[同包对照指南](../guides/gpu-lighting.md#保持画面的光照性能对照)

此次按性能审查的前三项优先级处理建筑可见性查询、GPU 蒙皮前裁剪，以及 CPU 重复求值与绘制准备。
比较基线是 `e719c2f` 的已暂存程序。保留灯光、建筑遮挡、阴影、画质与动画采样时间。

## 最终实现与取舍

- 硬件片元建筑查询利用仅含不透明三角形的 AS，一次 `rayQueryProceedEXT` 完成遍历；保留循环变体
  作为同包对照。BOX 仍是 12 个表面三角形，射线起点、法线偏移、有限长度、双面和首命中规则保持一致。
  软件 BVH 与 DDGI 查询保持原路径。该优化只是减少查询控制流，没有减少有效建筑射线的数量。
- 从 bind 顶点的骨骼影响建立分骨 AABB；每次 palette 更新计算当前姿态的保守总边界，覆盖两骨混合、
  FP32 整数转换和计算舍入。非法或无法表示的输入退回完整绘制，屏幕来源不参加资源级裁剪。
  每个主/AUX consumer 独立生成相机和阴影位图；完全无人消费时省略蒙皮 dispatch，镜头外阴影仍可消费。
  submit 成功只提交实际录制的蒙皮缓存，未消费的封存更新在所有消费者退休后取消。
  staging 的未提交 bind 数据保留并随下一次 palette 更新重放，避免取消后使用旧绑定。
- 独立角色来源一次验证整个 roster；按来源槽保留独立 instance，仅在完整局部求值输入相同时复用
  composition/IK。世界位置、朝向、灯光和当前帧元数据仍重建；完整时间与身份变化会使 actor 求值缓存失效。
  各 pass 共用可见性位图，材料模式移出 primitive 循环，零自发光值直接编码为零。

曾试验最近固定灯 BOX 预检，两个镜头的 GPU 时间都增加约 0.47 ms，已撤销。
从光源端反向发射同一建筑线段没有获得稳定改善，也已撤销。未保留这些实验开关或数据字段。

`tmp/first-three-validation/`。临时日志、截图与程序副本不提交。

- Windows native 构建成功；此前硬件/软件完整 graphics 回归及非融合蒙皮路径通过。
  最终补齐 staging bind 重试后，强制 staging 的完整 Core/Synchronization 回归通过 7176 checks；
  准备专项、非融合路径、公开姿态和 120 帧 native generation 再次通过。
- 新增独立 CPU 顶点/画面对照，覆盖不同骨骼位移的混合权重、当前姿态进入相机、全隐藏保留封存、
  AUX 独立相机消费、镜头外阴影消费和取消后的重新上传。准备专项确认同步验证激活且无 VUID/同步错误。

建筑查询追加 45 秒间隔的车间二层同包 AB/BA 两轮，各 120 帧预热后采样 240 帧，

15.959/15.959 ms，两轮统计中位数只差 0.025 ms，端到端没有稳定单轴收益。
控制流优化保留，但它没有解决局部建筑射线的主开销。证据位于 `tmp/first-three-ray-cooled/`；
保留循环变体的普通/计数 SPIR-V 数组均与基线字节一致，其余原有数组也未改动。

## 仍有成本的路径

局部灯的建筑射线仍是 WORLD 的主要 GPU 成本；单次遍历只带来小幅收益。
CPU 姿态提取和 palette 主机复制仍先于资源级可见性判定；同包关闭动态裁剪不能撤销共享位图的
录制准备优化，关闭 pose reuse 也不能撤销批量 roster 验证。不能把三个单轴的差值相加作为整组收益。
当前 Scene 仍为单槽，native present 后立即等待 retire；该等待与 GPU 执行重叠，不与 GPU 时间相加。
