# V22h 保真诊断现场（2026-09-30）

> 状态：历史验证记录，不定义当前实现
> 当前入口：[角色保真诊断](../guides/character-fidelity.md)

冻结源为 V22h GLB，SHA-256
`2ba400bd99fd02c2e5394f4667fb658726fa35c8f9fef6a13fd0c9f88fe3a79f`。
51,984 顶点、74,596 三角形、49 骨骼、19 材质；无图片或纹理。未修改头部、头发或眼部源几何。

## 归因

| 局部存储 | 精确退化三角形数 |
| --- | ---: |
| GLB 源 | 181 |
| 512 格/米 | 16,896 |
| 8192 格/米 | 1,800 |
| 65536 格/米 | 840 |

65536 档剩余退化面中 812 个属于衣服材质，眼白 16 个、皮肤 10 个、头发 2 个。
源中的 76 个重复面也属于衣服材质。计数含极小拓扑，不等于同数量的可见缺陷。
三个虹膜材质在 512 档共退化 104 个三角形，在 65536 档为零。

虹膜边界范围的正面平行射线中，原 GLB 的 4,328 次虹膜命中没有与脸/眼白在 0.1 微米内重合；
512 档出现 2,198 次重合，65536 档为零。脸/眼白在虹膜前的命中数分别为 802、1,419、801；
正常眼睑遮挡包含在其中，不能将这些数都解释为穿插。

保留 65536 资产和浮点变换，只恢复倒数深度量化，正面 384 RFU 的固定中心区域改变 3 个像素，
1536 RFU 改变 271 个像素。近景原始眼周碎裂的主要证据指向导入坐标损失，深度量化对远距离
仍有独立影响；不能把所有异常归为一个 shader 表达式。

## 本次验证

- Windows native 构建和完整逻辑回归通过。
- 原生 graphics 测试 114 项检查通过：包含旧深度桶顺序依赖、新深度顺序稳定、局部单位换算等价、
  平滑/无光照、过滤、层序及资源复用。
- 公开 RFCHAR 材质/精度回归 11 个用例通过；V22h 高精度产物通过原生 runtime 与实例隔离检查。
- 同一运行包完成三视图乘六显示模式；384/1536 RFU 分色捕获、528 帧缓慢绕转拉远正常退出。
- 三视图的分色 draw 逆序对照在矩形 `[400,180,850,590)` 内均为零像素差异。
- Blender 重新导入同一 GLB，输出三视图的无光照、材质分色和 studio 参考。

本地证据目录为 `tmp/character-fidelity/`，其中 `before-after.png` 左旧右新，`review.html` 汇总图像，
`geometry.json`、`surfaces.json`、`evidence.json` 和各捕获目录的 manifest 保存输入、哈希和结果。
原 512 资产保存在该目录；本地实验场安装产物为 65536 档、标准 sRGB 与显式 visual roles，SHA-256
`03b573d04b7a1d583de3e1cd2fff1c15747ba06038321f91be3c96456e622038`。
角色源与产物仍为私有内容，不提交到仓库。

CPU 旧固定 BMP golden 的额外抽查发现，即使用旧颜色转换，本机 Blender 5.2/Windows 输出也不等于
该测试记录的 Blender 4.3.2 历史哈希，因此未用这次结果覆盖它、也未宣称该旧 golden 通过。
当前结论来自上列原生逻辑、合同、GPU 行为测试及同包对照。

这不是整个角色计划签收：当前分色是材质 ID；连续脸/眼睑共用材质不能单独分色。
无纹理样本不能证明角色纹理/MASK，studio 与基础漫反射也不要求逐像素相同。
造型继续冻结，后续再按侧面脸型、头发体积、眼部纹理的顺序推进。
