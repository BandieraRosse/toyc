## 计时口径

主线程 CPU 占比 = 匹配帧窗口累计 GetThreadTimes(kernel+user) / 累计 begin-to-begin 墙钟。
它是一个主线程占用一个逻辑处理器的时间比例，不是整机 12 线程利用率，也不含音频与驱动其他线程。
CPU 起止点连续，累加后抵消中间离散记账；单帧 0/15.625ms 不作为单帧 CPU 百分比。
每轮量化端点不确定度估计上限为 31.25ms / 该轮采样墙钟，另有 OS 记账与调度影响。
下面各细分是墙钟，包含抢占和相应函数中的同步等待；不能把它们称为各项独占 CPU 时间。
等待 GPU 的 retire 与 GPU timestamp 重叠，不能相加。主准备中的蒙皮 batch、敌人几何/上传、
图层提取/裁切/打包/上传均为嵌套项，另外列出，不重复计入一级分解。
一级阶段按同一批完整帧求均值，保留 active 未覆盖部分及帧间节流/调度，完整闭合到帧间隔。

## 原始证据

本组是低扰动确认组。此前另完成四场景各三轮逐三角形细分、两轮无细分对照，
见[详细诊断组](cpu-profile-detail-20261007.md)。两组共 32 次有效运行，
14,400 条匹配 CPU/阶段样本；独立重读确认帧 121–840 连续、GPU query 属于同帧、GPU 时间非零，
一级墙钟逐帧精确闭合，两组 EXE 和全部 246 个运行资产文件的 SHA-256 相同。
程序实际选中 NVIDIA index 1、queue-family 0；所有运行均退出 0、SCENE-PERF valid=1。
验证记录见[verification.json](../../../tmp/cpu-profile-20261007-coarse/verification.json)。

前哨站详细组图层准备均值 2.604ms，本组为 1.555ms；详细组整帧均值 15.970ms，
本组为 14.829ms。两组 GPU 均值分别 7.741/7.952ms。这支持逐三角形读时钟产生明显扰动，
不能把详细组的 53.9% CPU 占比直接当作普通前哨站占比。轻场景两轮本组仍有较大波动，
占比 70.3–78.1%，应保留范围而非认定精确固定的 74.4%。

本机在持续原生负载下升至 86–87°C，前哨站和车间有明确 GPU 热限频记录；
数据描述本次实际热机条件，不能作为恒温、锁频或正式五轮收益签收。

这组旧地图轻场景仍有 27 个正式 actor，并非空场景。即使活感染者为零，
敌人/程序角色准备仍为 5.871ms，几何提取占其中 5.022ms、上传 0.770ms；
初始 60 敌人组实际存活 3–58，准备 6.261ms，其中几何 5.311ms、上传 0.847ms。
所以应调查这条共享动态来源的 CPU 几何生成，而非只依据活感染者数量估算成本。
前哨站主要 CPU 阶段为图层 1.555ms、录制 0.966ms、WORLD 0.779ms，
pose 和 actor 准备各约 0.73ms。车间 pose 与 actor 准备各约 1.3ms，
但 retire 17.870ms、GPU 17.643ms，占整帧的等待明显更大。

CPU 占比是 GetThreadTimes 的真实线程活跃时间；阶段表是墙钟，驱动调用中的忙等可同时
消耗 CPU 时间和等待 GPU。因此 CPU 占比不能再与 retire/GPU 百分比拼成互斥的 100% 分区。
