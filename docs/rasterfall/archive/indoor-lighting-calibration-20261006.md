# 前哨站室内亮度初步校准

> 状态：历史验证记录，2026-10-06
> 归档原因：记录本轮参数、设备和限定画面，不作为全场景照度标准
> 当前入口：[GPU 光照](../architecture/gpu-lighting.md)、[建筑语法](../reference/architectural-environment-v1.md#标准房屋生成语法)、[地图格式](../reference/map-format.md#v1-render-记录)

用户确认上一轮 DDGI 改善了室内，但整体尤其上部仍暗，要求初步接近普通现实室内照明的亮度。
本轮工作区证据在 `tmp/lighting-calibration/`，原图保留在 `tmp/ddgi-refine/final-visual/`。

## 改动与观察

- 楼板原先共用上下表面颜色，天花板因此沿用楼上地板的深色基础色。新增 BOX 的
  `attr.bottom_color`，经 Parser/Runtime attribute、绘制投影、Scene 静态缓存和 GPU 建筑元数据
  同步到可见底面与 DDGI 反射率。颜色不通过单独 GI 增益放大；零值可明确表示黑色。
- 前哨站天花板使用 `E3E6E8`，室内墙面使用 `B4C0C5`；地板仍使用既有蓝灰色。
  楼梯平台/顶盖也独立指定底面色。凹槽、封闭楼板、渲染记录数量和 collision 几何保持不变，
  仍是 640 条 render；生成器重复执行字节相同。
- 顶灯相对强度由 48 调到 72，配光 outer/inner cosine 从 0.20/0.65 调到 0.05/0.50，
  颜色由 (0.88, 0.95, 1) 调到 (0.95, 0.98, 1)，扩大上部墙面的覆盖并减弱冷色偏移。
  灯数、作用半径、射线数及反弹上限不变；曝光继续为 1。
- 最后复核发现楼梯仍偏暗，再将壁灯相对强度从 24 调到 48，outer/inner cosine 从 0.15/0.70
  调到 0.02/0.45，颜色由 (1, 0.83, 0.64) 调到 (1, 0.90, 0.78)。台阶和背墙可辨，保留暖色与遮挡。
- `final-visual/` 保存最终实现的 B1、一层、二层、楼梯和研究翼正常 Scene 镜头，1280×720、固定天空、
  NVIDIA 原生窗口。天花板和上部墙面明显更易辨认，地面与家具保留细节，灯面没有恢复共面黑纹。
- `v1/` 和 `direct-only/` 是最终壁灯调整前的同版本 GI 开/关对照：关闭 GI 后天花板重新变暗，证明上部提升依赖真实表面反弹。
  浅色表面也暴露了原 DDGI 在局部墙角的插值不均，二层后墙和地下层墙脚仍有局部明暗折线。
  本轮没有据此放宽遮挡或添加无来源的环境光。

固定天花板区域 `(240,60)–(1100,160)` 的输出 RGB 加权亮度中位数（0–255）：

| 镜头 | 调整前 | 调整后 |
| --- | ---: | ---: |
| B1 | 9.9 | 70.0 |
| 一层 | 20.2 | 99.8 |
| 二层 | 19.8 | 103.9 |

这些是截图显示值，经过色调映射与 sRGB 编码，仅用于复核相同区域变亮；不是照度、物理能量比
或任何场景的验收阈值。当前光强仍是相对单位，本轮未声称完成流明/lux 或自动曝光系统。

## 验证

- Windows native 构建和完整逻辑回归通过，见 `logic.log`；壁灯 profile 最终调整后的构建见 `build-final.log`。
  新增 `BOX-FINISH` 覆盖 Parser、Runtime、
  绘制投影的缺省、大小写十六进制与显式黑色；闭合楼板用例验证底面色不会改掉其他面的颜色。
  初次专项失败是新 fixture 未纳入 package，已补齐 `windows/Makefile` 暂存规则并重跑通过。
- `python tools/test_building_kit.py` 通过，嵌灯跨板裁分仍保留底面色，玩法记录不被裁分修改。
- NVIDIA hardware/software 和 AMD auto 的 `--gpu-lighting-test` 均通过。新增 `BOX REFLECTANCE PASS`
  保护白底面产生反弹、显式黑底面吸收光以及其他面不会替代底面色；NVIDIA 两路径 RGB 总和一致。
  原有纯反弹、隔板零漏光、动态注入、来源去重、历史衰减、resize 和拒绝无效替换均继续通过。
- 14 个嵌入 SPIR-V 模块通过 `spirv-val`；原生 1080p 同步检查实际加载 validation 和
  Synchronization，检查 VUID、SYNC-HAZARD、退出码与正常帧 bridge/readback。

## 成本

`perf-final/` 使用 RTX 3050 Laptop、1920×1080、`outpost-light-1f`、0 敌人，三轮交替前后版本；
每轮预热 120 帧、采样 240 帧，关闭 validation、capture 和片元计数。前后各使用对应颜色地图，
几何和模型资产相同；原始命令、EXE/map 哈希与逐轮结果保存在该目录。
`perf/` 是补充壁灯调整前的三轮采样，单独保留，不混入最终结果。

各轮指标的中位数，单位 ms：

| 版本 | GPU P50 | 整帧 P50 | 整帧 P95 | 整帧 P99 | 探针更新 P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 调整前 | 9.800 | 16.633 | 18.035 | 20.026 | 0.191 |
| 最终校准 | 9.575 | 16.517 | 17.406 | 18.128 | 0.193 |

三轮配对 GPU 差值为 -0.185/-0.229/-0.176 ms，未观察到此次亮度校准的性能回退；
该小幅差值没有单独做因素归因，不宣称普遍提速，也不外推全场景稳定帧率。
最终 EXE SHA-256 为 `7231EB40BA890CB63BD2A5D7CC993BA8DF561AC29444810288AF665D24C526A2`。
最终运行目录已恢复校准后的地图，与仓库地图及构建 EXE 核对一致。
