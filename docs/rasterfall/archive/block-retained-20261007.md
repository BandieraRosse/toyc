# 程序 Block 角色常驻几何：2026-10-07 原生记录

> 状态：历史现场，2026-10-07（本轮实现与限定验证完成）
> 所有者：Rasterfall GPU Scene
> 归档原因：记录一次同包性能对照及验证边界，不作为当前架构规范。
> 当前入口：[GPU 资源合同](../architecture/gpu-rendering-architecture.md#程序角色常驻几何)、[对照指南](../guides/rendering-performance.md#程序-block-常驻几何对照)。

## 范围与结果

根据[主线程 CPU 实测](cpu-profile-20261007.md)，本轮优先减少旧地图的敌人/程序角色来源成本。
标准 Block 身体、武器与职业装备保留 bind 网格，逐帧只求动作、IK 和变换 palette，交给已有
GPU skin batch。普通感染体的程序几何、WORLD 光照和多帧 pipeline 不属于本轮改造。
默认启用，`RF_GPU_BLOCK_RETAINED=0` 在同一程序内选择原动态三角形路径。

旧地图 27 actor、零感染体的程序来源阶段由 5.97 ms 降到 1.43 ms，整帧由 16.81 ms 降到
12.54 ms；初始 60 感染体组整帧由 18.32 ms 降到 13.86 ms。这里是五轮各自均值的中位数，
对应整帧改善 25.4% 和 24.3%。十个轮内场景对照的整帧均值全部改善。

## 同包性能条件

- Windows 原生，Ryzen 5 5600H、NVIDIA RTX 3050 Laptop、1920×1080，正常实时玩法。
- 两个场景、两种路径、五轮 AB/BA 交替，共 20 次有效运行；每次预热 120 帧后取 720 个匹配
  帧，共 14,400 个样本。阶段使用轻计时，关闭逐三角形时钟；性能组不截图、不加载验证层。
- 每张样本校验连续帧身份、scene/query 对应和有效 GPU 时间；线程 CPU 与整帧使用同一窗口。
  检查期间未发现工具监控名单中的其他编译/游戏进程，不能据此排除所有系统背景负载。
- 运行前后 240 个程序、配置与资产文件哈希一致；程序 SHA-256：
  `9b73686a9d960863df1601f2519cfa936eebfefdf5b0fe2c0b7ba16eb6790aa5`。
- 温度记录包含启动阶段的 77°C，后段多为 86–87°C、最高 88°C，并出现 thermal slowdown。
  AB/BA 降低顺序影响，但不是锁定频率实验；结论限于本机这轮持续负载。
- 压力组按实时推进，旧路径实际存活 3–57，新路径 13–59。新路径完成相同帧数所需墙钟更短，
  两组不是相同感染体数量轨迹；零感染体、27 actor 组是更干净的结构优化证据。

复现命令：

```powershell
python tools/gpu_block_retained.py --output tmp/block-retained-perf --rounds 5 --samples 720
```

文档维护，本轮未测实际峰值显存。前哨站和车间没有追加常态性能对照，不外推上述百分比。

## 几何、画面与生命周期验证

Windows native doctor、构建并暂存通过。公开 `--gpu-scene-pose-test` 配合
`RF_GPU_POSE_PUBLIC_TEST=1` 通过现有公开姿态/衣物缓存回归和新 Block 几何回归：
全部职业、武器（含无武器）和动作共 720 组，覆盖移动、瞄准、开火、倒地、死亡、复活，
并检查颜色、三角形顺序、数量、失败传播和不支持来源。最大位置误差为 2 RFU，门槛为 3 RFU。
这反映 CPU 分步取整与 GPU 合并 FP32 求值的区别，不能宣称逐像素相同。
证据：[公开姿态日志](../../../tmp/block-public-pose.out)、[构建日志](../../../tmp/block-build-final.log)。

完整私有 RF-C01 姿态组另有尝试，但因本机缺少 `rf_c01_v028.rmesh` 未通过其既有握持测试；
没有以替代模型或放宽断言计为通过。新 Block 覆盖使用公开资产，不依赖该模型。

四个固定 tick 镜头在同包两条路径各截图一次，并检查成对画面；身体、武器、装备与动作构图
保持对应，存在轮廓和着色边界细小变化。变化像素计数排除左上 240×100 的 FPS 区；RGB 平均
绝对差按全图计算，单位为 0–255。此组不进入正常性能统计。

| 镜头 | 变化像素占整图 | RGB 平均绝对差 |
| --- | ---: | ---: |
| near0 | 1.841% | 0.0893 |
| near60 | 0.597% | 0.0480 |
| actor-procedural | 6.796% | 0.4844 |
| actor-actions-lab | 0.385% | 0.0267 |

证据：[截图身份](../../../tmp/block-captures/report.json)、[像素统计](../../../tmp/block-captures/pixels.json)、
[成对画面](../../../tmp/block-captures/compare.png)。最大单通道差可达 227，不能用全图低均值掩盖轮廓差异。

Khronos validation 与 synchronization validation 均确认加载，完成单位 AUX、双 AUX、
强制 staging 三组短程运行（分别 14、5、15 帧），主动发送窗口关闭并正常释放；五种
acquire/record/submit/present 故障在第 2 帧注入，退出码符合原合同，无 VUID 或 SYNC-HAZARD。
验证层把复杂场景放大到每帧数秒，因此短程验证只签收本次运行覆盖的同步和释放。
此前一个长验证尝试由测试工具主动终止，未计为通过；上述重跑正常退出。
证据：[验证层与故障报告](../../../tmp/block-lifecycle-v2/report.json)。

关闭验证层后另跑持续辅助视图：单位视角、双视图各 121 个稳态样本，`UI-PERF valid=1`；
单位视角刷新 19 次，双视图两个槽分别刷新 31、30 次，有效 GPU query 对应。
本次双槽刷新采用错峰调度，不宣称同一帧同时刷新已覆盖。
证据：[辅助视图报告](../../../tmp/block-aux-continuous/report.json)。

既有 `gpu_scene_play.ps1 -Stage World` 原生换图检查通过 120 帧，在第 30、60、90 帧切换世界，
连续 native/source 帧身份通过，覆盖 world generation 变化后的重建与释放；此组未开验证层。
证据：[换图日志](../../../tmp/block-world-cycle/world-cycle.out)。
