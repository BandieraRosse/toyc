## 范围与方法

延续[上一轮全景测量](panorama-performance-20261003.md)，本轮实现 GPU 显示几何常驻、同资源
相同 palette/敌人冻结值复用、静态 world freeze 缓存及 ID 哈希校验。资源不变时省去生成/复制/
上传，变化时按对象重建；不降低天空质量、不删模型，不引入多帧 pipeline。

Windows native、RTX 3050 Laptop GPU、默认 1280×720、正常 120 FPS 节流及 native present、
固定天空时间 0。`gpu_performance_lab.ps1 -Stage Panorama -Rounds 1 -Capped -CompareBackend
-ProfileSlow`，每种展示状态依次参考/优化，各五个观察点，保留完整背景。按用户要求尽快收尾，
本轮只做一轮成对初测，尚未执行多轮反转顺序和 1080p 扩展。

同构建参考侧关闭四种准备缓存，保留上一轮 CPU quad 缓存；两侧共用新 ID 校验，不等同旧提交
二进制。慢帧记录开启，原有角色成本日志也存在；低扰动签收应另测。全景总值按实际采样帧数加权，
不同视角各固定时间，不能把它当作相同帧序列的严格 A/B。逐视角结果用于补充判断。

证据目录：`tmp/scene-preparation-panorama/` 的 config、hashes、report 和各 stdout/stderr。
采样 exe SHA256：`2BE946B98EB4E464605B1A1B364F5AD1A13D66AA5062EDCDF3F0AAB35ABC9D88`。
采样后仅修正 CPU 缓存分配失败时的回退分类，正常分配成功路径未变；最终构建另做 native 回归。

计算机近景的展示准备：关闭展示 **5.556 → 1.674 ms**，全开 **5.771 → 1.788 ms**。
全开计算机近景平均帧耗时 **23.339 → 15.163 ms**，但 P95 仍为 **17.525 ms**；光照视角
P95/P99 为 **17.455/26.460 ms**。关闭展示的大厅/天空点 P99 也有 **17.811 ms**。
因此只能说准备成本和本轮总体分布改善，不能宣称所有视角稳定 60 FPS。

逐三角形裁剪计时另用 `RF_GPU_SCENE_PROFILE_LAYERS=1` 定位，明显扰动提取阶段；上表未开启。
新增慢帧记录已观察到 retire 墙钟时间明显超过 GPU 时间的帧，但它可能包含驱动等待与调度，
不能仅凭当前线程 CPU 时间推断系统原因。后续归因与缓冲策略留在活动计划。

## 验证边界

- Windows native 构建通过；初次高并行构建遇到临时磁盘空间不足，降低并行度后成功。
- 完整逻辑回归通过，包括新增快照热缓存、内容/世界代数/空气墙变化、独立值所有权及失败原子性。
- Scene frame 独立测试通过，覆盖满容量唯一 ID 和末尾重复 ID；修正该 Windows 测试目标的 hosted 头文件及 memset 链接配置。
- GPU 准备测试直接上传和强制 staging 路径各 103 项检查通过，覆盖几何/颜色更新、设备顶点比对、相同 palette 无提交，以及取消更新后重新计算。
- 最终构建的计算机侧面、全展示电子区各一次新旧路径对照，1280×720 Scene 捕获逐像素一致；
  native 世界切换 120 帧、死亡 100 帧、特效容量涨落 4 帧、连续战斗 160 帧均通过，检查实际退出码和帧审计。
  证据：`tmp/outpost-perf/scene-final-*`、`tmp/scene-preparation-world/`、`tmp/scene-preparation-combat/`。
  最终 exe SHA256：`AD9BD26EC8780CD4691128E479325D2F36A21503376026209F212670DF43C9B5`。
