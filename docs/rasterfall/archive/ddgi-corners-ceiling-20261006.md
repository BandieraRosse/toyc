# DDGI 墙角、嵌灯与闭合楼板优化现场

> 状态：历史验证记录，2026-10-06
> 归档原因：记录本轮设备、场景与版本的结果，不作为稳定架构
> 当前入口：[GPU 光照](../architecture/gpu-lighting.md)、[验证指南](../guides/gpu-lighting.md)、[建筑语法](../reference/architectural-environment-v1.md#标准房屋生成语法)

用户要求继续降低光照成本、改善 DDGI 墙角，并让同高吸顶灯替换原天花板体积，消除干涉。
工作区证据在 `tmp/ddgi-refine/`，不提交 exe、日志或临时截图。

## 修正与效果

- Scene BOX 原来省略底面，却被建筑查询视为完整实体。仰视时看到上表面背面，DDGI 接收位置
  落在实体内，分块侧面也暴露出来。现在绘制完整底面，闭合 BOX 改为朝外绕序并剔除背面；
  退化/反向区间整类双面回退，普通墙片不变。最后的 RTS 二层复核发现剖切后会看到内部面，
  因此主视图剖切/溶解期间恢复建筑双面绘制；AUX 和普通 FPS 不走此回退。
- `BuildingKit.ceiling_light(..., ceiling)` 用透光面高度表达齐平安装，`finish()` 将灯体安装
  包络从楼板可见体积扣除，留下封闭背板。跨板边界可裁分，上层 collision/surface 逐行不变。
  前哨站生成器重复运行字节不变，移灯/删灯会先恢复原楼板。
- 原顶灯黑底座与发光面的底面共面。资产生成器改为分区灯框和独立透光面，消除随视角变黑；
  运行 RMESH 同步重建，灯具尺寸、材质编号和发光插口合同不变。
- GPU 在首次更新前做有界静态探针重定位；真实 BOX 提供内部判定，一般三角形只提供双面距离。
  插值使用实际位置、八面体边缘折叠和少量朝相机的接收偏移。CPU 预存每个插值格的八个索引，
  将片元八次哈希查找变成一次。
- 仅修正几何和探针后，上部墙面仍偏暗。因此加入默认第二次漫反射：每条探针主射线首次命中后，
  额外两条确定性余弦半球射线求第二表面的直接受光；不递归读取探针输出，不形成反馈。
  `RF_GPU_GI_BOUNCES=1` 保留同版本对照，默认 2。不改曝光、直接光强度和半球填充。

最终图为 `final-visual/{b1,1f,2f,stairs,research}.png`，1280×720、NVIDIA、固定天空与正常 Scene 镜头。
顶灯恢复连续发光，天花板的大范围锯齿/条纹消失；上部墙面获得额外反弹。墙角仍可见低频明暗变化，
地下层仍暗于上层，不能据本轮截图宣称任意薄墙无漏光或整个室内均匀照明。

原型仍无动态几何遮挡、太阳/天空反弹、镜面 GI 或任意网格内部的完整重定位。第二次反弹是有限
路径采样，不是递归收敛的无限反弹场；固定的两条次级射线仍会留下低频采样误差。

## 验证

- `build-cutaway.log` 为最终 Windows native 构建；最终 EXE 的 `logic-final.log` 包含完整逻辑通过和
  `persistent closed slab: PASS`，后者保护上下表面面积与朝外绕序。
- `python tools/test_building_kit.py` 三项通过：楼梯地面、四向/跨板嵌灯的体积并集与无重叠、
  封闭背板、碰撞不变、挂装不切割及薄板拒绝。生成器幂等、collision/surface 未变另核对通过。
- `nvidia-hardware`、`nvidia-software`、`amd-auto` 均完成光照专项，实际加载 Khronos validation，
  没有 VUID、SYNC-HAZARD 或 Validation Error。纯反弹 2304 像素，封闭隔板泄漏 0；
  黑反射率、固定来源去重、动态注入、历史衰减、隔离、resize、无效替换和清空继续通过。
- 新增三种相对格点偏移的墙角腔体用例；每种 64 个被测接收像素全部受光。
  同版本第二次反弹使所测墙角色调映射后 RGB 总和至少增加 34.3%（NVIDIA 两路径相同，AMD 为 34.4%），
  深度逐位不变。此数字属于合成测试，不能当作整张前哨地图的亮度增幅。
- 14 个嵌入 SPIR-V 模块经 `spirv-val` 通过，硬件目标 Vulkan 1.2、软件目标 Vulkan 1.0。
- 最终构建的 `native-sync.log` 确认实际加载 validation 与 Synchronization，1080p 正常场景完成
  12 帧并正常退出，没有同步错误；正常帧 bridges/readback/mixed_execute 均为零。
- 引入背面剔除时，`v4/` 双面与 `v5/` 剔除的五个室内镜头逐像素相同。之后加入第二次反弹，
  默认图存于 `delivery/`，不能再要求与一次反弹图逐像素相同。最终补充剖切回退后重拍的
  `final-visual/` 五张图与 `delivery/` 字节相同。
- 剖切回退修正后，`cull-views/` 的室外 `sky-north`、首图 RTS 二层 `frontier-floor-2` 和屋顶
  `frontier-roof` 与双面参考逐像素相同。此轴显式使用一次反弹，隔离剔除行为；默认仍为两次反弹。

前哨站当前 49 盏固定灯、14723 个探针、768 RFU 间距，探针及插值索引缓冲共 10788080 字节。
新增邻居表以约 1 MiB 保留存储换取较少片元查找；本轮没有将这项单独定量为 GPU 时间收益。

## 性能

RTX 3050 Laptop GPU、Windows native、1920×1080，`outpost-light-1f`，0 敌人；固定天空，
真实时钟与 120 FPS 上限。每次预热 120 帧、采样 240 帧，五轮交替顺序，无 validation、截图、
片元原子计数或并行 GPU 工作。表内为五个单轮指标的中位数，单位 ms。

`perf-delivery/` 比较上次交付 EXE 与本轮光照 EXE（补充剖切回退前），双方使用同一份当前地图和灯具资源，
因此衡量的是本轮代码及默认光照行为差异；不是还原旧地图包的整机历史分数。

| 模式 | GPU P50（五轮范围） | 整帧 P50 | 整帧 P95 | 整帧 P99 | 探针更新 P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 上次原型 EXE，一次反弹 | 12.468（12.360–13.147） | 19.593 | 21.051 | 22.484 | 0.093 |
| 本轮光照 EXE，两次反弹 | 9.814（9.773–10.255） | 16.927 | 18.438 | 21.113 | 0.192 |

配对 GPU 节省中位数 **2.659 ms**，范围 2.587–3.037 ms；单轮 GPU P50 的中位数下降约 21%。
主要收益来自闭合建筑背面剔除。中间版本补底面但仍双面绘制时反而变慢，证据保留在
`perf-final/`、`perf-culled/`，未混入最终样本。

`perf-bounces/` 用正式脚本 `-CompareGIBounces` 做同 EXE 的一次/二次反弹五轮比较：
GPU 配对增量中位数 **0.107 ms**，范围 0.041–0.242 ms；探针 compute 配对增量中位数
**0.107 ms**，范围 0.104–0.111 ms。片元仍采样同一个探针场，不增加邻居数量。
该批绝对 GPU P50 为 10.402/10.644 ms，与上一批不同时钟状态，不跨批相减。

本轮仍有整帧长尾：最终版本第五轮整帧 P95/P99 为 23.297/33.849 ms。没有逐帧功耗/频率同步
证据，不将漂移一概归因于温度。首次完整探针更新含重定位和额外射线，未单独签收启动 GPU 耗时；
稳态结果不包含首次预热，也不构成全场景稳定 60 FPS 承诺。
