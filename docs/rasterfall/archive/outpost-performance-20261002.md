# 实验园区与天空组合性能优化现场（2026-10-02）

> 状态：历史优化现场，2026-10-02；仅覆盖本文所列场景
> 归档原因：记录本轮实现、Windows 实机测量及其适用范围，不作为后续版本的性能保证。
> 当前入口：[性能诊断](../guides/rendering-performance.md#实验园区正常场景采样)、[活动计划](../plans/gpu-lighting.md)

## 场景与结论

用户主要使用默认窗口，展示大多关闭。本轮保留地图、多区域精细模型和新天空，减少 CPU 提交与上传，
没有用隐藏可见展品、降低模型精度或停止玩法更新换取帧率。

Windows native、NVIDIA GeForce RTX 3050 Laptop GPU、1280×720 下，四个固定观察位置各进行五轮对照。
优化后的每轮 P95 均低于 16.67 ms，符合本轮常用场景的 60 FPS 初步目标；这不保证每一帧均不超时。
全部展示开启的单轮压力测试 P95 为 20.391 ms，尚未达到相同目标。

## 改动与归因

- 展示文字、投影和终端产生大量相邻的小 draw。无纹理动态层改用 20 字节颜色顶点，按三角形保存颜色和透明度，
  合并相邻兼容项；保留透明顺序、空间原点、pass 和不透明深度规则。
- 透明展示三角形在上传前做保守相机裁剪；主场景按资源包围盒剔除。
  阴影使用各自的光空间裁剪，避免误删视野外的投影物。GPU 蒙皮不使用 bind pose 包围盒剔除。
- 相邻阴影 draw 复用 pipeline/buffer 绑定；静态模型过滤选项从每子网格读取改为每次场景准备读取。
- 正常无限帧游玩不再打印逐帧审计；显式审计和有限帧诊断保留原日志。
- 天空默认仍为每维 1/4 分辨率，march 从 24 增至 32 步，收窄采样偏移并调整太阳遮光、相位和云底填光。
  暖光、雨天捕获已检查；远景碎云仍可见分层纹理，后续视觉工作仍有空间。

阶段诊断指向提交与准备成本。原路径约每帧 1.4 万次主场景 draw、10 MB 动态上传；
同构建优化路径主场景为 336～1061 次 draw、0.39～2.67 MB 上传。
整帧收益不能全部归于天空；也不能把不同阶段的嵌套计时相加。

## 测量口径

入口：`tools/gpu_outpost_perf.ps1 -Compare -Samples 240`，默认五轮，隔轮交换 reference/optimized 顺序。
每次启动预热 120 帧，再采样 240 帧。40 次运行全部实际退出且采样有效。
采用真实时钟、正常 120 FPS 上限、实际 immediate 呈现（`present_mode=0`），不开逐帧审计或 Vulkan validation。
天空固定时间 0、每维 1/4 分辨率。测量结束后核对机器为接通电源、均衡电源方案。

reference 与 optimized 使用同一个最终可执行文件和相同资产、32 步天空。
reference 仅恢复旧动态颜色分组并关闭展示三角形与主场景/阴影剔除；两组都保留绑定复用、过滤选项提升和日志关闭。
因此这是合批与剔除的同版本对照，**不是旧可执行文件与新版的完整比较**。
更早强制 reference 重复绑定的试跑不进入本结论。

下表单位为 ms，数字为五轮各自分位数的中位数；不是将所有帧合并后计算的分位数。

空区跳过候选为 2.185/2.688 ms，配对节省中位数 -0.007 ms，继续保留完整扫描默认。
该隔离测试不构成 1080p 园区整帧签收。

全部展品开启补测使用 `electronics-lab -AllLabs -Rounds 1 -Samples 240`：
P50/P95/P99 为 16.509/20.391/22.086 ms，GPU P50 为 3.140 ms，主/阴影 draw 为 695/3761。
该条件仍需继续优化 CPU 准备与展示更新；不能只凭 GPU 时间认定已定位其全部瓶颈。
