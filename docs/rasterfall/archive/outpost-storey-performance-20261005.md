## 建筑与碰撞

用户要求先修复并提交建筑/碰撞，再继续上下楼性能优化。建筑修复 `0b9f9a1` 建立
离线 BuildingKit→V1 的墙、门洞、楼板及完整折返楼梯生产规则；前哨站墙顶统一连接，
梯段填满墙与中轴之间的可走区域，设备分件碰撞、下降扫掠落地及可站立屋顶护墙接入 Game。
没有增加 native 地图文件语法，也没有将视觉网格 AABB 直接当作物理真值。

Native doctor/build/test、资产工具、地图容量正反例、生成幂等、文档检查通过；正式
1F→B1→2F→屋顶→1F 命令和普通移动通过逻辑回归。CPU 正常帧审计与 NVIDIA RTX 3050
Laptop GPU 的八帧 Scene 检查保存在 `tmp/outpost-renovation/`，原生进程退出 0。
GPU 无 bridge/mixed；仅指定 capture 帧产生读回。两次正常窗口输入脚本未取得前台焦点，
未把这两次尝试或固定取景当作手操楼梯路线通过。

## 卡顿定位与实现

Windows native 诊断在正常 session 固定步内观察到首次跨层查询同步执行大量碰撞试走：
每段搜索展开 323/594/601/1221 节点，却执行约 64万/248万/250万/415万移动样本。
原来的 4096 节点上限没有限制单帧碰撞工作量。后续普通行走固定步很轻，首次搜索占主导。

高度区间筛选排除缺少坡道/连续台阶连接的重叠层。区间合并最多四遍，未收敛时仍进行
完整试走，不能将不完整分析当作不可达。仅加这项筛选时三轮完整位置轨迹与原版一致，
首次搜索仍需约 40–125ms。

最终实现将起终点附着和堆搜索都续跑，包括密集格子内的邻接游标；单次查询按确定性
候选/移动样本预算执行。一个 Game 拥有一个未完成搜索，其他角色排队，目标、请求、身份、
位置和地图失效后释放。追加细化节点时清除新增 parent；有向边缓存和地图重建同步失效。
规划等待只保留命令，不注入身体移动。搜索总展开上限和失败重试保持既有契约。

## 串行 A/B

`tools/storey_performance.py` 两次启动各版本，第二次反转顺序；每启动内三轮，
每段共六个样本。两 exe 同处暂存目录，共用同一资产；无并行构建或 GPU 任务。
对照从建筑修复后的寻路源码重建，双方使用同一计时/计数诊断入口和公共头；不是未修建筑版。
执行真实 `--logic-test`，seed=1、dt=16ms、24 个 host actor 槽，读正式前哨站 surface 目标。

## 验证边界

Native build/test 退出 0，包含前哨站/首图楼层往返、工作预算、排队 owner、停止、换目标、
身份和地图失效，以及原有战斗、寻路与确定性回归。证据 `tmp/building-test.log`。
Native gpu-test 的 120 帧物理 GPU Scene 检查退出 0，全部帧 bridges/readback/mixed_execute=0，
记录有效 GPU 时间戳；证据 `tmp/building-gpu-test.log`。固定诊断镜头不代表行走性能。
上述 A/B 为纯逻辑固定步计时，没有 GPU、present 和限帧成本；不能据此签收手操 FPS
上下楼、普通窗口整帧 P95/P99、帧率稳定性或所有地图路线。正式现场输入仍受前台焦点限制。
