# 固定光照烘焙与跨启动复用现场

> 状态：历史现场
> 日期：2026-10-08
> 原因：记录固定太阳、天空和设施灯的实现及 Windows NVIDIA 限定验证。
> 当前入口：[光照架构](../architecture/gpu-lighting.md#固定光照烘焙)、[光照指南](../guides/gpu-lighting.md)

## 本轮实现

用户明确太阳、天空与室内灯全部固定。fast 模式默认启用烘焙，静态建筑使用表面间接光、
太阳可见性和固定灯遮挡缓存；移动角色、道具读取固定空间光场。材质、视角相关高光、
动态物体阴影和手电／枪口／爆炸直接光仍实时计算，不把最终颜色直接固化到材质。

接收拓扑、空间场和表面数据分别持久保存；几何、反射率、固定光源、天空和着色器版本
进入失效键。缓存长度、版本和校验和不符时重新烘焙，不可写时仍可使用内存结果。
主/AUX 保留独立光场及资源退休规则，设备本地副本不进行主机映射。

表面采样避免跨接收域插值；细长三角形按边高内缩。固定灯遮挡只缓存几何可见性，
距离、锥角和法线因子实时求值，避免低分辨率遮挡掩码形成照明条带。
单 owner 表面预算为 128 MiB，超限绘制回退固定空间场与正常遮挡查询。

`tools/bake_lighting.py` 调用正式渲染路径逐图准备并验证再次启动命中。两张正式地图的
缓存已生成于 staged 包的 `build/`；缓存和本机日志不进入版本控制。
`RF_GPU_BAKED_LIGHTING=0` 可恢复实时对照。操作入口与参数以当前指南及脚本为准。

## 原生验证

Windows 原生构建通过，设备为 NVIDIA RTX 3050 Laptop GPU。

- 完整光照回归通过，覆盖固定更新游标、表面读取、动态直接光、曝光独立、持久化像素
  一致性、损坏缓存回退、改灯失效和 clone 独立性。
- 最终回归及 8 帧 native present 均确认实际加载 `VK_LAYER_KHRONOS_validation`，
  开启同步校验，无 Validation Error、VUID 或 SYNC-HAZARD。
- 前哨站 B1、一层、二层、楼梯、研究区完成截图采集，并核对室内代表镜头及边缘站点车间
  与同包实时模式的画面对照。低分辨率表面插值有局部平滑差异，不宣称像素等价。
- 两张正式地图均通过脚本 prepare/verify，第二次启动命中拓扑、空间场和表面数据，
  表面预算回退数均为 0。前哨站表面约 19.7 MB，边缘站点约 16.5 MB。

本机证据：`tmp/baked-final-build.log`、`tmp/baked-final-sync.log`、
`tmp/baked-native-sync/`、`tmp/baked-final-views/`、`tmp/baked-reference/`、
`tmp/baked-frontier-workshop/`、`tmp/reference-frontier-workshop/` 和 `tmp/baked-prebuild/`。
这些路径为本次现场文件，不是仓库交付依赖。

## 同包性能与边界

1920×1080，同一可执行文件和地图，太阳／天空时间均固定为 0。每轮预热 120 帧、采样
180 帧，实时／烘焙三轮交替运行，关闭验证层、截图和诊断计数。
下表取三轮各自 GPU P50 的中位数，不是全场景帧率承诺。

| 前哨站镜头 | 实时 GPU | 烘焙 GPU | 耗时降低 |
| --- | --- | --- | --- |
| 一层 | 5.669 ms | 5.203 ms | 8.2% |
| 楼梯 | 4.769 ms | 4.040 ms | 15.3% |

GI 更新约 166–168 us、receiver 更新约 44 us 降至接近零；渲染主体仍有材质、动态阴影和
其他成本。第一轮后服务重启，剩余轮次按原配置续跑；没有连续温控记录。
采样配置与逐轮结果保留于 `tmp/baked-perf/config.json`、`tmp/baked-perf/report.json`。

热缓存预热总耗时仍有波动：一层三轮中位数约 1.558→1.745 s，楼梯约 1.606→1.450 s。
缓存消除了重复 GI 求解，但读取、上传、管线和角色准备仍在，因此不宣称整体启动加速；
首次启动、改图、改固定光源或着色器后会重新烘焙，冷启动可能更慢。
本轮没有给出全部地图、密集战斗或长尾性能结论。
