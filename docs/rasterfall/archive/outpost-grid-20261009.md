# 前哨站网格标准化现场

> 状态：历史
> 日期：2026-10-09
> 范围：空间标准化与离线通行诊断；正式导航迁移尚未实施

用户授权先记录计划，再推进前哨站建筑与地图标准化。活动顺序归
[战术基础计划](../plans/tactical-foundation.md)，稳定规则归
[地图网格 V1](../reference/map-grid-v1.md)，复现入口归
[地图制作指南](../guides/map-authoring.md)。

## 本轮实现

- 世界格线固定为 512 RFU，宽深向上取整后再定位；覆盖负坐标、半格中心与四向旋转。
- 大厅、翼楼、楼梯和园区地块采用同一规则；五格门洞两端对齐格线。
  墙厚调整为 150 RFU，使半格中心与半径 180 RFU 身体有净空；楼板厚保留 154 RFU。
- 47 个设备组合按实际碰撞联合包围盒生成整数格规划占地，附件整体移动。
  规划占地和实体碰撞分开；模型不拉伸。出生点和 World Content 角色位置同步规整。
- 大厅按实际十字形楼板并集增加连续支撑面，楼梯接口补充真实范围内的支撑。
  这是正式目标校验要求完整足迹落在同一支撑面后的接缝修复；没有填补楼外空角或楼梯空井。
- 指挥桌操作区提示改为从实际桌对象计算；布局导出分别显示规划占地和实际碰撞。
- 原生地图检查器输出坡道厚度和双端高度，离线工具生成多层支撑节点、净空、八邻接候选边、
  组件及 PNG/JSON。它不改变 Game 的导航、动态避让或碰撞。

## 验证与证据

Windows 原生 `asset-tools`、构建和完整逻辑回归通过；共享取整、编码保留、楼层重叠、
两格走廊、有限坡道及规划坐标展开的七个回归通过。既有地图布局导出、查询和组件测试通过。
全量重建后所有相关地图及 World Content 字节不变；47 个规划组合通过检查。

最终诊断得到 13527 个支撑节点、48688 条候选边、71 个组件和 28 条跨层候选边。
最大组件有 12413 个节点，包含地下室、一层、二层、屋顶及室外。
玻璃围场和设备顶面存在独立组件；候选图不能证明正式单位可达。
产物位于 `tmp/outpost-grid-layout/`、`tmp/outpost-grid-diagnostic/`，不进入版本控制。

RTX 3050 Laptop GPU 原生常规路线完成地下室、二层、屋顶、一层往返和楼梯入口；
连续支撑修复后的最终复验 `tmp/outpost-grid-native-floors-final/report.json` 为 passed=true、
exit_code=0，共 25 项记录。
扩展路线通过大厅南侧入口、研究翼、操作翼、北侧服务通路、指挥桌、主终端、
角色实验室、电子实验室、光照实验室和 `experiment_road_6` 的目标坐标及实际移动检查。
过程只使用正常窗口输入和只读 UI 审计。

扩展运行在前往 `experiment_road_7` 时原生进程以 1 退出，stderr 记录：
`SCENE preparation/submit failed stage=enemies frame=7934` 和
`SCENE-WORLD-GPU normal audit failed`。证据在
`tmp/outpost-grid-native-layout-v3/`；不能将此结果归因为地图不通，也不能宣称该路线已通过。
分段补验 `tmp/outpost-grid-native-layout-campus/` 再次通过三个实验室和第一段性能道路，
在同一下一段道路上于 frame=5088 重现敌人提交失败；缩短运行不能排除此问题。
`tmp/outpost-grid-native-layout-remainder/` 从出生点直接请求远端道路则停于园区入口外，
60 秒到达超时，工具清理后的原生退出码为 0；这不是通过结果。分段请求与直接长距离请求
表现不同，须在正式导航迁移时复核，离线连通图无法解释或替代此运行行为。
剩余性能场连接、性能终端和返程尚未签收。先前两次尝试暴露的屏幕目标落入 HUD 和
复用目录捕获序号问题已在验证工具修正；指挥桌支撑接缝已在地图生产者修复并通过实机接近。

## 后续边界

正式一米格导航尚未迁移：当前固定格容量、随范围放大格子、敌人格外补点和友军导航差异仍在。
下一步先收尾剩余园区路线与 GPU 提交失败，再实施共享分层拓扑；跨层边必须由正式运动规则证明。
本轮没有签收玻璃翻越、动态实验负载、密集单位导航、菜单交互或长时间性能。
