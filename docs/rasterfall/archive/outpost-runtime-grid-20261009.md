# 前哨站正式运行时一米格

> 状态：历史
> 日期：2026-10-09
> 归档范围：用户追加要求后的实现与本次验证现场
> 当前合同：[Game 网格所有权](../architecture/gameplay.md#敌人共享目标导航场)

前序空间标准化与移动修复提交后，用户要求前哨站的单位移动、格子可走判断、建筑占位和导航
均通过网格状态。此前离线分层诊断只作参考，不作为正式 Game 图。

## 本轮实现

`game_grid.inc` 随现有 `game.c` 编译，由 Game 保存固定 512 RFU 格和独立 X/Z 原点。
Runtime 投影的全部碰撞与支撑按覆盖格建立引用表，保留原图元顺序与各层高度；查询只取覆盖足迹的格记录。
普通 actor 与感染者共用格中心分层节点；普通 actor 搜索与敌人共享场保留各自的确定性预算。
前哨站不再生成格外补点或四分格细分，格连线及实际落地移动均查询经过的格层，斜线检查两侧格。
单位仍连续移动；精确身体、平台过渡、坡道和空中高度规则继续由正式运动实现解析格记录。

五个主体建筑模块进入独立占位位图，地图重建保留并重新投影范围；建筑内部不会因占位而整体禁行。
动态单位查询从当前身体生成占格候选，包含跨格足迹，接触扫掠保留圆形和高度区间规则。
它不把临时拥堵写成静态图断路，也没有预约、排队或新的施工玩法。
其他地图继续兼容原导航，session 在前哨站显式启用新模式，Game 不识别地图名字。

当前前哨站实机状态为原点 `(-53760,-47616)`，185×132 格、28129 个图元引用、13213 个分层节点。
容量不足拒绝通行，不放大格子；建筑格、节点格和实时单位候选属于同一 Game。

## 迁移中发现的问题

相接楼板之间的足迹会暂时分属两块支撑，不能用“单个图元完整支撑”替代真实接缝运动。
平台唇缘过渡也不能用静止身体查询提前否决：格查询验证格层和中心支撑，完整连边与实际移动
再由正式运动证明。保留该边界后，出生点至屋顶能够在共用格图上规划并实际到达。

旧分层搜索最多展开 4096 个节点，在固定一米格后不足以覆盖本图；新模式允许遍历完整有界节点图，
每次查询仍保留候选和采样配额，新增格连线采样也计入预算。
临时定位输出、诊断接口和对照试走均已移除，独立定位程序留在未提交的 `tmp/`。

## 验证现场

- Windows native 完整逻辑回归通过，包含负坐标、独立原点、分层隔离、建筑重建占位、实时单位占格、
  格中心一致性、受阻位移、斜角、地面缺口和容量拒绝；既有 B1/二层/屋顶/地面往返通过。
- 物理 GPU 的 `rts_floors_check.py --outpost --grid-layout-check` 70 项通过，原生进程退出 0。
  覆盖大厅四向、家具与终端、三实验场、远端道路、网格场连接和终端、返程及楼层路线。
- 独立出生点直达远端道路、网格场连接/终端及返程的 28 项实机检查通过，原生进程退出 0。

实机证据位于 `tmp/outpost-runtime-grid-native/` 与 `tmp/outpost-runtime-grid-direct/`，逻辑日志为
`tmp/outpost-runtime-grid-final-test.log`；关闭模式的单位查询防护复验另存
`tmp/outpost-runtime-grid-final-guard-test.log`。这些派生证据不进入版本控制。
本轮不代表密集单位长期拥堵、全地图迁移、格预约、施工接口或性能压测已签收。
