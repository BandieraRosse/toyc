# 局部灯整接收域遮挡缓存

> 状态：历史现场，2026-10-06～07
> 归档原因：记录限定设备的实现与实测，不作为稳定架构合同
> 当前入口：[光照架构](../architecture/gpu-lighting.md#固定灯保守遮挡掩码)、[同包对照指南](../guides/gpu-lighting.md#保持画面的光照性能对照)

用户在只读检查后授权继续优化局部灯建筑遮挡。本轮基于 `715ac3c`，保留真实建筑遮挡、
直接光和 GI 的空间精度；正常默认开启缓存，`RF_GPU_LOCAL_BLOCK_CACHE=0` 保留同包对照。

## 实现与取舍

复用 fast BSP 的叶定位，以每叶 128 位掩码排除能证明整个接收包围盒都被同一真实 BOX
挡住的固定灯。CPU 在建筑或灯布局变化后分类，采用截面上的透视区间证明，覆盖原射线的
法线偏移和有限范围；普通三角形的 AABB、角点可见性采样均不作为遮挡证明。每灯 BVH
遍历有预算，无法证明的条目继续逐像素查询。瞬时灯沿用原路径，零强度灯提前跳过。

第一版在片元逐灯比较缓存键，车间两轮总 GPU 减少 0.439/0.524 ms。最终将键校验放到
每帧 CPU lighting upload，片元在灯掩码层剔除；固定灯改色/强度复用分类，移动直射灯立即
失效。新增绑定、叶边界和 AUX clone/释放由既有 graphics owner 管理。

车间 31889 叶/43 灯：28552 个遮挡对，6883163 次节点访问，一盏灯耗尽预算，其余条目
仍查询；GPU 掩码 510240 B、CPU 叶边界 765336 B，分类约 50–55 ms。
前哨站 12144 叶/49 灯：13223 对、2529134 次访问，无预算耗尽，GPU 掩码 194320 B、
CPU 叶边界 291456 B，分类约 23–25 ms。该成本在布局变化时支付，不能算成每帧收益。

## 正确性与实机对照

Windows native build 与 22 个生成 SPIR-V 的 `spirv-val` 通过；NVIDIA RTX 3050 Laptop GPU
硬件路径通过完整 `--gpu-lighting-test`。新增证明测试检查 20250 条独立有限线段，包括三轴、
反向、开口与光源位于实体内；GPU 回归检查薄墙、RGBA/深度/HDR 等价及直射灯独立移动。
原有 resize、切顶、无效输入、清空、改色/关闭/恢复及 AUX 独立缓冲/源失效回归通过。

1280×720，固定逻辑步与天空，车间二层、上楼梯和前哨站一层各做普通画面及照度诊断：
最终缓存关闭/开启的六组 PPM 与三个 HDR 文件逐字节一致。证据位于
`tmp/local-block-20261006/final-validation/`；该目录首轮请求的校验层因依赖 DLL 缺失未加载，
不能把这轮像素检查算作同步验证。

随后把校验层与运行时依赖 DLL 暂存到仓库临时目录，确认 loader 实际插入 Khronos 层，
通过 `VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT` 开启
同步校验。完整光照回归及三个正常 native 镜头均退出 0，无 VUID、Validation Error 或
SYNC-HAZARD；正常 PPM 与上轮逐字节一致。有效证据为 `lighting-sync.out/.err` 与
`active-sync-pixels/`，均位于 `tmp/local-block-20261006/`。

## 同包普通性能

1920×1080，每次预热 120 帧、采样 120 帧，30 秒间隔，两个镜头各做 AB/BA 两轮。
关闭计数、capture 和 validation；热限频记录均为 Not Active。表内单位 ms，分别比较同一
程序的缓存关闭/开启，不能把不同 pass 的分位数相加。

| 镜头 / 轮次 | 总 GPU 关闭 → 开启 | WORLD 关闭 → 开启 | 端到端 p50 关闭 → 开启 |
| --- | --- | --- | --- |
| 车间二层 / 1 | 16.033 → 15.471 | 14.313 → 13.765 | 22.692 → 22.263 |
| 车间二层 / 2 | 16.038 → 15.453 | 14.319 → 13.751 | 22.818 → 22.233 |
| 前哨站一层 / 1 | 8.019 → 7.506 | 5.537 → 5.092 | 14.526 → 13.894 |
| 前哨站一层 / 2 | 8.020 → 7.507 | 5.545 → 5.109 | 14.322 → 14.073 |

总 GPU 中位数分别下降约 3.5–3.6% 与 6.4%；p95/p99 有升有降，尤其第一轮车间 p99
由 25.913 增至 33.870 ms，不能宣称帧长尾改善。原始配置、哈希、日志和热记录在
`tmp/local-block-20261006/final-perf/`。最终采样程序 SHA-256：
`60f351f66f2a205eb5bafe894c464d4b04a4b4b17969df16cbc212497f696868`。

另用优化前的完整暂存程序与候选交替两轮，保留同一 package 资源。第一轮基线出现一次热
限频，整组不作为收益依据。第二轮 BA 均无热限频：总 GPU 15.954 → 15.518 ms，WORLD
14.235 → 13.806 ms，端到端 p50 22.843 → 22.240 ms；说明新增缓存后的整程序仍有净收益，
该干净单组约 2.7% GPU 改善，不能等同于五轮统计。证据为
`tmp/local-block-20261006/version-r*-*/`；优化前程序 SHA-256：
`d7064a19f5018d307a71ac198075ae928b0fdc8a0e5d9d92ba91f6871e863ae8`。

## 射线计数与边界

单独以 `-ProfileLights` 运行同镜头对照。车间每帧局部建筑射线由 32127767 降至 27569833，
减少 14.2%；可见贡献计数均为 10699444，着色次数均为 8678078。前哨站射线由 15683883
降至 12171059，减少 22.4%；可见贡献均为 8909393，着色次数均为 10233777。计数 shader 的原子操作
开销很大，不能用其时间评价普通性能。证据在 `tmp/local-block-20261006/final-counts/`。

该优化只覆盖已证明遮挡的固定灯/有效接收域。纯金属、关闭 GI、reference、缓存外区域、
动态建筑以及任意复杂地图仍不具备全范围签收；动态模型投影仍受原阴影图名额限制。
没有关闭建筑遮挡、降低分辨率或恢复先前已撤销的逐像素多 BOX 预检。
