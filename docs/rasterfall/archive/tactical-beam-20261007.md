## 实现和验证范围

Beam 按成员组合根行动，默认宽度 2、每人最多 4 分支、800ms 保持根行动，真实对局
每 200ms 重算。它尚未搜索连续多轮决策，也未预测对手策略响应；对手预测为 HOLD。
HOLD 基准与保留的完整联合计划在同一时域比较。默认 128 工作单位可以覆盖六名存活
成员的全部赋值层、HOLD 与一个完整挑战预测；提前终局允许继续比较其他保留计划。

引擎返回有效健康、移动/目标距离、路线尾部风险、到点双向火力及各武器准备时间。
策略不读取私有 HP/回避拆分、world、map 或未来 RNG。预测与真实执行共享移动、
换弹/冷却、恢复、同时伤害和命令时序，预测采用期望命中。修正过的边界包括：

- 低命中率射击不能先把平均伤害全部塞入回避储备；每步枚举同时命中组合后结算资源。
- 己方换弹不减少敌人的入射窗口；到点关系使用目的地几何及敌人独立准备时间。
- 显式 FIRE 的目标死亡后停止射击，尾段不能奖励 HOLD 的自动重选目标。
- 廉价评分计有限弹匣和换弹时序，单发伤害还原使用共享模型的原始周期。
- 随机射击的均值死亡不授予确定终局硬奖励；真正无抽样随机的预测终局仍先于权重分数。

Windows native 严格构建和 self-test **65,355 项、零失败**，完整玩家构建与逻辑回归通过。
新增测试覆盖根状态/地图/随机状态隔离、分支不污染、完整时域预算预检、0/1/9/128 预算
合法返回、六名成员全部展开、trace 不改变选择，以及同时分配射击目标避免过量集火。
低血量随机预测和确定终局的排序分别有稳定用例。真实执行 12 场参考 hash/时间/胜负
保持一致；32 场既有 trained/mechanical 批次 hash 仍为 `274e6f54`。

CLI 验证内置 Beam 与 `.cfg` 相同结果、无效参数/重复字段拒绝、日志与无日志一致，
批次重复 hash 一致、交换岗位后的策略成本归属正确。宽度 8 的六人日志约 100.6KB，
原生 inspect 可以完整读取。HTML 通过 JavaScript/DOM 检查：联合层、父排名、评分分项、
不确定射击数、成员死亡、旧日志兼容和占领后攻守标签。浏览器连接不可用，未做视觉签收。

## 预测校准与不确定终局修订

[完整校准](tactical-beam-20261007/prediction-calibration.json)使用一张生成地图、合法节点、
1v1 步枪、双方 HOLD 和 800ms 时域。敌人延长换弹以保持被动，恢复延迟保持 3000ms。
每条件 **4096** 个真实射击种子，五条件共 **20,480** 次采样；不由 Python 重算仿真。
私有 HP/回避仅由历史诊断读取，公开预测接口仍只返回有效健康。

| 条件 | 预测有效健康 | 真实均值 | 均值标准误 | 真实死亡率 |
| --- | ---: | ---: | ---: | ---: |
| 10m 全身，HP100/回避45 | 17.000 | 17.000 | 0 | 0% |
| 55m 全身，HP100/回避45 | 86.540 | 86.617 | 0.324 | 0% |
| 60m 探头，HP100/回避2 | 87.970 | 88.161 | 0.287 | 0.098% |
| 10m 全身，HP5/回避2 | 0 | 0 | 0 | 100% |
| 60m 探头，HP5/回避2 | 0 | 4.037 | 0.054 | 42.334% |

健康目标的有效健康误差在本次样本中小于一个标准误，但 55m 条件内部 HP 高估约 1.568、
回避低估约 1.645，说明跨步均值无法保存完整资源分布。低血探头目标更明显：均值预测
120ms 死亡，真实 800ms 死亡率只有 42.334%。这些场景不能推出移动、多人射击、
更长时域或压力恢复的精度保证。

因此增加 `uncertain_shots`，统计非确定命中或头身随机的成功发射。含这类射击的终局
只使用连续健康等分数，不给 ±10000 硬终局分。
[修订事实探针](tactical-beam-20261007/prediction-uncertainty.json)中五条件分别为 0/8/8/0/2，
健康值与推进时长完全保持原结果。修订堵住确定胜负奖励漏洞，**没有修复均值死亡、健康
分布或恢复压力近似**；零不确定射击也依赖固定行动和敌方 HOLD 假设。

历史诊断源码一并保存，仅调整了引擎 include 相对路径，未进入生产构建：
[校准源码](tactical-beam-20261007/tactical_forecast_calibration.c)、
[事实探针](tactical-beam-20261007/tactical_uncertainty_probe.c)。从仓库根目录复现数值：

```powershell
$env:PATH='C:\msys64\mingw64\bin;'+$env:PATH
& C:\msys64\mingw64\bin\gcc.exe -std=c99 -O2 -Wall -Wextra -Werror -Irasterfall/include docs/rasterfall/archive/tactical-beam-20261007/tactical_forecast_calibration.c rasterfall/lib/rf_tactical_weapon.c -o tmp/archived-calibration.exe -lm
.\tmp\archived-calibration.exe tmp/calibration-check.json
```

本轮已从归档源码重编译，两份诊断的全部条件与记录一致。源码依赖当时的私有引擎，
未来重构不保证其编译兼容。编译器路径是本次环境事实，正式工具入口仍用 NativeCodex。

成本和 snapshot 校验。二进制 SHA-256 分别为
`2d27b3d97e1eb1914d717c19034b1fb87d7b71f2d5977522284d521ef4501af3` 与
`06a7502868aa5d2dbde878ace756809df9965debe8aab089de8be85a05122082`。
Beam 参数 hash 为 `d0a81aac`，trained 为 `d08d1a61`；算法实现用 exe SHA 区分，参数 hash
不能代替实现版本。两轮 snapshot 全部保持不变，均无预测服务缺失。

benchmark 支持不可变 exe/cfg 副本、SHA、并行作业、逐批 journal、失败保留和稳定排序。
native 只返回批次聚合，尚无逐局配对结果，不计算 McNemar 或宣称统计显著。最终运行
墙钟约 435.4s，三进程并行，期间部分 Windows 构建/回归并行；不能据此比较单策略 CPU。
Windows CPU 用 GetProcessTimes，elapsed 用 QPC；旧版 `clock()` 的 `cpu_seconds` 标签
实为 elapsed，新旧该字段不能混作实际 CPU 对照（[Microsoft CRT clock 说明](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/clock)）。

另在两轮任务和玩家回归结束后，运行同进程 Beam 对 trained 的 16 场镜像/交换岗位对局，
使双方拥有相同 3525 次决策调用。地图50000–50003，不参与参数选择。
[原始成本记录](tactical-beam-20261007/same-process-cost.json)：

| 成本 | Beam | trained |
| --- | ---: | ---: |
| 求解平均 elapsed | 0.473ms | 0.000547ms |
| 观测/预测准备平均 elapsed | 1.709ms | 1.410ms |
| 预测次数 / 20ms 步 | 6979 / 277110 | 0 / 0 |

这个倍数仅代表上述规模与机器环境，不是无图形相对图形版的倍数，也不能由该表划分
每个策略的进程 CPU。计时包含现场调度，未声称最坏帧延迟或正式场景性能。
