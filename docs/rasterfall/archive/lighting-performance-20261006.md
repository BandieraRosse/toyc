# 自然光之后的渲染性能优化

> 状态：历史现场，2026-10-06
> 归档原因：记录本轮实现、限定设备验证和性能取舍，不作为稳定架构合同
> 当前入口：[GPU 光照架构](../architecture/gpu-lighting.md)、[GPU 渲染架构](../architecture/gpu-rendering-architecture.md)、[同包对照指南](../guides/gpu-lighting.md#保持画面的光照性能对照)

用户确认自然光与车间翻新的视觉效果后，要求继续优化性能，并明确只维护 NVIDIA 独显硬件主线。
比较基线为 `c07f55f` 的已暂存程序，保留自然光、两次反弹、真实室内灯具、建筑遮挡与原生分辨率。
本轮没有加入 GTAO，没有用 AO 替代建筑可见性或光传输。

## 实现

- 两种 GI 场中，间距、接收点偏移及重定位后的探针位置一致时，复用几何插值权重；各场的
  辐照度、有效覆盖和归一化仍独立。缺邻居、位置不同或独立加粗时回退原查询。
- 在二维灯表之外增加按相机深度分段的保守候选掩码；片元按两个掩码的交集遍历灯，
  首末段覆盖无限远边界。只增加 640 字节，不读取深度缓冲，不截断灯表或改变累加顺序。
- 不透明 WORLD 先写深度，再运行完整光照；共用楼层溶解覆盖规则，透明和 viewmodel 保留原语义。
  公共批次若在 WORLD 插入不测深度的屏幕 draw，则保留原顺序并跳过预通道。
- 性能脚本增加三项互斥开关轴，保存 EXE/map 哈希并核对实际激活日志。

## 验证

证据主体位于 `tmp/lighting-opt-20261006/`；光照专项使用既有 helper，日志位于
`tmp/daylight-20261006/opt-final-lighting-r1/`。临时日志、程序副本和截图不提交。

- Windows native 构建通过；着色器用本地 glslang 离线生成，未以 WSL 运行结果替代 GPU 验证。
- NVIDIA RTX 3050 Laptop 的完整 graphics 回归通过 **7138 checks**，包含分层、颜色几何、
  蒙皮、资源更新、纹理、浮点深度与辅助视频视图。
- `--gpu-lighting-test` 通过：GI 复用 HDR 一致；20 组灯表颜色/深度一致；11 组深度预通道
  对照一致，覆盖共面顺序、全/半剖切、透明、混合相机、viewmodel 与不测深度的 WORLD draw。
  原天空、物理单位、隔层遮挡、两次反弹和建筑生命周期回归同时通过。
- 光照专项日志确认启用 Core 与 Synchronization validation；两套回归均未发现 VUID、同步危险或 validation error。
- `capture-final/` 的 10 个 1280×720 固定镜头，与基线图逐像素一致：实验区、车间内外、
  一层/二层、上下楼梯、屋顶、前哨站一层及楼梯。该批次之后仅补公共屏幕 draw 的预通道保护。
- 最终 EXE 在 `capture-current/` 复查车间二层与前哨站一层，仍与基线逐像素一致。
- `interactive/` 通过 native 4 帧启动及 80 帧菜单/暂停恢复、输入、窗口缩放测试；退出码均为 0，
  日志确认 Synchronization validation 启用且无 VUID/同步错误。
- `tool-reuse/`、`tool-depth/`、`tool-prepass/` 各通过一轮同包开关采样与激活日志检查。
  这些热机短样本用于验证脚本，正式完整版本比较使用下述五轮数据。

## 原生性能

设备为 AMD 5600H + RTX 3050 Laptop，驱动 616.56；交流电、原有均衡电源方案，未更改电源设置。
1920×1080、required hardware/native present、120 帧预热后采样 240 帧；关闭 capture、HDR readback、
validation 与片元计数。完整版本每镜头五轮 AB/BA，报告五个单轮分位数的中位数，未合并所有帧重算。
基线 EXE SHA-256 为 `5a4c2d2f9ab179b233540829aac1ffa006d8d3f20b56b6ad67bd8c9430192c63`，
候选为 `fb7cdef8c7286cf3c770f7627529aba15083f305e7447a3e4d1b119b066f1af5`。

| 固定镜头 | GPU P50 | 整帧 P50 | 整帧 P95 |
| --- | ---: | ---: | ---: |
| 车间二层，基线 | 26.337 ms | 33.615 ms | 35.659 ms |
| 车间二层，优化 | 22.401 ms | 30.243 ms | 31.609 ms |
| 前哨站一层，基线 | 17.588 ms | 24.872 ms | 26.488 ms |
| 前哨站一层，优化 | 13.986 ms | 21.435 ms | 22.632 ms |

车间 GPU 五轮中位数减少 **14.9%**，整帧减少 **10.0%**；对应约 29.7 → 33.1 FPS。
各轮 GPU P50 范围为基线 25.675–29.372 ms、优化 21.505–24.106 ms。
第三轮起出现 86–87°C 温控限频，原始频率、功耗、温度及限频标志保留在 `report.json`。
因此这组数据反映连续运行中的本机效果，不能据此承诺其他温度、电源状态或所有场景的固定收益。

前哨站 GPU 减少 **20.5%**，整帧减少 **13.8%**，对应约 40.2 → 46.7 FPS。
GPU P50 范围为基线 17.150–18.524 ms、优化 13.608–14.142 ms；两侧均观测到温控限频。
最终车间 WORLD 中位数仍为 20.594 ms，阴影 1.350 ms、探针 compute 更新 0.150 ms、
天空/环境 0.094 ms；CPU Scene 准备为 3.665 ms。这些分段分位数不能相加解释整帧。
预通道让车间主绘制计数由 894 增至 1775，但降低了 WORLD 着色成本；不能只凭 draw 数判断快慢。

此前未观测到温控限频的两轮 AB/BA 定向实验：

| 单项比较 | GPU P50 前 → 后 | 解释 |
| --- | ---: | --- |
| 车间 GI 权重复用 | 25.661 → 22.751 ms | 约 11.3%，最大单项收益 |
| 车间深度分段灯表 | 22.698 → 22.581 ms | 约 0.1 ms，整帧收益落在波动中 |
| 前哨站深度分段灯表 | 16.426 → 16.121 ms | 约 0.3 ms |
| 车间深度预通道 | 22.593 → 21.351 ms | 约 1.2 ms，包含额外深度提交成本 |

这些实验使用逐步实现的程序，基线和温度不同，不能把单项差值相加当作最终净收益。
早期 `perf-reuse-r1` 将旧 EXE 放在包外，因程序按可执行目录定位资源而失败；未计入任何性能结果。

## 边界

WORLD 中的光照着色仍是主要 GPU 成本。额外深度提交也有 CPU/顶点处理代价，轻量场景的收益不能
由室内重着色镜头推断。本轮固定视角采样不等于完整战斗路线或全场景 60 FPS 签收；车间仍未达到
稳定 60 FPS。软件 BVH、核显与 Linux 运行按用户范围未验证。代码与证据未自动提交。
