# 集团集结、跟随与采样修复现场

> 状态：历史实现与验证现场（2026-09-26），不作为性能签收
> 当前合同：[玩法架构](../architecture/gameplay.md)
> 后续性能目标：[活动计划](../plans/gpu-scene-renderer.md#敌人直接追击与集团导航)

用户要求集团成立时固定随机人数上限，满员或八秒出动，并减少地面采样。
实现取消集结漫游，容量一次确定为 8–16；成员保留接入路点、到达转角后再推进，
目标重规划后接不上路线的成员从自身位置修复，不重新集结。
集团按领队实际半径验证网格边，不以大体型扩张后的保守 component 判死窄门。
共享有向边缓存随地图重建失效，近追意图按 256ms 错峰刷新，移动仍逐步检查碰撞。
邻居分离改为合并推力后逐敌人查询一次，限制推力以保证前进。

## Windows 逻辑验证

原生 package 构建完成；完整 `--logic-test` 输出 `logic test passed`，
直接等待真实进程取得退出码 0。集结边界为 499 个 16ms tick（7984ms）仍开放、
500 tick（8000ms）封组；另覆盖固定容量、满员封组、混编窄门、
16 人绕墙、领队死亡、目标迁移、地图重建、同输入确定性和近追缓存刷新。
正式走廊在八秒等待上限加原有 600 tick 行进窗口内检查全部 64 名成员通过并产生攻击。
旧坡道与绕墙用例仅将显式集结等待加入原有行进窗口，保留通行断言。

`RF_TERRAIN_BENCH=1` 扩为 960 个 16ms tick，0/16/32/64 人、authored/flat 各五轮。

64 人导航采样减少约 82.8%，全部地面查询减少约 74.7%。未绑定 profile 的五轮累计
world 更新平均从 1,373,054us 降至 349,012us（960 tick 总和），不是整帧时间或 FPS。
两侧保持全部敌人存活，均穿过坡道并到达目标附近。新旧等待时间、集团数量、轨迹和交战时间
不同，不能把累计差值归因于单项缓存；新规则的全员通过另由逻辑回归约束。
最终样本有 6 次集团搜索、6 条路线、0 次旧路径搜索；一轮集团更新最大值约 1.33ms，
约 1ms 导航预算仍未完成签收。第一轮中间实现的约 90% 采样降幅不作为最终结果。
