# 顶部遮挡缓存与 DDGI 原型现场

> 状态：历史验证记录，2026-10-05 至 10-06
> 归档原因：记录本次限定场景与设备的实现、视觉和性能证据，不作为稳定架构
> 当前入口：[GPU 光照架构](../architecture/gpu-lighting.md)、[光照验证](../guides/gpu-lighting.md)

用户要求降低光线遮挡判断成本，并按 DDGI 路线改善前哨站天花板发黑。本轮实现保守顶部
可见性列缓存及 GPU 探针一次漫反射；局部灯和太阳继续精确追踪建筑。没有改动地图灯具强度、
直接光 BRDF、曝光或玩法真值。

## 实现与行为验证

前哨站完整固定灯表为 49 盏，布置 14706 个探针，间距 768 RFU，每探针 128 条射线。
探针结果与哈希布局占 9700896 字节；该值不含屋顶缓存、建筑命中元数据和已有 BLAS/TLAS。
首次完整更新，之后每帧最多更新 256 个，完整轮转约需 58 帧。六方向辐照度和 8×8 距离矩
用于表面插值；动态灯可注入，几何仅含静态建筑。

证据位于工作区 `tmp/probe-gi/`，不提交临时产物：

- Windows native build 和逻辑回归完成；`logic-final.log` 含 `logic test passed` 与展示来源回归。
- `nvidia-hardware.out`、`nvidia-software.out`、`amd-auto.out` 的光照专项全部通过。
  `INDIRECT PASS` 覆盖七种顶部缓存/原射线颜色深度相等、2304 个纯反弹受光像素、黑反射率、
  封闭隔板零泄漏像素、固定灯去重、动态注入/历史衰减、隔离视图、resize、无效输入及重建清空。
  第七例保护起点在 BOX 内且出口小于 triangle tMin 时的软件固体语义。
- 三种路径都实际加载 Khronos validation；`native-sync.log` 另确认 Synchronization 启用，
  NVIDIA 1080p 普通场景完成 12 帧、退出 0，没有 VUID、SYNC-HAZARD 或 Validation Error。
  正常帧 `bridges/readback/mixed_execute` 均为零。
- 生成的全部嵌入 SPIR-V 模块通过 `spirv-val`，硬件目标 Vulkan 1.2，软件目标 Vulkan 1.0。
- 架构、操作、默认能力清点和计划入口随实现更新，文档检查通过。

早期捕获与 package 暂存同时运行，导致暂存删除被锁定、后续视图缺资产；该批不作为验收。
串行恢复 package 后重新完成捕获。另有捕获批只请求了 validation 但 DLL 未实际加载，
它仅用于画面对照；同步结论只取明确验证 layer 已加载的 `native-sync.log` 和专项日志。

## 视觉结果与限制

`reference/` 为 GI 关闭，`accepted-visual/` 为原型开启，均为 NVIDIA、1280×720、
同五个正常场景固定镜头：B1、一层、二层、楼梯、研究翼。天花板获得地面/墙面反弹，
一层、二层提升最明显；地下层和楼梯仍偏暗，角落还有低频插值不均匀。
最初的规则黑色星形网格来自错误的权重分母下限，修正归一化和跨接收面筛选后明显消退。
截图不承担性能或任意薄墙无漏光的证明。
最终构建的 `delivery-visual/` 重拍五镜头，与 `accepted-visual/` 逐字节相同；
同一最终构建的一层 `roof-0/roof-1`（GI 关闭）捕获也逐字节相同。

此原型不包含完整探针重定位、多次反弹、太阳/天空反弹、镜面 GI 或动态几何遮挡。
探针轮转和历史混合使短时动态光可能漏采或残留；纯动态灯且没有固定灯布局的区域暂不覆盖。
后续应先改善墙角有效探针与插值成本，再考虑多次反弹。

## 性能采样

RTX 3050 Laptop GPU，Windows native，1920×1080，`outpost-light-1f`、0 敌人，
同一 package、硬件 Ray Query、固定天空时间、正常实时时钟与 120 FPS 上限。
每次预热 120 帧、采样 240 帧；每轴五轮 AB/BA，关闭 validation、capture 和片元计数，
没有并行 GPU 任务。报告五个单轮指标的中位数，原始轮次与 EXE/map 哈希留在各目录。

最终边界修正后的证据为 `final-perf-roof/` 与 `final-perf-total/`；此前 `perf-roof/`、
`perf-total/` 和 `perf-pilot/` 保留为迭代记录，不混合样本池。
最终 EXE SHA-256：`82167835F609A9664A08096431E16DAF0216C08047A5B7F39E3878FFC61F11C8`。

单位 ms，下表 GPU 为单轮 P50 的五轮中位数，括号为五轮范围：

| 比较轴与模式 | GPU P50 | 整帧 P50 | 整帧 P95 | 整帧 P99 |
| --- | ---: | ---: | ---: | ---: |
| 顶部缓存轴：关闭，GI 关闭 | 10.593（10.549–11.565） | 17.478 | 19.762 | 21.697 |
| 顶部缓存轴：开启，GI 关闭 | 9.403（9.302–10.398） | 16.430 | 17.619 | 22.327 |
| 组合轴：缓存和 GI 均关闭 | 13.063（12.001–14.577） | 20.055 | 21.513 | 23.210 |
| 组合轴：缓存和 GI 均开启 | 14.433（13.513–15.369） | 21.657 | 23.867 | 26.193 |

顶部缓存按相邻轮次相减，GPU 节省中位数 1.247 ms，范围 1.167–1.845 ms。
组合轴净增中位数 1.334 ms，范围 0.567–1.947 ms；不能声称新增 GI 被优化完全抵消。
组合开启时 GI 更新区间中位数为 0.116 ms，片元插值另计在实际绘制区间中。
两批时钟状态不同，不能把其绝对帧时间相减推导 GI 单独成本。

本次连续采样存在明显慢移和整帧尾部抖动；结束附近 `nvidia-smi` 记录 GPU 温度 86°C，
但没有逐帧频率/功耗同步记录，不能把全部变化归因于温度，也不能据此给稳定帧率保证。
早期迭代的组合增量约 0.4–0.8 ms 不作为最终稳定成本承诺。

独立计数实验 `roof-counts/`（边界修正前，GI 关闭）记录每帧顶部查询从 12067271 次降为
5499446 次，约减少 54%。局部与太阳查询保持原路径。原子计数使该运行达到约 0.4 秒/帧，
不能用于性能结论；计数包含 overdraw，不能视作正常帧硬件射线数。

以上均为限定镜头的成本证据。首次完整 GI 预热不包含在稳态结果中；当前未给出其独立 GPU
启动耗时，未签收全场景稳定 60 FPS。
