### 敌人直接追击与集团导航（已被替代）

2026-09-25 用户确认的方案，属于本计划阶段 4 的逻辑帧时间优化；已接入有界短连接查询与集团路线，
余下的图连通性和性能验收仍按下列切片实施，
不代表已达到导航或整帧性能目标。允许路线不最优、轻微扰动及集结停顿，要求复杂障碍正确绕行，
并在目标最终稳定、真实可达且通道未永久堵塞的条件下有限时间到达。持续逃离的目标不作必达承诺。

#### 行为优先级与范围

1. 近距离且直接可达时，个体优先追击最近的有效敌对目标，覆盖集结、等待规划和集团跟随。
   候选仍遵守存活、战斗区域、空气墙、安全区及 developer-only 等现有资格约束。
   在近距离候选中选择最近且直接可达者，不能因最近者隔墙而忽略另一名可直接追击的目标。
2. 直接可达必须按实际碰撞半径、起始高度、地面支撑及连续通行检查确认；视线无遮挡不等于
   可以走到，不能越过间隙、墙体或高度断层。近追距离是待实测的参数，实施时结合速度、查询成本
   和地图尺度确定。短距离通行检查也计入导航开销，使用空间候选缩小及错峰刷新，避免形成新热点。
3. 直接追击加入小幅、持续短时间的方向偏移；实际位移始终经过碰撞。受阻或无进展时取消扰动，
   失去直达条件后恢复有效集团路线或提交接入请求。目标/碰撞变化使缓存失效；不因预算耗尽随机散开。
4. 集团是主要的远距离和绕障进攻策略，不是每个敌人必须满足的攻击前置。近追期间可保留集团身份，
   但不能拖住集团推进；返回时重新校验到路线的接入。使用小幅距离滞回避免边界反复切换，
   不以滞回延迟已经满足近追条件的首次进入。
5. 普通敌人与 Smoker、Charger、Tank 均有聚团和跟随倾向，首版共用分组、领队和路线机制，
   不按特感类型另建编队、护卫或专属寻路策略。既有技能前摇、执行和冷却继续遵守技能状态机，
   已进入技能执行的强制运动不由近追或编队覆盖；技能结束后回到同一导航选择机制。
   集团导航不区分成员体型，按建组领队的通行尺度规划和跟随；领队能通过即假定成员都能通过。

#### 集结与集团生命周期

- 相近且局部可通行连接成立的敌人倾向加入同一开放集团；不隔墙吸附，不为每名成员单独搜索
  完整集结路径。用空间邻域候选和有界短连接检查控制发现成本。
- 2026-09-26 修订：建立时一次随机确定 8–16 人上限，满员立即封组；自建立起最多等待 8000ms，
  超时允许不足人数甚至单个敌人出发。人数减少不重抽上限、不重置时限。近追随时优先。
- 开放集团成员原地等待，取消频繁漫游；人数随机化采用确定性散列，不消耗战斗随机流。
- 封组后停止主动招募，短暂停留并提交集团规划；计划未完成时保存任务，不同步阻塞整帧。
  集结超时与规划排队分开计时；后者由公平调度保证完成，不能伪装成不断重置的集结等待。
- 集团保存稳定 ID/generation、目标身份、成员、领队、路线版本、规划任务和推进状态；个体保存
  集团引用、路线段游标、间距/偏移及进展计时。释放成员槽位、死亡、切图和重置必须清理过期引用。
- 领队死亡或转入近追/技能且无法继续带路时，由路线靠前的合适成员接任，稳定 ID 打破平局。
  路线属于集团，换领队不重新寻路。掉队成员不让全组无限等待；长时间无法接回则脱离为小集团。

#### 一次完整规划与路线跟随

- 每个集团以领队的有效导航接入点为起点，向统一目标附近可站立、满足攻击条件的位置执行一次
  完整 A* 或等价完备搜索。允许非最优路线；不能用固定搜索深度或单帧预算耗尽判为不可达。
  搜索可跨逻辑步续算，保存开放集、父链和重建游标，完成后发布整条路点/通道序列。
- 集团路线按建组领队的通行尺度验证。成员接入和沿线移动使用同一尺度，不因 Tank、Charger 或普通
  敌人的体型差异拆组；地图设计和集团行为采用“领队能通过，成员都能通过”的合同。
- 保留已有导航图作为起点，先验证复杂绕障、窄道、坡道接缝、上下层及网格外接入的表达能力；
  漏掉的物理可达连接须修复或补充局部连接。图上不可达与地图真实不可达分开诊断。
- 领队沿路线推进；成员沿同一序列追赶各自的跟随位置，不能直接连线追领队当前位置。
  成员有独立路线进度；只在验证过的连接内前进，首版接受逐路点转弯，不反复从父链终点向后
  做长距离通行探测。宽处松散展开，窄门/转角收窄队列并抑制横向扰动，出口后展开。
- 每个成员保留接入路点，常规前探最多两个节点；失败后按 512ms 限频查询局部连接，
  后备路线也逐成员验证接入，不隔墙直追领队。接入失败不会立即触发全组重算。路线可按目标、碰撞版本、
  领队通行尺度及有效接入条件跨集团复用；不要求建立全图方向场作为本方案前置。
  局部连接仍失败的掉队者从自身位置提交独立修复任务，继承领队尺度，跳过已完成的集结等待。
- 正常静态追击只规划一次。目标局部移动时校验并更新末端；目标换通道/楼层、门关闭或连接失效时，
  集团合并为一次修复/重规划。旧路线仅在仍安全有效的部分继续使用；在失效连接前停止。
  连续目标更新合并到待处理版本，不每 250ms 清空未完成搜索；发布前校验目标资格和地图版本。

#### 更新频率、配额与进展保障

| 工作 | 初始安排 |
| --- | --- |
| 集团目标重评估 | 500ms，目标失效立即处理；近距离个体目标选择优先 |
| 近追候选/短连接及普通导航意图刷新 | 250ms，稳定 ID 错峰；首次候选、受阻和失效提交优先刷新，候选结果过期不得继续假定直达 |
| 远处稳定跟随 | 500ms；近追进入候选筛选仍按较快频率 |
| 完整搜索、路线重建/验证、接入与修复 | 每个逻辑步按固定工作配额推进，保留未完成任务 |
| 移动、碰撞、攻击与下一路点读取 | 每个固定逻辑步；不等候下一次 250/500ms 意图刷新 |

- 导航 CPU 工程目标约 1ms/固定逻辑步，包含集结候选、近追通行查询、搜索、重建、路线验证及修复；
  移动碰撞、技能、敌人分离另计。补步时同时报告每呈现帧累计导航时间，不能将多步开销藏在单步指标中。
  Windows 墙钟绝对上限不作保证。保留 Game 确定性，使用实机校准的固定工作配额，时钟只用于诊断；
  配额与最大敌人/任务容量一起明确，记录最大耗时和超 1ms 次数。
- 初始化、清空数组、父链重建、通行采样及地图变更后的导航更新也须有界或分片；地图初次加载可独立统计。
  预算耗尽保留有效路线，未取得安全方向时等待；不执行不可中断的大扫描或无约束随机移动。
- 优先级兼顾近处响应与等待年龄，为最老搜索/脱困任务保留固定份额；队列容量有上限，满时确定性排队，
  不淘汰仍被活集团依赖的任务。持续加入的新敌人不能让老任务饿死。
- 进展按路线段完成情况和实际位移衡量，不只看与目标的直线距离。约 1 秒无进展作为初始脱困阈值，
  按速度与路点间距调整；有限次局部侧移失败后取消扰动，严格跟随或修复连接。
- 窄道采用稳定优先级让行；分离力不能永久抵消沿路线的推进。集结、调度、领队替换、掉队脱离及扰动
  都必须有有限等待/尝试边界。必达验收还要求每条路线连接可在有限时间通过，不能只证明搜索结束。
- 所有导航状态及伪随机状态归 Game，由主机权威推进；使用独立可复现随机流，避免扰动消耗改变战斗随机序列。
  session 负责生命周期接线，renderer/HUD 只读。实现时检查显式网络编码与回放边界，不直接同步 C 结构布局。

#### 实施切片与验收

1. 先补诊断与图连通性用例，确定近追范围、任务容量和配额单位；建立短连接查询、集团/任务工作区及生命周期。
2. 接入近追优先、小幅扰动和 8–16 人集结；覆盖特感参加同一集团及不足人数超时出发。
3. 接入可续算的完整集团搜索、整条路线跟随、窄道队列和领队替换；消除正常跟随中的逐敌人完整搜索。
4. 接入目标/地图变更合并修复、掉队接入、公平调度与严格脱困；再校准 250/500ms 和约 1ms 工作配额。
   每个切片更新当前玩法架构及维护入口，完成后将稳定合同移入 architecture，现场数据归 archive。
