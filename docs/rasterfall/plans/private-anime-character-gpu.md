# RF 新一代角色体系与 GPU Scene 接入

> 状态：活动
>
> 所有者：Rasterfall character art、RFCHAR 与 GPU Scene presentation
>
> 开始：2026-09-28

> 体系决策：2026-09-29；以下新增能力均为待实施目标，不表示当前 runtime 已支持。

## 目标与范围

建立面向后续 RF 角色的正式资产、动画、材质与 GPU 资源体系，以私有原创 RF-C01 为首个完整内容包，以前哨站 `RF_MODEL_LAB` 为首个正常帧消费者。交付同时包含通用基础设施和经过验收的模型内容；只显示分色静态模型属于中间诊断，不代表体系完成。后续角色应通过规范资产与目录接入，不修改渲染器中的角色名称、骨骼编号或材质序号特判。

RF-C01 的脸、头部和发型参考成熟动漫角色的造型规律，模型、拓扑、纹理、动作及身份均独立创作。纹理优先服务脸部辨识、发束分层和材质分区，正式内容必须包含实际纹理及运行时材质审阅；不以高分辨率或材质数量作为质量目标。

体系沿用 RFCHAR 的 canonical 骨架、稳定 humanoid role、attachment 和 resource/instance 所有权，按明确版本扩展 RFM2、RFANIM 及材质合同。新体系不等于重写已验证的 Vulkan device/present 或另建人形骨架抽象；也不因历史格式限制而静默丢弃新内容。正常帧首期为 Windows 单人 GPU Scene。CPU 旧动漫绘制、Eula/Maid/PMX/VMD 正常帧恢复、联机画面及 CPU/GPU 画面对照不属于本计划。实验场验收与单人默认切换分开签收；后者须等待正常单人接入完成，保留显式 CPU 入口。

本计划只拥有执行顺序和完成门槛。骨架、资产与动画合同分别见[角色资产](../reference/character-assets.md)和[动画架构](../architecture/animation-architecture.md)；Scene 帧与资源所有权见[GPU 架构](../architecture/gpu-rendering-architecture.md)。

## 已知起点与技术取舍

- 现有 RF Humanoid V2 提供完整的 21-role canonical 骨架、稳定 socket、正式动作组合和 GPU Scene 蒙皮路径，可作为骨架与握枪基础；其简化脸部和头发不足以承担本角色的动漫近景表现。
- 本地 Eula RFM2 样本有 20,197 顶点、73,923 索引、213 根骨骼和 25 个材质组；材质记录包含基础纹理、toon、sphere、边线与双面标志。它仅用于技术清点与视觉研究，不作为待接入资源或顶点、骨骼、材质数量目标。
- 当前 RFCHAR GLB 输入允许基础颜色纹理、OPAQUE/MASK 和最多两项顶点权重；不直接表达完整 PMX toon/sphere/edge 语义，也不接受 morph target。材质能力需要明确的 RF 资产元数据与 GPU consumer 合同，不能依赖旧 PMX 字段的偶然兼容。
- 当前 Scene 角色路径固定 RF Humanoid V2 body，按索引逐帧打包角色几何，仅提交平色材质，并限制单网格索引数。新角色需要资源目录、材质提交和不可变数据缓存；不把 fixture 路径原样扩为正式高模路径。
- 2026-09-29 核对 V22h GLB：51,984 顶点、223,788 索引（74,596 三角形）、49 骨骼、19 个不透明双面材质，无图片、纹理、动画或 morph；已有导入日志记录 8 个 attachment 与 RFM2 v14。历史验证通过不等于本轮游戏签收。
- `rf_gpu_scene_native.c` 当前角色提交拒绝超过 65,536 索引的模型，并限制为不透明平色。`graphics_v0.frag` 已有最近邻/repeat RGB 纹理采样，但未形成角色材质管线；资产端接受 MASK 不等于 Scene 已消费遮罩。

- 决定 RFM2 版本/扩展块、旧资源兼容和不支持版本的拒绝规则；优先演进现有容器，只有无法表达或验证时才另立格式。确定公开、独立原创的最小测试资产，公共回归不能依赖私有 RF-C01。

出口：合同字段、能力必需/可选表、错误处理和迁移方案可供生产者与消费者共同实现。稳定规则落到对应 reference；尚未实现部分明确标为提案，不能把现有 V1 文档直接改成虚假的已支持能力。

### P1：正式资产构建与 GPU 资源基础

- 扩展统一 manifest/importer，生成依赖清单、版本和内容哈希；模型、纹理、动作、LOD 在完整验证后作为一组安装，失败保留上一个可用版本。构建可复现，源修改能准确使相关产物失效。
- 扩展角色目录与 Scene 只读来源，使 body、材质和动作来自资源描述。现有 Humanoid 通过适配接入，清除新路径对固定 body、前两个材质调色和角色名称的依赖。
- 建立共享不可变 mesh/index/skin/material/texture 与独立 instance pose/palette/action history。GPU 资源按内容版本缓存，逐帧只提交变化的实例数据；GPU 蒙皮结果按帧槽/实例隔离。
- 解决高索引数提交：优先保留索引化网格和明确的索引宽度；确需分块时由通用准备阶段按容量拆分并保持材质、骨架和 LOD 映射。不能只提高一个常量，或为通过上限破坏源模型。
- 明确加载、切换、失败和退出时的资源状态，覆盖在途帧 pin、generation、退休与释放。缺失/不兼容资源有可见诊断；实验场不得用另一角色冒充加载成功。

出口：公开小样与 V22h 都走同一资源接口；两种资源、多实例不同姿态互不污染；稳态不重复上传不变的 bind mesh/纹理；切图和加载失败不遗留错误资源。未完成材质可以用显式诊断模式检查几何。

### P2：角色 GPU 材质与纹理管线

- 实现 base color 因子乘纹理，明确 sRGB 颜色、线性光照与输出编码；数据纹理保持线性。纹理导入、TTEX 存储、GPU 上传和 shader 消费必须一致，需要新格式时版本化。
- 实现首版所需的过滤与 mip 链，声明 wrap/filter 和缺失纹理规则；验证眼睛近景、UV 接缝及远景闪烁。禁止把摄影棚明暗直接当成基础色烘入贴图来掩盖光照问题。
- 接通逐材质双面、OPAQUE 与 MASK 深度行为；验证头发、睫毛与 WORLD 的遮挡。BLEND 暂不作为首版内容依赖，需要时另补排序、深度写入与层序合同。
- 实现可调 toon 明暗、脸部法线/明暗控制和按材质启用的描边。脸部修正必须在角色/骨骼局部空间随姿态正确变换；描边宽度、距离变化与内部边界可控。首版高光是否需要专用贴图由 P0 材质小样决定，不能仅为兼容参考模型增加功能。
- 用公开材质小样分别验证颜色、遮罩、双面、toon 和描边，再用 RF-C01 实机联合审阅；区分几何法线错误、贴图错误和 shader 错误。

出口：材质语义从导出到 shader 可追踪，首版能力无静默丢失；基础色、toon、描边能独立诊断。Blender 摄影棚与游戏不要求逐像素一致，要求约定材质含义及角色辨识一致。

### P3：RF-C01 正式内容包

- 从显式锁定的 V22h 候选继续分部件创作；保留既有版本和空间接口，造型审阅与基础设施开发可并行。冻结用于本轮验收的源版本，不让运行时隐式加载最新候选。
- 修整肩袖、膝、手指、口周与发束搭接，检查法线、封闭边界和动作穿插；完成可用于贴图的 UV、岛间留白与 texel density 规划。
- 制作脸/眼、头发、服装需要的基础纹理和材质参数，按近中远镜头决定图集与分辨率；合并等价材质时保持语义身份，不按显示色猜测等价。
- 制作并绑定 idle、walk、rifle idle/aim/fire 动作集，复用 lower/upper/additive、finalized socket 与双手握枪链。辅助骨骼若超出现有 RFANIM role 轨道，须先补通用动画通道合同，不能藏进角色绘制代码。
- 准备近、中、远 LOD，保护脸部辨识、发型轮廓、关节变形和材质边界；维持 socket、骨架映射与动作相位。预算由实测修订，不把 V22h 当前面数或参考模型规模当目标。
- 随包保存源清单、许可/原创记录、导入报告和审阅结果。公共工具与 fixture 可提交，私有几何、贴图和产物留在 private-assets；检查本地 package 复制行为，公开包不得意外携带私有内容。

出口：同一锁定版本可重建完整模型/材质/动作/LOD 包，通过合同、变形与附件验证；新增第二份公开测试角色仅改内容和目录，不增 renderer 特判。

### P4：前哨站实验场正式接入与签收

- `RF_MODEL_LAB` 使用同一正式角色服务和 Scene 提交链，添加独立开关、动作时钟和固定观察镜头；初始及离开前哨站后隐藏，不创建玩法 actor，不进入网络真值。
- 覆盖静止、步行、持枪/瞄准/射击、正侧后与三分之四、近中远、FPS/RTS；提供可重复的动作时间和材质诊断视图。资源未就绪显示明确状态，不把占位模型记作通过。
- 检查世界深度、阴影/明暗的已支持边界、双面/遮罩、描边、LOD 切换、多实例和资源换代；实测记录 CPU 准备、上传字节、GPU 蒙皮、draw、显存与 present/长帧。对比同包空场、单实例、多实例，先定位成本再定容量预算。
- 运行最近的 importer/runtime/材质与逻辑回归，再按风险执行 Windows native GPU、切图、resize、反复显示隐藏、退出及失败传播验证。离屏截图不替代物理 GPU present 签收。

出口：完整 RF-C01 包在正常前哨站 GPU 帧中通过视觉和生命周期验收，提供复现入口、日志与截图；基础设施和内容分别列出通过项与剩余限制。此时可以交付实验场，不自动切换单人默认 renderer。

### P5：正常单人复用与默认入口

在 Outpost/Campaign 正常角色来源复用已验收目录、资源、材质和动画，补齐该范围需要的受击、倒地、死亡、复活及缺失动作策略。正常场景的 gameplay/session、GPU 提交、窗口生命周期和性能门槛通过后，再将 GPU Scene 设为单人默认入口并同步帮助与用户指南。CPU 显式入口及未支持的新角色能力提示保持清晰；联机 Scene 不随默认值变化隐式开放。

## 完成门槛

阶段门槛分别见 P0–P5；整体完成还要求以下项目，不以静态展示或单张截图替代。

1. 原创源资产、manifest、导入产物和角色身份可复现；GLB contract、RFM2 runtime、骨架/附件与动作验证通过。私有源和产物按现有 private-assets 边界保存。
2. 正常 GPU 单人帧显示该角色的脸、头发、身体、动作、武器、LOD 与选定动漫材质能力；缺失能力有明确状态，不用旧 CPU 绘制补画。
3. 静态几何及纹理跨帧复用，多实例共享不可变资源且姿态互不污染；GPU skinning 和 frame lifecycle 通过实机日志验证，没有明显的加载、上传或 present 回退。
4. GPU Scene 成为单人默认入口，显式 CPU 入口和网络模式选择行为清晰；帮助、Windows 工作流、角色与 GPU 架构文档同步更新。
5. 公共测试资产可以独立验证新体系；新增另一角色无需修改 GPU shader 或绘制循环的角色特判。版本兼容、无效依赖、缺失能力、资源生命周期和多实例隔离均有稳定回归。
