# 独立 GPU Scene 渲染架构计划

> 状态：当前唯一活动计划；目标尚未全部实现
> 所有者：Rasterfall GPU 渲染与性能主线
> 方向调整：2026-09-24
> 当前切片：阶段 4，西侧走廊 32/64 敌人优化；推进直接追击与集团导航、碰撞候选缩小及资源更新优化

## 决策

2026-09-24 按核心功能调整门槛：单人 GPU Scene 游玩已基本成立，阶段 3B 以现有核心功能基线结束，
现在进入阶段 4。旧功能未来会调整，不再要求全面补齐旧功能、展示站/编辑器表现、全部交互组合
或展示细节才允许推进。保留核心游玩、内容遮挡、只读来源、零旧路径补画及原生稳定性约束；
影响这些约束的缺陷随阶段 4 修复。此决策不追加未经执行的验收，也不代表架构或性能已全面签收。

新 GPU 渲染器与旧 CPU/mixed 帧组织分开。新路径只消费玩法和展示状态的只读快照，
独立提取 Scene、准备资源、执行分层 pass 并 native present；禁止先运行旧渲染入口，
再丢弃 RasterCmd/mixed recording 来获得 Scene 输入。

复用已经验证的 Vulkan 绘制、GPU skinning、资源 registry/cache、资产解码、动画求值、
swapchain 与同步能力。重建帧编排、各层目标、透明顺序和资源生命周期的组织方式，
不重写 session 或网络权威状态，不推倒底层 GPU 后端和资产系统。2026-09-25 用户确认的
敌人直接追击与集团导航作为阶段 4 逻辑帧时间优化单独分步实施；该行为调整按下文专节验收。

旧路径保留为整帧独立启动选项，只修必要问题，停止围绕它扩展新功能。
默认路径在完整新帧验收前仍为 mixed。3B 提供显式的单人可玩新渲染入口；
当前独立预览只用于开发，不代表完整画面或产品性能。

## 目标链路与合同

```text
玩法/session + 展示缓存
  → 单次冻结的只读帧快照
  → 独立 Scene 提取（可见性、pose/socket、实例、材质、有序透明）
  → 资源准备、整帧 preflight、generation pin
  → SKY / WORLD opaque / transparent / EFFECTS / VIEWMODEL / POST / OVERLAY
  → native present / slot retirement
```

- renderer 不修改 gameplay；GPU executor 不回读玩法数组。世界、碰撞、可见几何保持分层。
- WORLD 共用 color/depth；透明保留显式稳定顺序、source-over、depth-test/no-depth-write；
  VIEWMODEL 独立 depth/coverage。天空、标签、HUD、菜单和特效都必须进入新帧。
- preflight 在目标写入前完成；失败整帧退出，禁止局部 CPU replay、depth bridge、
  readback 或 framebuffer copy 补画。资源 pin 保留到对应 GPU slot 退休。
- 第一版单 graphics queue、显式有序 pass；完整帧成立后按测量优化复用与流水。
- 画面验收以内容完整、遮挡正确、光照和材质表现合理为准。旧整数光栅舍入和整图像素匹配
  不再是开发前置或永久 ABI；已知差异记录后重构收敛。固定新画面规范在完整帧阶段建立。
- 性能以 RTX 3050、固定 workload、1280×720 的完整帧 whole-loop 与分段计时证明；
  缺层预览、减少敌人或 draw 数都不能作为 FPS 收益。

## 已有功能基线

`--gpu-scene-independent-preview` 已开始落地独立来源：跳过 `rf_game_render_profiled`，
使用只获取窗口 surface/extent 的 Core begin，直接冻结地图、正式模块化队员、旗帜、投射物和交互物，
消费已有 Scene 资源准备、GPU skinning 与 native present。逐帧检查旧 command/mixed draw 数为零。
旧 `--gpu-scene-world-preview` 保留为 producer 驱动的诊断对照，不再作为新功能接入入口。

独立预览已从只读展示接口接入普通/特殊/LEGACY 敌人、死亡变换与阴影/舌头、程序角色、
补充模块化角色、downed 和网络角色输入。日志报告 `dynamic_sources_pending=0` 及各类来源数量；
该字段只表示动态来源已接通，不表示整帧完成。天空、地图透明与死亡渐隐、特效、
VIEWMODEL、HUD/交互提示/地图标签和基础暂停/结算面板已进入独立分层批次。
特效已补世界空间近裁剪射线、盒体碎片和受击方向箭头。暂停设置、结算、动态准星、
计分板共享 canvas 布局，AI 名字/血量/倒地反馈由 Scene 提取。Console/GUI 在 normal runtime
本就受关闭 gate 限制，不作为单人入口的新增前置。展示站/编辑器专用表现仍未纳入完整验收。
目前仍共享 runtime 中的 Scene 审计编排、串行资源 owner 和底层 renderer 几何/光照 helper，
独立 begin 仍使用已有 GPU 初始化设施；这不是最终 Core/Scene executor 拆分或多帧流水。

动态来源由独立 adapter 冻结，使用各自 presentation history；补充模块化项仍是帧内身份，
不是跨帧异步资源方案。定向捕获可在显式帧读回同一 Scene 批次，常规 native 帧保持零读回。
本轮来源、原生捕获与验证现场见[动态来源记录](../archive/gpu-scene-dynamic-sources-20260924.md)。
首版分层与定向验证见[分层接线记录](../archive/gpu-scene-layers-20260924.md)。
`--gpu-scene-play` 已开放显式实验性单人入口，沿用真实输入和时钟；基本窗口输入、resize、
world-cycle、fault 和真实波次连续运行已通过，现场见[单人入口记录](../archive/gpu-scene-play-20260924.md)。
购买/重启等未完成专项、完整内容规范与展示细节不再作为阶段 4 前置；后续按核心功能缺陷及实际需求处理。
现有预览日志 `world_only=0` 只表示含非 WORLD 层，不是完整帧签收。资源重建成本明显，尚无性能达标结论。
禁止为补齐内容重新调用旧 producer 或给新路径加入兼容 Raster 通道。

## 西侧走廊 32/64 敌人优化方案

2026-09-25 制定，以下均为待实施步骤，不代表已取得收益。实测依据见
[高负载续查](../archive/west-corridor-performance-20260925.md)。不另建活动计划。

### 目标与边界

本次同时解决持续准备成本与逻辑长尾。64 档动态几何/资源更新约 15–16ms；原随机池的
帧内逻辑均值约 18ms，真实时钟会触达四步上限并丢弃时间。freeze 约 1.4ms，不能作为主攻项。
不承诺各项收益简单相加；减少渲染耗时也可能通过减少补步间接降低帧内逻辑时间。

保留 1280×720、正式地图、26 AI、全部地图组件、原有敌人种类与数量、正常战斗和逻辑频率。
不靠锁血、停 AI、减少波次、降低分辨率或调整最大补步数获得收益。可见性只影响展示工作，
不改变玩法更新；不可见来源可以减少准备/上传，必须证明应见身体及附属内容没有缺失。
敌人导航专节允许改变追击策略和规划更新频率；固定逻辑步、实际移动碰撞与战斗仍正常推进。

阶段工程目标如下，用于决定是否继续优化，不替代正式性能标准：

| 检查点 | 32 敌人，两种随机池 | 64 敌人，两种随机池 |
| --- | --- | --- |
| 首轮收敛目标 | realtime 热帧 mean ≤16.67ms，P95 ≤20ms | realtime 热帧 mean ≤25ms，P95 ≤33.33ms |
| 长尾目标 | 消除可重复的逻辑丢时事件 | 消除可重复的逻辑丢时事件，并使 P99 持续下降 |
| 最终方向 | 按常规场景 60 FPS 预算验证 | 按压力场景 60 FPS 预算验证 |

同时报告帧间隔与 whole-loop；低扰动正式门槛仍由
[GPU 性能标准](../reference/gpu-performance-standards.md)拥有。若 64 档仍无法达到最终预算，
保留未完成状态和剩余成本，不用首轮目标冒充签收。

### 执行顺序

**第 1 步：补足决定实现方向所需的计时。**

- 在 runtime/session 更新边界细分玩家与会话、队友、敌人更新、分离及其他逻辑；在确定性
  Game 算法内只增加可关闭的诊断 hook/计数，不引入 Core 或渲染依赖，不让计时参与分支。
  继续向下区分导航搜索、地面/碰撞和特感。记录每 tick 耗时、调用次数、扫描量、最大耗时，
  同时保留整帧逻辑、tick 数、丢弃时间；嵌套计时注明包含关系，避免重复相加。
- 拆开 `rf_gpu_graphics_triangle_resource_update()` 的验证、map/copy/flush、transfer/等待；
  拆开几何枚举与光照查询，记录顶点数、缓存命中、资源数及上传字节。按来源类别汇总，
  不在每顶点/每 primitive 上读时钟或输出日志。
- 先跑 64 原随机池及无 Tank 的短诊断，再复核 32；同时看生成后的冷开销、持续战斗和
  逻辑尖峰窗口。用相同负载关闭诊断复跑，量化计时扰动。
- 交付热点表和可复跑入口。只有此时才决定逻辑优化先做哪一个函数、资源更新先减验证还是搬运。

**第 2 步：把保守可见性判断移到昂贵准备之前。**

- 在独立 Scene 的角色/敌人来源与 pose、几何、上传之间建立展示侧 bounds。先覆盖完整身体
  和武器装备，再覆盖阴影、舌头及目标端点、死亡翻转/飞行和击飞；bounds 不能只用身体中心。
- 不确定的 bounds 保留原路径；靠近视锥/近裁剪边界时保守保留。第一轮只做视锥和已有距离
  规则，不追加遮挡剔除或更激进 LOD，以便隔离正确性。
- 保持必要的 presentation history 推进，避免重新入镜时步态或动作跳变；GPU owner 按稳定
  来源身份或明确的容量 slot 规则复用资源，不能让剔除破坏来源顺序、透明顺序或 generation。
- 验证固定冻结输入下开启/关闭裁剪的图像；定向覆盖转身入镜、屏边武器、Smoker 舌头、死亡
  与近距离击飞。比较实际准备人数、几何数和上传量；视锥内密集 64 人仍保留全量负载对照。
- 若收益很小，不继续扩大裁剪复杂度，直接推进第 3/4 步。

**第 3 步：只优化第 1 步证实的逻辑热点。**

| 实测热点 | 实现方向 | 必须保持的语义 |
| --- | --- | --- |
| 地面、碰撞或 LOS 全 primitive 扫描 | 在玩法投影 owner 建立空间候选索引；切图、重载、门/碰撞启停时失效或更新 | 候选按原 primitive 顺序精确判定；高度、坡道、边界与启用状态一致 |
| 敌人分离 | 以空间桶缩小候选配对，保留原 slot 的 i/j 顺序 | 推挤会立即改变位置，索引需随移动更新并处理新候选；不能只用 tick 开始时的一份邻居表 |
| 导航搜索/路径可通行检查 | 按下文直接追击与集团导航方案复用完整路线及可续算工作区，减少重复长路径验证 | 允许改变寻路选择和队形；保持真实通行、权威所有权和确定性，缓存按碰撞版本与通行能力失效 |
| 特感索敌、技能或队友更新 | 缓存同一 tick 内完全相同的只读查询，按实际热点缩小扫描 | 查询结果依赖的状态变化时失效；保留目标选择、技能时序及确定性 |

语义不变的优化保留原实现作为诊断对照。相同 seed、命令、固定 tick 下逐 tick 比较权威状态和事件，
覆盖拥挤、门切换、坡道、击飞、死亡、切图；先通过逻辑回归，再测 realtime。
未测出热点的候选不实施，不同时重写导航、碰撞和 AI。已授权的导航行为调整按下文分步验收，
新旧策略不要求逐 tick 状态相等；同一新策略在相同输入下必须可复现。

**第 4 步：缩小动态网格的生成、验证和搬运量。**

- 第一小步保持现有三角形语义，为 Scene 颜色几何提供专用紧凑顶点表示，避免每帧携带
  不使用的字段。保留 position、光照、逐面颜色及必需标志；同步修改 CPU 打包、shader、
  resource layout 和验证。量化字节/顶点与 pack、validate、copy 耗时。
- 将拓扑、索引和其他不变量的检查放到资源创建/拓扑变化时；每帧仍检查动态范围、容量、
  所有权、generation、pin 和批次合法性。不能直接删除 preflight。
- 第二小步再引入有索引的唯一顶点更新。共享键必须包含全部着色属性，不能只按位置合并，
  保留逐面颜色、硬边、透明顺序；先做普通感染体，再按收益扩展刚性特感/程序角色。
- 光照缓存必须按精确位置及光照 generation 失效；不能因 pose 不变就复用已经发生世界位移
  的顶点光照。GPU 蒙皮/刚性实例化只有在上述步骤后 CPU 变换仍主导时再立项。
- 每小步均用相同冻结输入检查图像、颜色、遮挡、透明/死亡、三角形覆盖及更新/增长/复用，
  跑 graphics 回归和 native/sync；不把新增格式、索引和 GPU 姿态一次性合并。

**第 5 步：依据剩余等待决定上传流水和并行。**

先判断 host-visible 路径还是 transfer 路径占主导；前者才评估持久映射和批量写入，后者才
优先合并 staging/copy 提交。无论哪种路径，都在已退休 slot 中更新，保留 flush 和 barrier。
准备成本下降后若退休等待仍限制整帧，再试双 slot，让上一帧 GPU 与下一帧 CPU 重叠；明确
每 slot 的动态 backing、descriptor、pin/generation 和关闭流程，并测输入到呈现延迟及显存。

CPU 几何仍超预算时，先把 renderer 全局/scratch 拆成只读冻结输入和私有工作区，再引入
少量 worker，按稳定来源顺序合并。每项单独比较 whole-loop 和尾延迟；平均值改善但 P95/P99
恶化超出重复测量波动时，保留诊断开关并停止默认启用。不得通过删 fence 或提前复用资源提速。

V1 bake 缓存作为独立的小改动安排在主要热点明确之后：由地图/光照 owner 按有效输入与
generation 缓存，验证重新 bake、切图和光照变化；其收益上界仍受 freeze 总预算约束。

### 敌人直接追击与集团导航

2026-09-25 用户确认的方案，属于本计划阶段 4 的逻辑帧时间优化；现已接入有界短连接查询，
其余行为仍按下列切片实施，
不代表已达到导航或整帧性能目标。允许路线不最优、轻微扰动及集结停顿，要求复杂障碍正确绕行，
并在目标最终稳定、真实可达且通道未永久堵塞的条件下有限时间到达。持续逃离的目标不作必达承诺。

#### 行为优先级与范围

1. 近距离且直接可达时，个体优先追击最近的有效敌对目标，覆盖集结、等待规划和集团跟随。
   候选仍遵守存活、战斗区域、空气墙、安全区及 developer-only 等现有资格约束。
   在近距离候选中选择最近且直接可达者，不能因最近者隔墙而忽略另一名可直接追击的目标。
2. 直接可达必须按实际碰撞半径、起始高度、地面支撑及连续通行检查确认；视线无遮挡不等于
   可以走到，不能越过间隙、墙体或高度断层。近追距离是待实测的参数，实施时结合速度、查询成本
   和地图尺度确定。短距离通行检查也计入导航开销，使用空间候选缩小及错峰刷新，避免形成新热点。
3. 直接追击加入小幅、持续短时间的方向偏移；实际位移始终经过碰撞。受阻或无进展时取消扰动，
   失去直达条件后恢复有效集团路线或提交接入请求。目标/碰撞变化使缓存失效；不因预算耗尽随机散开。
4. 集团是主要的远距离和绕障进攻策略，不是每个敌人必须满足的攻击前置。近追期间可保留集团身份，
   但不能拖住集团推进；返回时重新校验到路线的接入。使用小幅距离滞回避免边界反复切换，
   不以滞回延迟已经满足近追条件的首次进入。
5. 普通敌人与 Smoker、Charger、Tank 均有聚团和跟随倾向，首版共用分组、领队和路线机制，
   不按特感类型另建编队、护卫或专属寻路策略。既有技能前摇、执行和冷却继续遵守技能状态机，
   已进入技能执行的强制运动不由近追或编队覆盖；技能结束后回到同一导航选择机制。
   后续地图设计尽量避免 Tank 无法通过的进攻通道；当前地图仍须按实际体型检查，不能假定处处足够宽。

#### 集结与集团生命周期

- 相近且局部可通行连接成立的敌人倾向加入同一开放集团；不隔墙吸附，不为每名成员单独搜索
  完整集结路径。用空间邻域候选和有界短连接检查控制发现成本。
- 初始调参值：8 人可封组出发、16 人为上限；达到 8 人后最多再等待约 500ms，满 16 人立即封组；
  自集团建立起集结最多约 2000ms，超时允许不足 8 人甚至单个敌人出发。近追随时优先。
- 封组后停止主动招募，短暂停留并提交集团规划；计划未完成时保存任务，不同步阻塞整帧。
  集结超时与规划排队分开计时；后者由公平调度保证完成，不能伪装成不断重置的集结等待。
- 集团保存稳定 ID/generation、目标身份、成员、领队、路线版本、规划任务和推进状态；个体保存
  集团引用、路线段游标、间距/偏移及进展计时。释放成员槽位、死亡、切图和重置必须清理过期引用。
- 领队死亡或转入近追/技能且无法继续带路时，由路线靠前的合适成员接任，稳定 ID 打破平局。
  路线属于集团，换领队不重新寻路。掉队成员不让全组无限等待；长时间无法接回则脱离为小集团。

#### 一次完整规划与路线跟随

- 每个集团以领队的有效导航接入点为起点，向统一目标附近可站立、满足攻击条件的位置执行一次
  完整 A* 或等价完备搜索。允许非最优路线；不能用固定搜索深度或单帧预算耗尽判为不可达。
  搜索可跨逻辑步续算，保存开放集、父链和重建游标，完成后发布整条路点/通道序列。
- 集团路线按全组所需的通行包络验证，包含 Tank 时覆盖其半径及通行要求。首版不另分特感策略；
  若实际地图不存在该包络可走的路线，明确记录失败并按真实通行能力拆组重试，不能无限撞窄门。
- 保留已有导航图作为起点，先验证复杂绕障、窄道、坡道接缝、上下层及网格外接入的表达能力；
  漏掉的物理可达连接须修复或补充局部连接。图上不可达与地图真实不可达分开诊断。
- 领队沿路线推进；成员沿同一序列追赶各自的跟随位置，不能直接连线追领队当前位置。
  成员有独立路线进度；只在验证过的连接内前进，首版接受逐路点转弯，不反复从父链终点向后
  做长距离通行探测。宽处松散展开，窄门/转角收窄队列并抑制横向扰动，出口后展开。
- 每个成员先用有界局部任务接回路线；接入失败不会立即触发全组重算。路线可按目标、碰撞版本、
  通行包络及有效接入条件跨集团复用；不要求建立全图方向场作为本方案前置。
- 正常静态追击只规划一次。目标局部移动时校验并更新末端；目标换通道/楼层、门关闭或连接失效时，
  集团合并为一次修复/重规划。旧路线仅在仍安全有效的部分继续使用；在失效连接前停止。
  连续目标更新合并到待处理版本，不每 250ms 清空未完成搜索；发布前校验目标资格和地图版本。

#### 更新频率、配额与进展保障

| 工作 | 初始安排 |
| --- | --- |
| 集团目标重评估 | 500ms，目标失效立即处理；近距离个体目标选择优先 |
| 近追候选/短连接及普通导航意图刷新 | 250ms，稳定 ID 错峰；首次候选、受阻和失效提交优先刷新，候选结果过期不得继续假定直达 |
| 远处稳定跟随 | 500ms；近追进入候选筛选仍按较快频率 |
| 完整搜索、路线重建/验证、接入与修复 | 每个逻辑步按固定工作配额推进，保留未完成任务 |
| 移动、碰撞、攻击与下一路点读取 | 每个固定逻辑步；不等候下一次 250/500ms 意图刷新 |

- 导航 CPU 工程目标约 1ms/固定逻辑步，包含集结候选、近追通行查询、搜索、重建、路线验证及修复；
  移动碰撞、技能、敌人分离另计。补步时同时报告每呈现帧累计导航时间，不能将多步开销藏在单步指标中。
  Windows 墙钟绝对上限不作保证。保留 Game 确定性，使用实机校准的固定工作配额，时钟只用于诊断；
  配额与最大敌人/任务容量一起明确，记录最大耗时和超 1ms 次数。
- 初始化、清空数组、父链重建、通行采样及地图变更后的导航更新也须有界或分片；地图初次加载可独立统计。
  预算耗尽保留有效路线，未取得安全方向时等待；不执行不可中断的大扫描或无约束随机移动。
- 优先级兼顾近处响应与等待年龄，为最老搜索/脱困任务保留固定份额；队列容量有上限，满时确定性排队，
  不淘汰仍被活集团依赖的任务。持续加入的新敌人不能让老任务饿死。
- 进展按路线段完成情况和实际位移衡量，不只看与目标的直线距离。约 1 秒无进展作为初始脱困阈值，
  按速度与路点间距调整；有限次局部侧移失败后取消扰动，严格跟随或修复连接。
- 窄道采用稳定优先级让行；分离力不能永久抵消沿路线的推进。集结、调度、领队替换、掉队脱离及扰动
  都必须有有限等待/尝试边界。必达验收还要求每条路线连接可在有限时间通过，不能只证明搜索结束。
- 所有导航状态及伪随机状态归 Game，由主机权威推进；使用独立可复现随机流，避免扰动消耗改变战斗随机序列。
  session 负责生命周期接线，renderer/HUD 只读。实现时检查显式网络编码与回放边界，不直接同步 C 结构布局。

   渲染改动比较相同 pose/相机/展示时间的冻结输入。fixed tick 本身不保证展示时间相同，

   不把不同日期的单次结果当作收益证据。不得与 build/package 或其他 GPU 测试重叠。
3. 保留完整 61–360 帧统计，另列首次资源增长与后续窗口；报告真实存活、种类、死亡、相机、
   AI、组件、每 tick/每帧逻辑、丢时、上传字节及分段 median/P95/P99。必须分别列出实际
   32/64 活敌人帧，人数不足或战斗阶段漂移时解释差异，不宣称等负载 A/B。
4. 根据改动运行最近的逻辑、图像、native/sync 测试。索引/资源生命周期变化补切图/重载，
   上传/slot 变化补 resize、world-cycle、fault 和连续运行。算法正确但无可重复收益的改动
   不继续扩大；无法解释的画面、确定性或长尾回归先修复再进入下一步。
5. 首轮目标达到后再进入低扰动五轮及正式生命周期签收。当前计划不把新增诊断的耗时表
   当作性能完成证明，也不因 32 档达标跳过 64 档。

## 验证预算与完成定义

日常只跑最近的构建、逻辑、离屏或原生定向验证；阶段 4 保持核心内容与遮挡、
零旧路径补画及必要的原生稳定性检查，不扩展为旧功能全面验收。完整生命周期候选再执行 Full、10,000 帧 soak
及正式五轮性能采样。开发预览每帧报告独立来源、缺口、draw/upload 和 GPU 时间，
不混入旧 mixed 的性能统计。实际工作流见 [Scene fixture](../guides/gpu-scene-fixture.md)。

单人可玩、架构完成和性能达标分别记录：3B 达到可玩门槛后即可提供显式启动入口；
完整独立帧、内容/遮挡合同、零 bridge/fallback/copy、Windows native 完整生命周期和 validation/sync 通过，才算架构完成；
[GPU 性能标准](../reference/gpu-performance-standards.md)的最终 median/P95/P99 通过，才算性能完成。
任一未达不得宣布整个计划完成。无需以推倒 Vulkan、动画或资产系统换取所谓独立性。

调整前计划和阶段证据索引保存在 [历史快照](../archive/gpu-scene-before-independent-20260924.md)。
稳定所有权由 [GPU 架构](../architecture/gpu-rendering-architecture.md)拥有，
接口增量参考 [Scene 接口](gpu-scene-interface.md)，与本次方向冲突的旧迁移前置不再适用。
