# 战术 AI 与无图形对抗核心

> 状态：当前
> 所有者：Rasterfall 战术仿真与 AI
> 事实入口：`rasterfall/include/rf_tactical.h`、`rasterfall/lib/rf_tactical.c`、`rasterfall/lib/rf_tactical_solver.c`

这是新枪战体系的独立、确定性仿真核心。`rf-tactical` 是 Windows 原生控制台程序，
不创建窗口、不初始化 GPU、不以墙钟时间推动玩法。靶场和对抗场共同消费
[枪械模型](../reference/tactical-weapons.md)和相同的基准战士。
既有 `toy_game` 的感染者、职业技能、网络快照和 RTS actor 控制继续由
[玩法架构](gameplay.md)负责；本核心尚未替换正式场景的 AI 与伤害规则。
移入正式场景时必须增加明确的地图/actor 投影与执行适配，不能把实验世界当成
正式 Game 的副本，也不能在 renderer 里推进它。

## 所有权和数据流

```text
seed + map generator → immutable tactical map / navigation / cover / static visibility
weapon profile + soldier baseline → authoritative tactical world
world + map → read-only observation / relations / candidate positions / path summaries
observation + compiled solver + numeric parameters + logical budget → plan
plan validation → navigation / simultaneous combat / recovery / orders
world → JSONL state and decision log → inspection / browser replay
```

world 拥有位置、生命、回避储备、武器状态、行动、命令、随机序列与胜负。
map 归宿主持有，world 只借用只读指针；对局及搜索副本存活期间不可释放或改写地图。
地图换代重新建立 world，旧计划不能跨代提交。world 不持有文件句柄或渲染资源，
执行状态可以复制并独立推进，为后续搜索模拟提供基础。主世界与搜索副本的随机状态互不影响。

observation 是按队伍生成的固定容量只读值快照：友军、敌军、双向关系、每人最多八个
位置候选、候选射界、移动耗时和沿路径积分的预计受伤。采用双明，双方看到相同规则
下的战场状态。策略只看到有效健康值，不读取内部恢复计时或导航状态。
引擎提供事实，不提供位置总分。

solver 没有 world/map 指针，不能调用几何射线或改写玩法。输出只是有界计划；
执行前验证协议版本、generation、tick、队伍、目标与目的地。无效行动回到 HOLD。
所有 solver 从全员 HOLD 开始，预算为零时仍返回合法结果；预算按候选/目标评价次数收费，
不使用 CPU 时间决定分支。

## 地图、射界与导航

首版是单层、米制的半开放据点与稀疏推进掩体，生成种子改变遮挡布置。
攻守出生区不对称，对比策略时在同一张图上交换攻守岗位。
导航负责可通行路径，策略仅选择离散位置。
推进候选沿目标的完整导航路线取前方位置，允许绕障时暂时远离目标。
候选同时报告欧氏目标距离与剩余导航距离；后者用于机械/utility 的推进评价，
简单策略只执行标记为 ADVANCE 的候选，避免在掩体旁因欧氏距离局部最小停滞。
仍在执行的 ADVANCE 保留已验证路线，抵达该段目的地后再生成下一段；其他行动可中断。
CURRENT 保留真实连续位置，不能与其最近节点混同；候选按实际位置去重。
ADVANCE/CONTINUE 的路径风险使用即将执行的剩余路线，而非另一条重新寻出的路线。
LOW/HIGH 掩体有方向法线、探身/越顶射击语义；身体暴露和实际射击遮挡由几何确定。
静态节点可见性和身体暴露预计算，当前位置与最终执行保留实际 LOS 校验。
路径摘要沿经过的路径累计不同区段的输入火力和暴露时间。
不把终点掩体质量当作全程安全，也不把终点 DPS 乘总耗时作为移动风险。

缓存只属于当前地图代际。动态生命、弹匣、冷却、位置和武器曲线进入每个战术 tick
的关系矩阵，不能烘焙为永久事实。后续接入 Runtime Map 时，以正式碰撞和支撑投影
生成节点，不从可见网格反推玩法；多层、动态门和破坏物需先定义缓存失效及连接合同。

关系 `expected_dps` 是当前后坐/暴露条件下含换弹的火力潜力，不是当前行动在该毫秒
实际造成的生命损失。路径风险按各采样位置的到达时间投影冷却/换弹结束，
敌人位置保持不变，不伪装为对手响应 rollout。采样间隔不超过 0.75m；它仍是廉价近似，
未来搜索需要通过真实短期推进校准误差。首版没有友伤、单位之间的身体阻挡、
装甲或真实弹道飞行；不能由这一实验核心直接推出正式关卡或复杂室内的结论。

## 命令、行动与时间

逻辑固定为 20ms，战术求解周期为 200ms。两方基于同一时刻的快照独立提交，
射击在同一逻辑步同时结算，避免队伍编号决定先手击杀。
人数是 world 配置，支持一至六人，主要评测四、五、六人镜像对抗。

DEFEND 是默认命令，守住所指定范围。ATTACK 清除目标范围内敌人，并让存活小队
占领目标周围；完成后由权威命令系统切为 DEFEND，而非依靠策略猜测。
范围外敌人不要求追杀，灭队与占领是不同的胜负理由。

HOLD 保持位置并向最近合法敌人射击，等距按稳定 ID 打破平局。
MOVE 只移动，FIRE 指定敌人并保持位置，RELOAD 执行换弹；行动互斥。
有限弹匣、无限备弹、射击冷却、反冲、命中、伤害和恢复均由核心处理。
恢复保持秒级延迟，不为搜索缩短游戏节奏。

## 求解器与训练边界

策略一进攻全员推进，防守站定并执行 HOLD 的默认射击。
策略二优先有效射击，否则寻求推进与掩体。
策略三用输入/输出火力、路径风险、命令进度、健康和位置冲突评价候选。
训练只优化策略三的数值权重；参数不改变士兵和武器规则。
基线参数冻结，训练与评测使用不同地图种子，交换攻守、步枪/SMG镜像配置。
结果只说明所测种子、对手、人数和预算的表现。

当前没有 Beam Search、对手响应搜索或神经网络。后续 beam 应复用候选/计划验证、
合法 HOLD 起点和可复制世界，保持独立预算与预测状态。短期精确推进和长期粗略健康
评价需要区分，不能把搜索模型输出覆盖真实世界。
动态算法文件、策略语言、DSL/VM 与热加载按用户指示延期；普通 `.cfg` 只保存
内置求解器参数，不是算法程序。操作见[战术实验指南](../guides/tactical-lab.md)。
