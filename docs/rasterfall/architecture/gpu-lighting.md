# GPU 固定与实时光照

> 状态：当前
> 所有者：GPU Scene presentation、Vulkan graphics
> 最近核对：2026-10-06

GPU Scene 使用独立光照；默认烘焙固定环境，动态直接光与投影仍实时求值。CPU 静态光照路径保留为遗产，按 2026-10-05 用户决策停止维护，不作为新增功能或视觉验收目标。GPU 不采样 V1/V2，不复制旧 CPU 烘焙场，不以 CPU 的颜色、整数深度或光照乘数作为兼容目标。

## 固定光照烘焙

`RF_GPU_BAKED_LIGHTING=1` 是默认 fast 路径：太阳、天空与设施灯的间接照明在首次准备时完整求值，
之后停止探针、方向环境与接收缓存的轮转更新。正常 Scene 天空时间固定为零；显式 `RF_GPU_SKY_TIME`
可选择另一个固定时刻。手电、枪口与爆炸只参与实时直接光，不注入固定探针，避免把加载时的瞬时效果
永久写入环境。移动角色、道具和未覆盖表面按当前位置、法线读取同一固定空间光场。
`RF_GPU_BAKED_LIGHTING=0` 恢复此前实时更新与天空运动，reference 和 direct_only_diag 仍是独立对照。

`rf_gpu_baked_lighting.inc` 为不可变、顺序三角形、平面着色的 WORLD 建筑生成双面表面缓存；
每个三角形每侧 4×4 采样，保存线性 HDR 间接辐照度及固定灯/太阳的静态遮挡。
采样内缩按三角形各边高度计算，避免细长面角点落入相邻实体；跨接收分区或无有效分区时，
片元回读固定空间光场，不能跨墙或跨楼板混合。直接光的距离衰减、材质 BRDF、高光与动态 shadow map
继续实时求值，固定遮挡使用表面数据；因此这不是把最终画面颜色写入材质。
表面数据独立于相机、曝光与 RTS 切顶，正反面分开；固定灯的位置、方向与锥角不匹配时恢复实时遮挡查询。
单 owner 表面预算为 128 MiB，超预算的完整 draw 使用空间光场与原直接遮挡，不截断几何。
`RF_GPU_BAKED_SURFACES=0` 只关闭表面缓存，保留固定空间光场，用于成本与画质对照。

`rf_gpu_baked_io.inc` 持有有界、带校验和的内容寻址磁盘缓存：接收拓扑、初始化后的两场探针/方向环境/
接收数据、静态表面数据分别保存。默认目录为运行目录 `build/`，`RF_GPU_BAKE_CACHE` 可指定目录，
`-` 禁止磁盘读写但仍在内存中烘焙。几何及反射率、完整固定灯输入、太阳/天空参数、格式/算法配置和
相关 compute SPIR-V 参与失效键；曝光、相机与瞬时灯不参与。文件失配、损坏、截断或不可写仅退回冷烘焙。
写入在 GPU 提交退休及 compute→host 屏障后执行，临时文件按进程隔离并原子替换；正常稳态无光照读回。
表面读回先批量复制到普通主机内存，再计算校验和及写文件；HOST_COHERENT 映射不保证 CPU 缓存，
不得在设备映射指针上逐字节计算文件校验和。保存日志分别记录复制、校验和与文件写入耗时。
换建筑沿原退休规则安装新代际；resize 保留光照；AUX 保持独立缓冲并复用主光场初始化结果。
生成数据不提交源码。预先生成、验证复用与同包对照见[烘焙操作](../guides/gpu-lighting.md#固定光照烘焙与对照)。

## 数据与所有权

`render/rf_gpu_scene_lighting.inc` 从只读展示状态提取设施聚光灯、枪口/爆炸瞬时点光源和可选手电筒。固定设施优先使用 spot light，point light 限于短时效果和少量局部工作光。`rf_gpu_lighting` 容纳最多 128 盏固定灯与 32 盏瞬时灯：固定灯保持地图顺序，与间接光使用同一完整来源；仅瞬时灯按强度与相机距离排序截断。相机移动不能改变固定灯的直接出光量。灯状态不写入 Game、地图碰撞或网络快照。

`gpu/src/rf_gpu_lighting.inc` 拥有每个 graphics slot 的光照缓冲、阴影目标、GPU 深度缓冲和后处理管线。`rf_gpu_indirect.inc` 拥有顶部缓存、探针布局和持久间接光场。光照在提交前复制，帧执行期间不可修改。resize 重建 HDR/LDR 目标和相关描述符，保留建筑与探针；关闭在 GPU 排空后释放资源。

## 可选接收空间缓存

本节及后文的逐帧轮转预算描述实时对照；默认固定光照在完整初始化后停止这些更新，
灯具/天空输入变化才重新求值，详见上面的烘焙合同。

`RF_GPU_INDIRECT_MODE=reference|fast|direct_only_diag` 在 graphics 初始化时读取；默认采用
`fast`。reference 保留探针与逐表面几何可见性对照路径。fast 复用灯具和自然光探针作为
数据来源，但将接收位置到探针的可见性移到缓存初始化。direct_only_diag 跳过间接漫反射、
旧环境填充、天空环境生成和探针更新，保留直接光、阴影、材质及可见天空，仅用于消融。

`gpu/src/rf_gpu_receiver_cache.inc` 从同一份完整建筑输入构造世界空间 BSP；真实 BOX 边界和
与区域相交的三角形平面分隔插值域，实体内部没有采样。三角形平面可保守延伸，因此可能
产生额外空分区。八个接收采样点投影到各自凸域，墙两侧和有限厚度楼板上下不能混合。
轴向三角形无论正、反绕序，分割后都收紧两侧包围盒；负轴法线不能沿用父包围盒，
否则会产生无法投影的角点和楼梯附近的空分区。光照回归保护两种绕序的采样数与实际 HDR。
角点投影按原顺序执行最多 64 轮；完整一轮后三维浮点位表示完全不变时提前结束，保持原固定点
和空间精度。`RF_GPU_RECEIVER_PROJECTION_FIXED=1` 保留固定 64 轮对照，回归逐位比较拓扑和位置。
拓扑不依赖主镜头、地图名或 RTS 切顶；角色、道具和建筑读取同一光场。正常片元沿最多
48 层树定位，在一个叶内做八点三线性和六方向瓣插值，不遍历候选探针、不查询建筑遮挡，
也不恢复天空射线。直接光先读取下述固定灯遮挡掩码，未证明遮挡的灯仍使用原有建筑查询和阴影图。

binding 16 由 graphics owner 独占；每个接收点占 128 B：32 B 静态位置、两场探针格引用、
天空方向与邻居可见性位，以及 96 B 动态灯具/自然光 E/π 六方向瓣。静态与动态区域分开排列，
邻居索引只在原探针格保存一份，三线性权重由接收点位置在刷新时重算。两种光照分别以
`packHalf2x16` 保存 RGB FP16，片元使用 `unpackHalf2x16`，不要求可选的 16 位存储特性；
超过 FP16 有限上界的值钳位到 65504。`RF_GPU_RECEIVER_FP32=1` 保留相同拓扑及邻居求值，
只将动态光照恢复 FP32（224 B/sample），用于数值和读取成本对照。辐照度采用既有 /100 HDR
存储尺度，在片元只乘一次接收材质反射率，不包含曝光、基础色或 AO。有效零照度按几何
有效性保存，不以亮度判断缓存缺失。六方向侧别权重在刷新时求值，几何短线段只在初始化
执行；自然光没有有效探针时，以初始化保存的天空可见掩码读取当前方向环境。

首次在探针重定位后完整初始化并刷新；稳态每帧轮转最多 8192 个接收点，不分配、上传或
重建 descriptor。`receiver` GPU timestamp 单独包含初始化或刷新；`gi` 只含原有探针更新。
灯具和自然光保存、控制分别独立。fast 中同数量、同位置/半径的固定灯改色、改强度保留
探针布局和接收几何关系，下一提交完整更新灯具探针并刷新接收值，清除旧人工光历史；
新增/移动灯和半径变化重新布置。短时动态灯、自然光仍受原有探针轮转预算约束。

建筑替换先构造新拓扑，成功安装后一起退休旧建筑、探针和接收缓冲；无效输入保留旧状态，
帧在途时拒绝替换。resize 保留拓扑和照明。compute 初始化、刷新及 fragment 之间有明确
读写屏障；AUX 保持独立照明缓冲，可 GPU 复制主场初始化结果并借用静态建筑查询结构，
生命周期见[多视图资源所有权](gpu-rendering-architecture.md#入图预热与多视图资源所有权)。
`disable_indirect` 与 `RF_GPU_GI=0` 不执行 fast 缓存更新。

当前缓存预算最多 32768 个叶、131072 个节点；超过预算逐次加粗，不能截断遮挡几何。
初始化日志记录间距、样本数、字节数、准备时间及退化/深度上限分区数。这些计数不是当前
镜头命中率。远离建筑的空间不分配叶；未覆盖/实体/退化区域只采用顶部列缓存能证明开放
时的廉价天空近似，否则保守为零，不回退 reference 查询。空建筑明确开放。
该回退未证明整个天空半球无遮挡；大空间中央、复杂斜面和缓存边界仍需专项视觉检查，
不能宣称任意地图均已覆盖或任意运动连续。reference 保留为显式对照入口，具体验证边界由
[本轮现场](../archive/fast-interior-lighting-20261006.md)记录。未增加门、破坏、动态建筑或镜面 GI。

## 光度单位与显示合同

512 RFU = 1 m。灯具 profile 的 `luminous_flux_lm` 是额定总光通量（lm），GPU 局部灯
`color_intensity.w` 是配光峰值光强（cd）。当前配光是在方向余弦上做 cubic smoothstep；
`ci`、`co` 分别是内、外锥的半角余弦，约束为 `0 <= co < ci <= 1`。

```text
点光源：I = Φ / (4π)
聚光灯：Ipeak = Φ / [π (2 - ci - co)]
E_direct = Ipeak × distribution(direction) × max(N·L, 0) / distance_m²
           × range_fade × visibility
range_fade = [1 - (distance / radius)^4]^2，超出 radius 为零
白色 Lambert 表面：L = E / π
```

因此改锥角保持额定流明不变，峰值 cd 随方向分布变化。距离小于 0.2 m 时继续使用有限近场
钳位；范围衰减和近场钳位是实时渲染近似，额定流明不等于任意距离球面上积分后的实际通量。
物理基准在远离近场、远小于影响半径处验证；不能对衰减明显的远处仍直接套理想平方反比。

局部灯和太阳的线性 RGB 在提交时以 Rec.709 亮度 `Y = 0.2126R + 0.7152G + 0.0722B`
归一化到 1，光强为正时必须有非零颜色；改变色调不会偷偷改变标称光度。太阳的
`sun_color.w` 是垂直于太阳方向平面的照度（lux）。`sky_illuminance` 是无遮挡水平面天空照度（lux），
程序天空提供方向和颜色分布，积分后归一化到该值，不包含独立太阳盘。正常 Scene 使用 120 lux
的初始美术标定，原始 API 默认值为零以保留隔离实验的旧光照。`environment.rgb` 是艺术性半球填充的
等效 RGB lux，仍受朝向和顶部可见性调制，不能算作真实天空传输。默认太阳保留原先低反差
美术预设，数值约 274 lux，不宣称是晴天太阳。程序天空和云的外观也未做真实天空亮度标定。

自发光 `draw.emissive` 是白色基础材质对应的亮度（cd/m²），乘线性基础颜色后成为实际
RGB 亮度。提交时使用 16 位对数编码，覆盖原先 0～15 的亮度上限。灯面自发光与灯具流明
目前仍独立：未根据发光面积和方向分布绑定能量，也不把灯面再注入 GI，避免重复出光。
前哨站灯具流明是初始迁移值，并非某款现实灯具的实测数据。

所有直接光、探针反弹、自发光共用线性 HDR 标度：1 内部单位 = 100 cd/m²；这是存储尺度，
不影响物理输入。非金属漫反射、GGX 镜面和反射率仍按材质计算。曝光 `environment.w`
只在后处理中乘显示信号，默认 1；它不改变照度、探针或光源。当前曝光是显示倍率，未建立
相机 ISO/快门/光圈模型。RGB 光度和最多两次漫反射是可测量近似，不是光谱照明设计软件。

`RF_GPU_GI_DEBUG=3` 的诊断 HDR 分别保存直接照度、GI 照度、艺术填充等效照度，单位均为
lux / 100，位于曝光和色调映射之前，不乘接收面反射率。天空、HUD、viewmodel 不可作为测点。
`rf_gpu_graphics_capture_hdr` 只读取最近一次显式 capture 的 RGBA16F，不增加正常帧 readback。
测量工具与标准场景回归见[光照指南](../guides/gpu-lighting.md#物理单位检查与照度读取)。

## 帧流程

### 建筑遮挡与灯具绑定

前哨站用 `light_ceiling` 吸顶灯和 `light_wall` 壁灯替换原路灯；布局由
`tools/outpost_storeys.py` 维护，覆盖 B1、一层、二层、楼梯间和入口。
`rasterfall_prop_light_profile()` 拥有模型局部 RFU 插口、发光材质编号、方向、锥角、颜色、流明和距离。
插口以模型底部中心为原点、+Z 为正面；位置与方向沿模型 yaw 旋转，位置和半径沿实例 scale 缩放。
灯罩材质自发光与照亮世界的 spot light 分别提交，但使用同一模型 profile；无游离世界坐标灯。
吸顶灯通过建筑生成语法 `ceiling_light(..., ceiling)` 将透光面与楼板底面齐平；
`finish()` 从 render BOX 扣除灯体安装凹槽，保留封闭背板和完整上层碰撞/地面。
灯具模型的透光面、暗色灯框分区建模，不允许重合底面。挂装与嵌装的高度语义见
[建筑生成语法](../reference/architectural-environment-v1.md#标准房屋生成语法)。
灯具 profile 的强度和配光是实际直接光与探针注入的共同来源；发光面只负责自身显示。
壁灯透光面为朝前下方的斜面，模型局部法线与 profile `(0,-0.8,0.6)` 一致；插口位于
透光面前方，不能用竖直白面配向下的出光轴。生成器检查发光面的法线，公开 RMESH 与插口同步更新。
当前顶灯与楼梯壁灯采用宽角配光，配合浅色室内表面；流明、cd、lux、自发光亮度和曝光
遵守上述合同。早期相对强度 `72` 不能回溯解释为 72 lm 或 72 lux。

Scene 在 world/map generation 改变时，从实际 WORLD 的 wall、box、ramp、platform、floor、boundary
不透明几何重建遮挡结构；应用 primitive 的真实世界平移，不从碰撞盒猜测遮挡，不按主相机剔除。
地面从冻结 mesh 恢复真实矩形，并合并同高度、同反射率、同横向跨度且严格相邻的矩形，
再生成两个三角形；局部 render origin 不限制遮挡合并。开口、材质边界和可见网格保持原有几何，
不以扩大图元上限、截断输入或地图名特例处理大面积细分地面。非矩形输入明确失败并打印诊断。
软件路径对普通 BOX render 直接按其真实上下界解析求交，避免重复查询细分后的平面三角形；这不是模型包围盒，
门洞仍由独立墙段与过梁组成。其他建筑使用实际三角形，包括楼梯踏步。
Scene BOX 网格包含底面，有限楼板的接收面必须与解析遮挡体表面一致；不能省略底面后
依靠双面上表面充当天花板，否则受光点会落在遮挡实体内并暴露分块侧面。
完整 BOX 使用朝外绕序并剔除背面，减少不可见内部面造成的重复着色；任一 BOX 区间退化或
反向时整类保持双面回退。普通墙片等非封闭网格仍由原材质双面属性决定。
RTS 剖切/溶解会打开实体，主视图此时恢复建筑双面绘制；未剖切的 AUX 保持完整世界及背面剔除。
BOX 底面可用 `attr.bottom_color` 独立于地板/侧面；Scene 网格与探针命中必须读取同一基础色。
提取时将可选底面反射率复制到 `rf_gpu_occlusion_primitive.bottom_rgb`；硬件最近命中元数据按
真实三角形面选择颜色，软件 BVH 按解析 BOX 的命中面选择。显式黑色与未覆盖分别编码，
不增加建筑图元、光线数或片元插值开销。更改底面颜色会使静态 Scene 内容缓存失效。
`gpu/src/rf_gpu_architecture_light.inc` 验证公共输入并路由硬件/软件路径，最多 65536 个输入图元，
超限明确失败；帧在途时禁止替换，resize 保留，空世界清除，关闭排空后释放。辅镜头拥有独立缓冲。
片元通过固定灯保守遮挡掩码及双面建筑求交检查太阳、所有 spot/point 到表面的可见性，因此建筑遮挡不受两个动态
聚光灯阴影名额限制。门洞保留真实开口，有限楼板和楼梯使用真实网格，RTS 切顶不移除遮挡。

正常自然光路径用下述天空与太阳传输替代艺术填充，不叠加另一份环境亮度。关闭自然光时，
旧向上可见性仍将有顶区域的半球填充压到 10%；该旧填充不是光传输。
静态道具、角色和透明物不进入本建筑结构；原太阳和两个 spot shadow map
继续承担不透明模型与角色的投影，其他局部灯仍不具备这些动态物体的完整遮挡。

WORLD producer 将已完整纳入当前建筑输入的 draw 标为 `architecture_occluder`（host metadata，
不进入 shader push constants）。非空建筑结构成功安装后，这些 draw 退出传统阴影图；硬件与软件
查询都适用。其余道具、角色和模型类别仍照常投影；BOX 类若存在解析输入未覆盖的退化或反向区间，
整类保留原投影。标记来源和建筑输入必须属于同一冻结世界；正常帧在提交前完成代际校验与结构替换，
替换失败不能继续提交该帧。清空结构恢复传统投影，无效替换保留原状态，resize 不清除覆盖状态。
`RF_GPU_ARCHITECTURE_SHADOW_MAPS=1` 在 graphics 初始化时恢复重复投影，仅用于同版本对照。
建筑仍由原先的二值射线遮挡决定阴影；移除重复 PCF 后，其阴影边缘不再叠加阴影贴图的过滤暗边。

### 固定灯保守遮挡掩码

默认 `RF_GPU_LOCAL_BLOCK_CACHE=1` 复用 fast BSP 查询得到的接收叶索引；binding 17 为每个有效叶
保存 128 位固定灯遮挡掩码，另有 16 B 头部。CPU 保留每叶 24 B 的保守包围盒，沿原建筑 BVH
寻找能证明整叶被挡的真实 BOX。不会从碰撞盒或普通三角形的包围盒推断遮挡，也不以若干角点
的射线结果代表整个分区。判定以 BOX 中间截面上的透视投影区间覆盖整个接收包围盒，光源坐标
另扩张 ±2 RFU，覆盖原射线法线偏移；严格内部与端点分离裕量保护浮点误差及原有限查询区间。
三角形、门洞边缘、未覆盖/实体/退化区域或不能证明遮挡的灯继续使用原查询。

掩码只依赖建筑与固定灯位置/半径，在布局改变后重建；每盏灯最多遍历 262144 个 BVH 节点，
预算耗尽后的条目保持未知。改色、强度及关闭/恢复复用掩码。每帧 CPU upload 逐灯比较当前
位置/半径和固定灯标记，上传 128 位有效键掩码；即使只更新直射灯的位置，旧条目也立即失效。
片元将有效遮挡位从原灯表掩码中剔除，再求值剩余灯的距离、锥角、建筑可见性和 BRDF；
零强度灯在求交前跳过。不会缓存可见结果，因此移动角色与道具仍使用当前位置所在的接收域。

各 graphics owner 独占掩码缓冲与 CPU 叶边界；WORLD AUX 的 GPU lighting clone 同时复制它们，
后续固定灯更新独立。建筑替换清除旧掩码，无效输入保留，resize 保留，源释放/替换解除 AUX
引用后使掩码失效。reference、关闭 GI、纯金属等未执行接收域查询的路径仍查询建筑。
`RF_GPU_LOCAL_BLOCK_CACHE=0` 在初始化时关闭此缓存；局部射线消融忽略掩码。日志的 blocked-pairs
是几何分类数，不能视为当前镜头实际减少的射线数；计数与交替性能对照由光照指南维护。

### 可选硬件 Ray Query

后端在 loader 和设备均支持 Vulkan 1.2 时，查询 `VK_KHR_acceleration_structure`、
`VK_KHR_ray_query`、`VK_KHR_deferred_host_operations` 及 `accelerationStructure`、
`rayQuery`、`bufferDeviceAddress` 特性。默认自动启用；不支持时保留原软件 BVH 着色器。
`RF_GPU_ARCHITECTURE=software` 强制对照，`hardware` 要求能力存在，否则初始化失败，不能静默替换。
此处软件仍是 GPU 片元查询，不是已停维的 CPU renderer。旧设备保留原 Vulkan 1.0 shader 路径。

`gpu/src/rf_gpu_architecture_ray.inc` 从同一建筑输入构建一个静态 BLAS 和 identity-instance TLAS；
真实 BOX 转为十二个表面三角形，其他建筑沿用原三角形。驱动构建使用 `PREFER_FAST_TRACE`，
scratch 地址按设备属性对齐；host coherent 输入、临时命令池和 fence 只存在于生成阶段。
BLAS 写入到 TLAS 读取、TLAS 写入到片元/compute 读取均有显式 barrier。成功提交并等待后才更新描述符，
原结构随之释放；失败返回错误，已提交资源排空后回收。空地图绑定已构建的零实例 TLAS。
BLAS/TLAS 和存储由各 graphics owner 保留，resize 不重建；不逐帧构建，不共享跨视图可变所有权。

硬件片元变体使用 GLSL 460 / Vulkan 1.2 SPIR-V，binding 7 为 acceleration-structure descriptor，
软件变体同一 binding 为 SSBO。射线保留法线起点偏移和有限光源距离，双面、不透明、首个命中终止。
建筑可见性与 DDGI 命中查询共用该结构；未引入光追 pipeline、SBT、动态 BLAS 或软阴影。
片元可见性查询默认只调用一次 `rayQueryProceedEXT`：该结构只包含不透明三角形，
BOX 同样已经转换为表面三角形，不存在需要返回着色器确认的 AABB 或透明候选。
这是 [Vulkan 遍历规则](https://docs.vulkan.org/spec/latest/chapters/raytraversal.html#ray-opacity-culling)
允许的完整查询，起点、有限长度、双面和首个命中规则保持不变。若今后加入程序几何或透明建筑，
必须同步恢复候选处理。`RF_GPU_RAY_SINGLE=0` 选择保留循环的片元变体作同包对照；
软件 BVH 和 DDGI 最近命中查询仍走各自原有路径。
两种路径在几何边界的浮点求交可有少量像素差异，不能假定所有场景逐位一致。

### 顶部可见性缓存

`rf_gpu_indirect.inc` 在建筑代际更新时建立 XZ 列缓存，binding 10 保存每列所有相交图元的
高度界和一个严格覆盖整格的阻挡高度区间。只有凸三角形或真实 BOX 包含整格四角时才确认全覆盖；
不能把四条采样射线当作覆盖证明。明确无遮挡或整格被挡时直接返回，混合格、边缘和高度不确定时
仍执行原始向上射线。楼板有限厚度、斜面、多层和射线最大距离都参与判断。
默认启用；`RF_GPU_ROOF_CACHE=0` 在初始化时关闭，提供同版本精确对照。该缓存不替代太阳或局部灯遮挡。

### DDGI 漫反射原型

此原型沿用 DDGI 的探针射线和时间积累结构，目标是让地面与墙面反弹照亮天花板；
默认以真实几何短线段可见性替代方向距离矩，避免墙角过滤误判。
不是 RTXGI SDK 接入。`scene_architecture_prepare` 为建筑图元提供 sRGB 漫反射颜色，并通过
`rf_gpu_graphics_set_indirect_lights` 提交完整、与相机无关的固定灯表，最多 128 盏；固定灯同时
进入直接照明表，标记为固定来源的直接灯不会再次注入。实际楼板和门洞决定光传输，不依赖房间编号或 RTS 剖切。

- CPU 仅在建筑/地图代际更新时围绕固定灯布置稀疏规则探针，初始间距 768 RFU；超出 16384 个
  探针预算时统一加粗。灯表、几何元数据、布局与结果由各 graphics owner 独占，resize 保留。
  清空/替换建筑清除旧光场；无效输入保留原状态，帧在途时拒绝替换。
  预先为每个插值格保存八个探针索引；片元一次哈希定位格子，再连续读取邻居，避免八次独立查找。
- 首次 GPU 更新先以六个轴向射线做最多四次有限重定位，避开近表面并尝试从真实 BOX 内退出；
  位移不超过间距的 45%，目标净空为间距的 18%。BOX 元数据标记封闭实体；一般三角形只按双面
  距离避让，不根据不可靠的绕序推断内部。无法在预算内退出的探针停用。位置、有效性和距离矩
  使用同一次求值结果；静态几何代际不变时不反复移动，不将旧位置的辐照度混到新位置。
- 灯表 compute 后、阴影前，`graphics_indirect.comp` 每探针追踪 128 条确定性球面射线，
  通过硬件最近命中或软件 BVH 获得表面、法线和反射率，再检查该表面到灯的建筑可见性。
  固定灯与当帧非固定局部灯形成漫反射；每个首次命中再发射两条确定性、余弦加权的半球射线，
  在第二个命中表面检查真实灯光与遮挡，补充地面经墙面到接收面的第二次反弹。
  路径最多两次漫反射，不采样旧探针或同 dispatch 的输出，不依赖 workgroup 顺序，也没有反馈能量累积。
- 每探针默认存六个方向辐照度瓣和重定位位置，共 7 个 vec4；距离矩对照为 39 个 vec4。
  过多近距离命中的探针被停用；首次完整预热，随后每帧轮转最多 256 个。辐照度历史混合在大幅变化时加快响应。
  compute 写入与片元读取有显式屏障，正常帧不读回 CPU。
- `indirect.glsl` 在接收面法线偏移后查找八个邻居，用三线性、法线侧别和实际短线段可见性加权，
  排除穿过楼板/墙后的样本，再归一化有效权重。结果以非金属漫反射加入线性 HDR；直接光、曝光及室外填充不变。
  低权重邻居不能用固定分母压暗，否则会在天花板上出现探针网格。
  侧别、方向和可见性使用重定位后的实际位置；三线性系数保留原格点拓扑。接收点保留法线与
  朝相机的偏移，不移动可见几何，也不改变直接光射线。
- 建筑 owner 保留一份仅含 bounds/type/skip 的紧凑 CPU BVH，用于代际更新时筛选真实建筑实体。每个格的
  查询包围范围覆盖原格与最大 45% 探针位移，收集所有相交 BOX；不超过 32 个且没有三角形时，
  将完整列表复制到探针缓冲。片元直接做短线段/实体相交，空列表证明无遮挡。三角形、密集区域
  自动使用完整建筑 Ray Query / 软件 BVH，不能因列表装不下而丢遮挡物。没有逐帧 CPU 查询。
  缓存与建筑代际、探针布局共同更新，resize 保留；硬件路径按 BOX 表面、软件路径按实体求交。

`RF_GPU_GI_VISIBILITY=1` 默认启用局部几何缓存；`2` 强制完整建筑查询，画面应一致，用于性能
和像素对照；`0` 恢复旧距离矩，仅作误差诊断。旧路径保留八面体折边、方差权重与 8×8 距离矩。
`RF_GPU_GI_DEBUG=1` 强制完整查询，`2` 显示邻居总权重，`3` 为照度，默认 `0`。
不应将“距离矩说可见”视为无遮挡证明，也不能只纠正其遮挡分支：两类误判都可能在墙角制造暗斑。

`RF_GPU_GI=0` 在初始化时关闭布置、更新及采样；默认开启。隔离模型/固定光照实验通过
`disable_indirect` 同时禁用注入与采样。固定灯颜色和位置变化目前依赖调用者重新提交灯表；
动态局部灯在轮转更新到相应探针后生效，因此短时枪口光可能漏采或残留。
`RF_GPU_GI_BOUNCES=1|2` 在初始化时选择反弹上限，默认 2；1 保留同版本的一次反弹对照。
只改变 compute 注入，接收面仍读取同一个探针场，不增加片元邻居数量。
当前没有动态遮挡几何、任意网格内部的完整探针重定位、两次以上反弹或镜面 GI；
接收点偏移、有限探针密度和简化有效性判定仍有误差；无固定灯布局的区域暂不覆盖纯动态灯 GI。

### 天空漫反射与太阳反弹

`graphics_environment.comp` 从 `sky.glsl` 的相机无关方向函数生成 32×16 上半球方向缓存，
均匀采样方位角与方向 Y；随后归约为六个 E/π 方向瓣。该缓存不包含太阳盘或假地面，
按水平天空照度归一化，随当前天气/风/太阳参数逐帧更新。binding 14 由 graphics owner 持有，
复用云噪声体积；即使没有 SKY draw 也可以生成照明环境。compute 写后向后续 compute/fragment 建立依赖。

`scene_architecture_prepare` 安装建筑与固定灯后调用 `rf_gpu_graphics_prepare_daylight`。
自然光使用独立的 binding 15 探针场，围绕实际建筑表面布点，不依赖灯具、相机或房间 ID。
初始间距 768 RFU，超过 32768 探针预算时统一加粗；不会挤占固定灯场的 16384 探针预算。
两场复用布局、有限重定位、局部实体缓存和短线段可见性算法；建筑替换清空两场，resize 保留，
无效替换不破坏旧数据。首次完整预热，自然光之后每帧轮转最多 128 个探针。
片元采样算法由 `probe_sample.glsl` 共享，各场在编译时固定缓冲绑定。局部实体缓存覆盖完整列表，
嵌灯产生的密集楼板分片在预算内仍直接查询；不能截断遮挡列表来换取速度。

`combined_irradiance` 在两场间距、接收点偏移一致且插值格均存在时，逐角检查探针有效性和
重定位后的实际位置。只有两场探针位置完全一致才复用几何可见性、侧别和三线性权重；
辐照度、覆盖权重总和与归一化仍各自计算。单场缺邻居、布局独立加粗或位置不同则独立查询，
自然光无有效覆盖仍执行直接天空回退。默认启用，`RF_GPU_GI_REUSE=0` 恢复独立采样作对照；
旧距离矩和权重诊断不复用。该优化不减少反弹次数、探针数量或遮挡几何。

`graphics_indirect.comp` 的自然光变体只注入天空与太阳，不重复注入灯具。首次射线逃逸获得天空；
命中表面获得经建筑遮挡的太阳照度，并用余弦加权射线估算天空和第二次表面反弹。
反弹路径限于 16 m 的局部查询范围；任何 miss 必须另行确认射线逃出整个建筑结构后才接入天空，
不能把局部查询距离当作开敞天空。最多两次漫反射、不读取旧场反馈；太阳直接项仍单独计算一次。

片元把两场的漫反射相加一次。自然光场无有效邻居时，用八条确定性半球射线回退到有建筑遮挡的
直接天空采样，避免缺探针时漏光；空建筑使用六瓣环境缓存。`RF_GPU_GI=0` 关闭探针与反弹，
仍保留此直接天空回退。`RF_GPU_DAYLIGHT=0` 完整恢复旧半球填充，默认 `1`；
`sky_illuminance=0` 或隔离实验 `disable_indirect` 也使用旧路径。

照度诊断的 GI 通道包含天空漫反射以及太阳/灯具反弹，正常自然光路径的艺术填充通道为零。
稀疏探针、六瓣表示、有限反弹范围和有限射线数会造成开口附近偏差；轮转及历史混合有更新延迟。
这不是完整路径追踪，尚未接入镜面 IBL 或 GTAO。深进深房间需要真实灯具，不能通过全局加亮天空
模拟室内工作照明；车间两层灯具由 `tools/frontier_station_map.py` 维护。

### 提交与合成

GPU 独立程序天空与体积云消费本页的同一太阳，compute 求值、HDR 合成与资源边界见[GPU 天空](gpu-sky.md)。CPU 继续使用旧天空。

天空 compute 后、阴影绘制前，`graphics_light_tiles.comp` 为每个 16×16 屏幕块生成五个 32 位候选灯掩码，覆盖 160 灯。
point 使用有限球体，spot 使用有限球扇形，对块视锥的四个侧平面及相机前平面做保守相交测试；
保留像素与世界空间容差，不读取场景深度缓冲、房间身份、接收面法线或建筑可见性。
同一 compute 另外生成相机前向的深度分段灯掩码，片元将屏幕块与所在深度段取交集。
分段只按光源体积保守筛选，首末段覆盖无限远边界；当前为 32 段，每段 4 m，仅增加 640 字节。
相机朝向的量化长度及边界容差同时进入投影，远处物体不会因超出分段范围丢灯。
`RF_GPU_LIGHT_DEPTH=0` 只关闭深度段，保留二维屏幕灯表，默认 `1`。
`RF_GPU_LIGHT_CLUSTERS=1` 在此基础上增加可选三维表，默认 `0`：先复用屏幕/深度掩码，再将候选光源体积
与每个屏幕块、深度段的联合空间 AABB 相交。spot 使用有限球扇形的保守包围球；相机量化
基向量按实际矩阵求逆，保留屏幕 Y 翻转及边界容差。末段无限远时保留原候选集合。
compute 两阶段之间及片元读取前分别有屏障；1080p 的三维表额外占 5,222,400 B/owner。
不透明 WORLD 深度预通道继续使用原附件与覆盖合同；灯表不以不透明深度排除透明来源。
因此透明物和楼梯开口沿用真实光源；精确半径、锥角、背光面和遮挡判断仍在片元执行。
片元按原灯索引顺序消费位掩码，不重排光照累加。混合相机/投影的 draw 和屏幕空间 viewmodel
退回完整灯表。各 graphics slot 独占掩码缓冲，resize 在退休后重建；compute 写入到片元读取有显式 barrier。
`RF_GPU_LIGHT_TILES=0` 在初始化时禁用筛选，供同版本画面和性能对照；默认启用。

1. 未由当前建筑查询完整覆盖的不透明 WORLD 几何绘制阴影：太阳采用三个相机附近的稳定正交范围；最多两盏聚光灯使用透视阴影。
   每张阴影图用独立光空间包围盒剔除，复用连续绘制的 pipeline/vertex/index 绑定；不套用相机可见性。
2. 阴影为 1024×1024 D32，深度在 GPU 内复制到 storage buffer；片元以 16 次深度比较求值连续移动的 tent PCF 核。
   权重随 texel 内的小数坐标变化，跨 texel 边界连续，不依赖硬件深度过滤扩展或随机抖动。
   此复制不经过 CPU readback。使用实际可见模型几何，碰撞盒不参与阴影。
3. WORLD、天空、透明、特效与 viewmodel 写入 RGBA16F 线性 HDR；世界深度为 D32 reversed Z。纹理先由 sRGB 解码，再参与过滤和着色。
4. compute 执行曝光与 ACES fitted 色调映射，将曲线肩部按其渐近值归一化，避免中高 HDR 值提前越过显示白而被硬裁切；
   最后编码为 sRGB RGBA8。极高亮度仍受八位输出量化限制。HUD 随后合成，保持界面颜色。正常帧直接 native present。

GPU timestamp 将 `world_draw_ms` 按命令区间拆为天空 compute、灯表 compute、DDGI 更新、阴影和主场景。
阴影区间含深度复制；主场景再拆为 WORLD/天空合成、透明/特效、viewmodel、后处理/视频合成及 HUD。
`detail_ms[0..5]` 依次保存灯表及这五个主场景区间，`detail_ms[6..8]` 保存 DDGI、接收缓存更新与合并蒙皮；没有 draw 的层也写入边界时间戳。
这些区间不能直接称为 Ray Query 耗时。native、离屏和 capture 共用读回解释，离屏不等待未写入的 present 查询。

光照计数只在 `RF_GPU_LIGHT_PROFILE=1` 的独立片元变体中启用，同时要求设备的
`fragmentStoresAndAtomics`。计数缓冲按块累加已着色调用、候选灯、顶部/太阳/局部可见性调用、
局部可见结果及 PCF 核调用，GPU 完成后才读回。它包含 overdraw，且存储副作用可能改变早期深度优化；
不是最终可见像素数或 RT 硬件计数。顶部计数只计缓存未能判定后的回退查询；探针 compute 射线不计入片元计数。普通 shader 没有这些原子操作，计数运行不得作为正常性能证据。
诊断消融可以分别跳过 roof/sun/local 可见性、PCF 或替换 BRDF，明确改变画面；
所得时间差只代表该改动后的边际成本，不是可相加的独立子系统耗时。

材质使用 GGX 镜面、Schlick Fresnel、粗糙度、金属度和标量自发光。平滑法线来自资源；无显式法线时用几何法线。风格化材质调整漫反射响应，仍消费同一组实时灯和阴影。当前粗糙度/金属度为 draw 标量；没有承诺 normal/ORM 纹理、镜面 IBL 或完整动漫材质，漫反射 GI 范围限于上述原型。

静态道具由 `rf_gpu_scene_world_gpu_prepare` 按 primitive 的 RFM2 v2 材质记录读取
金属度/粗糙度 u16 常量，编码到现有 graphics draw；粗糙度至少为 0.06，避免零值被视为
未配置并回退默认值。后续旧格式中相同字节承载 alpha/toon，不能作为 PBR 常量解读；
这些道具保持原有默认响应。几何、缓存身份、纹理和玩法状态不随材质接线改变。

关闭自然光后的旧环境填充按受光法线的世界 Y 分量，在较亮的冷色天空填充与较暗的暖色地面填充之间插值，
再消费上述建筑顶部可见性；阴影区保留表面朝向的明暗区别。不采样天空纹理，不代表间接光传输或 IBL。
直接光在太阳强度为零、PBR 背光面或聚光灯锥外时跳过无贡献的 BRDF/阴影求值；风格化材质保留原有暗侧响应。

## 边界与预算

- 太阳三个范围半径为 4096、20480、65536 RFU，即 8、40、128 m，512 RFU = 1 m。
  近级每纹素覆盖 15.625 mm，法线偏移保持为该级纹素宽度的 0.4 倍；光空间中心按整纹素对齐。
  每级光空间边缘向后续有效级别连续混合；
  零权重级别不读取阴影，内区剩余权重归零后停止。过渡带可能采样两级，预算不能只按单次 16 tap 估算。
- 最多两个聚光灯动态阴影名额按光强与相机距离评分分配，固定灯表本身不重排；所有局部灯另有建筑 Ray Query / BVH 遮挡，点光源不再穿过已纳入的实体墙板或楼板。
- 半透明、粒子和 viewmodel 不投射 WORLD 阴影；不透明角色、静态物与实验区球体参与投影。
- 环境填充为法线相关半球颜色与顶部可见性近似，没有反射探针；金属只反射当前直接光。
- 旧 `light_q8` 等字段在部分几何存储中暂时保留，但 GPU shader 不消费烘焙亮度；旧整数兼容 draw 被拒绝，兼容索引上传已删除，旧 shader 不再编入 SPIR-V。
- 暂未建立本版本正式性能基线，不据短帧诊断承诺帧率。

实验区普通进入默认关闭，由 Runtime 独立开关和展示时钟控制球体与移动灯；性能隔离期间不提取实验灯、地图灯或瞬时灯，太阳与环境填充保留，阴影实际绘制另计数。登记与生命周期见[实验区合同](../reference/experiment-labs.md)。

实验区和验证入口见[光照指南](../guides/gpu-lighting.md)，当前交付顺序见[活动计划](../plans/README.md)。
