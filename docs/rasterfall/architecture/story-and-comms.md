# 剧情会话、任务与 NULL 通讯

> 状态：当前
> 所有者：Rasterfall Story Runtime
> 事实入口：`rasterfall/include/rf_story.h`、`rasterfall/src/rf_story.c`
> 最近核对：2026-10-04

## 状态与扩展边界

Game Runtime 持有唯一 `rf_story`。FPS、RTS、HUD 和终端读取同一会话及任务投影；布局切换不会创建会话。
`rf_story_update` 在权威逻辑步读取 session、Runtime Map 和真实 actor；展示层不得更改节点、任务或 actor。
当前接入限定离线会话。加入联机需要主机命令、节点版本及状态同步，不能在各客户端独立运行触发器。

脚本是 `rf_story.c` 中的不可变节点表。每个节点有稳定编号、会话编号、说话者内容 ID、镜头 ID、地点、
台词、回答、下一节点、任务事件和优先级，另保留演出动作与条件字段。新增剧情应扩展内容和事件，
不要在 HUD 或输入分支中判断具体台词。现阶段动作/条件字段为保留项，不代表已有通用剧情语言。

会话 101 为前哨站介绍，102 为实验区介绍；编号写入存档后不重新分配。区域检测使用
`outpost_safe` 和 Runtime Map 的 `experiment` region，而非屏幕位置或参考图坐标。
未触发、排队、进行、中断、完成、主动关闭有独立状态。内容触发策略独立于存档进度：当前两段使用
`RF_STORY_TRIGGER_EACH_GAME`，每个 Game Runtime 生命周期各触发一次；离开再进入或重建世界不会重播。
每局触发位不写入存档，重新启动可再次触发；读档恢复的排队/活动会话计入本局，避免重复入队。
永久一次性内容可配置 `RF_STORY_TRIGGER_ONCE`。区域检测只在由外到内时发出进入事件，
停留不会循环播放；排队、进行或中断的同一会话不会重复入队。区域占用是瞬时状态，不写入存档。
队列按内容优先级
选择，平级按到达顺序；当前回答不会被普通介绍替换。战斗或其他输入所有者可延后新的普通会话。

回答必须携带生成它的 `session_revision` 与 `node_revision`。一次成功回答即改变节点版本，重复或
过期请求不推进新节点。当前两段为无选项的线性演出，通过节点的 `auto_next_node/auto_task` 推进和发布任务。
台词计时在 Story Runtime 的 live 逻辑步推进：无语音时暂按约正常语速，固定半秒，加每个中文字 250 ms、ASCII 字符 100 ms、
逗号 200 ms、句末标点 400 ms；按 UTF-8 字符计算。收起/中断时暂停，正常恢复后继续；
普通中断在角色恢复可用且无战斗、无其他输入所有者时自动重连。末句到时自动完成并关闭视频、释放令牌。
带版本的 `choice=-1` API 保留给计时器和命令边界，玩家 HUD 不显示回答或继续按钮。收起只隐藏展示；
主动关闭记为取消，不能记为完整阅读。历史保留有界节点/回答记录，文本由稳定节点表解析。

视频窗口默认关闭，仅演出期间打开，贴近屏幕左侧、位于 RTS 地图上方，内容区为固定 2:3 竖框，不随战斗缩放，
没有 `-` 或 `X` 点击按钮。台词位于屏幕顶部居中，FPS/RTS 共用半屏宽、四行字体高度的固定区域，
白字配局部深蓝灰字影，不绘制整块底板，标明说话者。新台词在下方出现并把旧台词向上挤；超出四行的旧内容从顶部裁剪。
`rf_player_ui_state` 持有有界字幕队列，由 Game Runtime 根据历史版本增量送入，逐条独立计时；
活动节点保持可见，节点结束后约 220 ms 快速淡出，新台词不会重置旧台词的寿命。无人说话且字幕消失后不保留可见元素。
Enter 展开同一区域的历史记录，以低透明度蓝灰底提示输入焦点；上下键和滚轮查看记录。Enter 或 Esc 收起后回到活动字幕，
没有活动会话也能查看历史。展开历史不会手动推进演出，也不会停止字幕各自的计时。
字幕寿命、滚动和焦点属于 Runtime 展示状态，不进入剧情存档或 Game 玩法状态。文字按同一字体换行并裁剪。

任务有稳定 ID、进行/完成/失败/取消状态及可选目标 ID，独立于窗口与对话生命周期。
`rf_story_emit` 只接受业务事件：进入实验区域、打开真实编织机、查看可用蓝图、设备失效等。
关闭通讯或打开地图不完成制造目标。目标位置从 Runtime Map 的真实 region/object 解析；
不存在的目标不发布地图坐标。本轮引导到查看蓝图为止，不自动开工、不发放资源。

## 换图边界

前哨站介绍与实验区介绍属于当前地图的演出。换图入口先验证目的地图，卸载前释放旧角色控制与镜头；
目的地图加载和 session reset 成功后调用 `rf_story_leave_world()`，清除活动节点、待播队列和台词计时，
关闭视频、清空活动字幕并释放聊天输入焦点。旧会话/节点版本同时失效，未播完或未播放的当地演出记为
中断，不记为完成；保留每局触发位，返回前哨站不会自动重播。预检失败不清理原演出。
聊天历史和独立剧情任务保留，旧地图目标坐标立即失效，在对应世界重新解析。站点任务短讯仍为纯字幕。
已绑定世界的代际变化也结束旧演出；新建或读档的未绑定 Story owner 则继续正常解析与重连。

## 边缘站点的临时通讯

站点通讯使用独立稳定会话 301～306，由 `rf_story_frontier_events()` 消费 session 的一次性任务事件。
事件涵盖抵达、首次周期感染者、整备、最终进攻、胜利与失败；任务阶段不会等待台词、窗口或镜头。
抵达短讯说明西侧蓝色基地、500 生命与敌方基地中央红色核心；后续短讯始终以摧毁敌方核心为目标，
设施接管和清剿不再表述为胜利条件。核心胜负由 session/Game 发布，字幕只读事件。
同一 mission ID 内排队去重，FPS/RTS 共用同一 Story Runtime 和字幕历史。

NULL 不在站点世界。V0 使用同一说话者身份与顶部计时字幕，连接状态为 unavailable，
不创建 `null_comms` 实体镜头、不打开伪造实时视频，也不复制 NULL actor 或模拟第二张地图。
这些短讯允许在战斗中播放，正常计时和输入仍由现有 Story/Player UI 路径处理。
无镜头 ID 的节点由 `rf_story_subtitle_only()` 标记为字幕通讯；界面只绘制紧凑身份和视频不可用提示，
不绘制空视频框，也不拦截其区域内的 RTS 战场选择或移动点击。

301～306 是本次任务的临时演出，不写入剧情进度存档；既有 101/102 的存档与每局触发规则保持独立。
换图、重试或 mission ID 变化会清除旧任务通讯的队列、活动节点、触发位和镜头/令牌引用，
新任务可以重新发布抵达短讯。任务、设备产权、制造资源与结果仍由 session/Game 持有，
字幕完成和通讯关闭不授予资源、接管设施或推进清剿阶段。

## NULL 行为与临时控制

此前 session 为 NULL 永久设置 `control_disabled=1`，而共享持枪采样器以 `!control_disabled` 作为
待机轮换条件，导致自然姿态一直被禁止。直接移除此标志还会触发 `companion` 跟随玩家策略。

驻地行为现在通过通用 `ai_stationary` 表达，保留驻地部署目标；角色继续经过普通 AI、动作计时与
共享随机持枪待机。`control_disabled` 仍只表示玩法中的高优先级控制。名称统一投影为 `NULL`，
session 的 `null_actor_index` 是 authored actor `id=null` 在本次生成中的解析结果。

通讯取得独立的 `movement_hold_token`，仅限制自主路径移动，不跳过 actor 更新，也不重新开始动画。
伤害、死亡/倒地、腾空、特殊控制、战斗目标或被强制移出镜头锚点会中断普通通讯并释放令牌。
中断节点保留，可显式恢复连接；恢复重新解析实际状态。正常结束、关闭、换图、读档前卸载与关机
均走同一释放路径。释放需同时匹配 world generation、actor ID、actor combat generation 和令牌，
旧会话不能修改已复用的槽位。没有保存或恢复旧路径意图，解除后普通 AI 根据当下部署重新决策。

当前注视采用有界平滑身体朝向，保留现有待机姿态。尚未增加独立头颈/眼球 look-at；将来可把同一
镜头位置交给角色表现层的附加骨骼层，不应另建整套人物动画或不断移动镜头掩盖朝向问题。

## 实体镜头与真实画面

`rf_story_camera_entity` 是 session 作用域的设备实体，稳定内容 ID 为 `null_comms`，有独立 generation、
绑定 actor 身份、世界变换、裁剪和取景参数。外壳与辅助 Scene 视图消费同一 `view`。外壳是展示设备，
目前没有制造、碰撞或拾取规则；主视图可见，自身视频视图排除自身外壳。

创建时沿 NULL 前方候选光路检查真实碰撞，有限尝试合法固定距离；没有合法位置就发布不可用状态。
节点镜头 ID 查找独立的 `story_camera_profile` 表，集中定义候选距离、水平偏移、眼高与俯仰；
更换取景无需改会话控制器。`null_comms` 优先距离为 720 RFU（约 1.41 米），受阻时尝试 680/640 RFU；
机位沿世界正 Z 方向布置，无侧偏，以零俯仰水平拍摄；高度位于标准站立身高中点上方约 35 厘米，
约为离地 1.23 米，取景偏重角色上身并保留身后环境；角色继续使用既有平滑转身面向实体镜头。
光路碰撞查询与镜头使用同一高度。实际投影仍服从 Scene 的约束。
通讯期间机位固定，不随 actor 每帧绕行；位置明显偏离锚点则中断。实体查询验证世界/actor generation，
失效后不解引用过期身份。连接尝试有时间上限；重试由显式恢复操作发起，失败不会卡住游戏循环。

视频复用真实 Scene 快照和辅助视图资源，参数必须与 GPU 实际投影一致，不能仅修改元数据。
通讯内容区在 720p 为 160×240，内部按相同 2:3 比例渲染为 240×360；合成只做等比缩放，避免人物压缩变形。
采样、外壳提交、刷新频率与共享资源生命周期由 [GPU 架构](gpu-rendering-architecture.md) 所有。
通讯与 RTS 单位视频使用独立辅助视图槽，选中、切换单位或收起 RTS 底栏不会占用或关闭剧情画面。
当前世界不按玩家距离卸载普通 actor；远程通讯不额外激活或模拟整张地图。

## 保存与开发入口

保存为带版本和校验的显式 little-endian 记录，通过写临时文件、关闭、同目录 rename 替换。
只保存触发/完成/取消状态、排队会话、进行中节点、收起状态和任务状态，不保存指针、actor 槽位、
临时控制令牌或镜头矩阵。加载先验证完整记录，再整体替换；下一次 update 才解析真实说话者并连接。
Windows `__rename` 与 `__openat` 使用同一相对路径解析，因此从不同工作目录启动仍写入同一目标。

本存档是剧情进度文件，**不是世界存档**：制造中的材料/能源/成品和世界对象仍遵循 session 重建语义。
会话历史当前只在本进程有界保留，加载恢复当前节点后重新开始历史记录。坏档保持当前状态并报告失败；
保存失败保留 dirty 状态，由 runtime 报告并限制重试频率。

`rf_story_reset(id)` 与 `rf_story_replay(id)` 是开发接口；0 仅用于全部重置，101/102 对应两段介绍。
普通玩家命令无跳节点权限。API 的回答/重播/重置以 1 表示成功、0 表示拒绝；文件读写以 0 成功、
-1 错误表示，load 另以 1 表示文件不存在。统一命令适配器须显式转换，不能直接把两类返回码混用。

逻辑回归 `rf_story_logic_test` 覆盖队列去重、战斗延后、版本拒绝、收起恢复、事件任务、存档重连、
实体槽复用、异常释放和待机轮换。视觉取景、真实背景变化与原生输入另由 Windows 实机验证，
不能用逻辑测试替代。UI 输入验收脚本为 `tools/gpu_player_ui.ps1`，操作与执行范围见活动验收记录。
其 `All` 路线在完成前哨站介绍后退出进程，再以隔离存档启动 `Resume`，检查 UI 模式、任务恢复
及新局介绍重新连接；`Resume -ResumeDirectory <目录>` 可单独复查先前的 Outpost 验收存档。
上述原生脚本仍包含旧回答/收起步骤，自动演出改动后不能直接作为现行交互验收结论。
