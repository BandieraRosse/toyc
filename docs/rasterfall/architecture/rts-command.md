# RTS 核心指挥

> 状态：当前
> 所有者：Game Runtime 选择与 HUD；session/Game 单位命令
> 事实入口：`rf_rts.h/.c`、`rf_rts_runtime.inc`、`rf_rts_ui.inc`、`rasterfall_session.c`

## 选择与编组

`rf_game_runtime.rts` 拥有选中集合、主选单位、悬停、拖框、分页与十个编组。成员使用 actor 槽位、
actor ID、combat generation 和世界代际共同验证；死亡或槽位复用剔除成员，world 重载清空所有选择和
编组。集合覆盖整个 Game actor 池，不另设小队人数上限。卡片分页只影响展示。

本地玩家和普通友方 AI 可选，敌人、基地核心与开发者展示角色不进入集合；倒地友军可查看，但不接收移动。
左键点选，空地取消；左键拖动矩形按屏幕中的身体中心选择，Shift 点选/框选追加。所有 UI 热区先消费输入，
框选必须从世界区域按下开始，鼠标释放完成；暂停、失焦、通讯焦点、视角切换或右键取消未完成拖动。
Windows 轮询保留本批第一次按下边沿和坐标，后续移动/松开不覆盖起点；最终指针和按住状态仍用于结束拖动。
因此按下、拖动和松开落在同一慢帧内时也能完成选择。UI 拦截按下起点，悬停使用当前指针。
失焦判断读取平台当前焦点快照，不能只等待启动界面可能已消费的首次焦点事件。

默认 `1…9、0` 召回对应编组，`Ctrl + 数字` 用当前选择完整重设该组，未选中的旧成员移出；空选择时清空该组。
编组条也支持左键召回、Ctrl 左键重设/清空。一个单位可以属于多个编组，重设不影响其他组。数字动作在 RTS 内优先消费，
FPS 武器槽仍使用原绑定。主选默认是集合中第一个有效单位；悬停只高亮并显示简略信息，不改变选择或移动对象。
编组条从左到右仍对应 `1…9、0`，格内仅显示有效人数，不显示组号。

## 权威移动

`RF_PLAYER_RTS_MOVE/STOP` 遍历身份仍有效的选中成员，交给 `rasterfall_session_rts_order_actor_height()`。
session 校验运行模式、存活、阵营、身份、剧情移动约束、目标地面支撑和碰撞。多选按稳定顺序分配小型方阵
落点；兼容地图的偏移落点不通行时尝试原点击点。前哨站落点吸附到一米格中心，编队从点击格向
X/Z 正方向按一格间距展开；点击格不可用时整条命令失败，其他编队格失败只保留对应成员原命令，
不回退公共落点。结果报告实际接受指令的人数。`rts select N` 的 N 是 actor 槽位，
`-1` 清空，`0` 是本地玩家。

### 前哨站目标格预约

Game 在正式 actor 上持有目标格、支撑高度、combat generation 和 navigation generation。
目标格同时检查地形支撑、身体净空、当前单位占格与其他 actor 的预约；占格查询沿用正式身体的
垂直区间，因此上下层不会互相阻挡，自己的身体和预约允许重复下令。
预约仅约束命令终点，经过格仍使用既有动态碰撞；不会自动让路或生成通路排队。
新目标通过校验后才替换旧预约；失败保留原命令，并显示 1.8 秒的不可走或占用/预约提示。
停止立即释放，到达后由实际身体占位接替预约；固定步与下次命令清理死亡、身份变化和到达的预约，
导航重建立即释放全部预约，换图初始化清空。FPS 切换仍保留已接受的移动意图与预约。

离线边缘站点的任务和 Game 仍在进行时，倒地本地玩家保留选择、编组、移动和停止指挥能力，
可以把存活队员调到身边救援。输入层不以本地生命状态关闭 RTS 指针与数字编组；统一命令层只对
选择、移动、停止开放此例外。倒地单位可查看，身体移动仍由 session 拒绝；制造和设施接管不能借此执行。

本地玩家目的地仍归 session，普通 AI 的 `command_destination_active/command_x/command_y/command_z` 是 Game
权威移动意图，在普通 AI 固定步内优先于出生部署和副官跟随，复用既有个体寻路、碰撞、持枪、索敌和开火。
本地玩家每个固定步通过 `toy_game_actor_navigation_target_height()` 查询 Game 路点规划；兼容地图的普通同层复用既有直达缓存，
前哨站查询共用一米分层格图与格连线，
session 将转向点变为世界坐标方向意图，直接交给正式玩家输入和加减速，不在规划查询中推进身体。
方向存于 session 的每步临时输入，不能按相机前进/侧移键量化；否则转向或瞄准可使身体偏出已证明线段。
临时路点使用较小输入死区；
只有最终目的地到达才能完成命令。实际碰撞阻挡清规划重新查询，射击仍可朝向敌人。
RTS 玩家通过 `toy_game_move_player_input_supported()` 推进：Game 按现有加减速计算下一步实际位移，
正式地形与单位碰撞滑行后检查身体是否仍落地，保留坡道接缝的部分足迹支撑规则。
惯性或滑行步子离开支撑时回滚该步身体状态、清速度/余数并报告阻挡，
session 清规划后重查；不是只检查当前输入所指的理想线段。兼容地图的普通 FPS 输入仍允许离边掉落；
前哨站的所有落地单位先检查格通行，拒绝进入缺支撑的格子。
跳跃、击飞和已经进行中的空中运动仍归原有 Game 运动规则。
前哨站显式命令以最终格中心 2 RFU 范围为到达条件，AI 最后一步不超过剩余距离；
本地玩家在一个移动步长内通过 Game 身体碰撞完成末段并清速度与余数，阻挡时保留命令，
不以原有部署半径或 250 RFU 玩家容差提前完成。目标预约同样保留到格中心到达。
兼容地图到达后留在目标附近；停止把目标设为当前位置。选择、镜头和 UI 不推进第二次玩法或动画。FPS 切换不撤销
AI 已接受的命令，本地玩家在 FPS 期间由手操输入接管；本地规划清除而最终目的地保留，恢复 RTS 后
从实际位置重新规划。新命令、停止和合法传送也清本地规划。RTS 指令目前仅在离线 session 开放。

旗帜保留物件、携带和区域查询用途；旗帜搬动、携带与初始 roster 不给队友写入旗帜部署点。

Game 可选自动分队只在成员没有显式移动/停止、救援和控制约束时提供移动目标，
详见[玩法分队合同](gameplay.md#可选普通角色分队)。它不使用或重设 runtime 的十个 RTS 编组，
也不覆盖 `command_destination_active/command_x/command_z`。到达和 STOP 继续保留用户意图；
对单个成员下令仅屏蔽该成员自动移动，其余成员保持原分队身份。领队倒地或槽位复用由 Game
稳定身份处理，不把旧 RTS 选择转成新 actor 的分队指令。
正式 session 的 actor 没有旗帜 assignment；旧商店及其 assignment 页面和请求已移除。
Hurd 状态查询按其 roster 身份统计人员，旗帜区域条件仍是该任务自己的只读条件，不控制单位路线。

## 只读展示

`rf_ui_layout_resolve()` 同时服务绘制和命中。底栏依次为单位信息、单位镜头、操作区，编组条位于信息框上方。
单选左侧为角色实际 body bind mesh 生成的线框，绿/黄/红对应当前生命比例，右侧按数据行显示名称、武器、
生命、回避、弹药与状态。`rf_rts_portrait.c` 首次读取对应模型生成小型只读网格遮罩后立即释放资源；
HUD 以 canvas run 绘制，不上传 CPU HUD 图像、不修改世界中的姿态。多选使用同一身体图标和独立生命条，
滚轮或翻页按钮浏览，点击卡片单选。增加属性可扩展信息行，增加角色沿正式 character profile/recipe 选择模型。

绿色脚底圈、目标菱形和连线由当前 actor 与真实命令目标投影到 HUD；连线表达移动意图，不承诺实际寻路路线。
标记和框选轮廓不会覆盖底栏及视频。地形与玩法支撑保持原来的分层。

单位镜头由 `rf_player_runtime.inc` 每帧读取主选单位的位置、高度与朝向，在其正前方保持固定距离；
不申请剧情 hold，也不强制演员转向。GPU WORLD 子视图读取与主视图同一份冻结世界，按卡片实际宽高比渲染，
并沿辅助镜头低频刷新合同合成到信息框与操作区之间；画面铺满卡片，不显示标题或姓名。
RTS 单位镜头使用独立 AUX 槽，与剧情镜头同时显示，各自持有身份、刷新与失败状态。
原通讯/设备槽仍优先设备预览。收起底栏、取消选择、镜头失效或换世界只停止对应视频；CPU 后端显示
镜头不可用。来源身份变化先清除旧 live 状态，新画面成功后才显示实时视频。

## 建筑与楼层 V1

Runtime Map 的 `kind=building_floor` region 提供 building、level、floor_y、ceiling_y 和 roof。
RTS 复制这份空间元数据，按世界代际清空；楼层焦点、镜头距离、手动选择和剖切动画属于 runtime
视觉状态，不写入 Game。全貌显示完整屋顶；点击建筑聚焦屋顶，顶部按钮显式进入一层、二层或屋顶。
近距离滚轮进入建筑最低楼层，拉远恢复全貌；手动选层保持到显式切换或拉远。聚焦单位读取主选身份及
实际脚底高度，跟随其当前楼层。恢复全貌还原进入前的镜头位置和距离。

楼内点选和框选按脚底高度过滤当前层，楼外单位照常选择；已选集合及编组不会因切层消失。
友军显示楼层标记，敌军不通过 HUD 透视定位。右键拾取只接受当前层的真实支撑面，命令携带 Y；
session 用目标 Y 校验支撑、净空和身份，阵型偏移保持同一层。旧 X/Z 请求按接收者当前高度查询支撑。
小地图仍按接收者所在层解释 X/Z，跨楼层操作使用主视图。

Game 的显式楼层命令在既有分层 flow nodes 上按目的地优先搜索，分段保存最多 64 个路点，
长路线到段尾后继续规划；边连接使用正常 actor 足迹和移动碰撞，并检查中心连续支撑。
Game 合并显式跨层搜索为一个可续跑任务，保存起终点附着、堆及邻接扫描游标。
每次规划查询最多处理 4096 个候选和约 4096 个实际试走样本；最后一条连接最多额外 76 个样本。
预算取决于工作量，不读取墙钟；未完成时返回等待，session 保留最终命令且不移动身体。
其他 actor 排队，不清空未完成任务；停止、新命令、身份/位置失效及地图重建使旧任务失效。
动态细化只追加节点，续跑时清除新增节点的 parent scratch；既有节点身份和有向边缓存仍有效。
兼容地图完整搜索最多展开 4096 个节点，前哨站允许逐步展开整个有界格图，失败等待 1000ms 后重试。
楼层入口可能远离重叠 X/Z 的起终点，
搜索不裁掉固定距离以外的楼梯连接。角色半径的有向边缓存独立于感染者缓存，地图重建同时清空。
试走前用候选地面的高度区间及正常台阶高度做保守连通筛选；缺少坡道或连续台阶的重叠楼层
直接排除，通过筛选的连接仍由原 transactional movement 证明。
路径属于权威移动状态，镜头不推进身体；本地玩家通过原 session 输入推进一次，AI 由固定步推进。
楼层不同不会因 X/Z 相同而提前完成。自动跟随和救援仍保留既有策略，首版跨层调度使用显式 RTS 命令。

GPU 主视图在选中建筑 bounds 内按 ceiling 丢弃上层片元，约 220ms 有序抖动过渡；原几何仍参与
shadow pass，碰撞、射击、导航和世界缓存不变。单位/通讯 AUX 的 world_only 视图不上传剖切参数。
CPU 主视图按同一楼层元数据隐藏上层 draw/prop/actor，箱体在层顶截断，切换即时。

首图回归读取正式楼层和守军 region，覆盖楼板上下两份支撑、普通 actor 通过楼梯往返
一层→二层→屋顶→二层→一层；选择回归覆盖重叠 X/Z 的楼层过滤和世界切换清理。
`tools/rts_floors_check.py` 通过目标 HWND 的正常输入检查正式首图楼层按钮、目标高度及 native capture，
记录实际退出码；固定诊断取景不替代完整行动路线。

## 原生指挥回归

### 命令面板与网格辅助视图

右下角使用三列方形命令卡，停止、镜头跟随、FPS、网格四个按钮共用绘制与命中的矩形；
其余槽位只是空背景，不接收命令。停止和跟随在未选择单位时禁用。悬停解释卡固定在面板上方，
显示功能、绑定快捷键、不可用原因以及跟随/网格开关状态，悬停不执行操作。

网格视图默认关闭，按钮与 `rts grid 0|1` 通过统一命令入口修改 `rf_player_ui_state.grid_view`。
开关不改变 Game；FPS/RTS 切换保留开关。CPU 和 GPU 共用 Canvas 在主画面上叠加一米格线，
只投影当前楼层或玩家所在层，并跳过屏幕外与投影不足 3 像素的格子。该辅助叠加不做世界遮挡，
可透过建筑查看选定层；它不参与碰撞、导航、光照或单位 AUX 镜头。
GPU Canvas 将裁剪后的每条格线作为一像素宽四边形（两个三角形）提交，避免按斜线像素拆分 HUD 矩形；
同高度、同状态且投影端点连续的格线合并提交，颜色或高度变化处分段，状态标记仍逐格绘制。
CPU Canvas 保留扫描线回退。友军动态颜色直接遍历其身体足迹，不为每个足迹格重复扫描全单位池。
性能诊断可设置 `RF_GPU_CANVAS_LINE_REFERENCE=1`，在同包内恢复矩形扫描线，比较原生帧时间与层准备开销；
正常运行不设置此变量。
颜色为绿：可走；蓝：建筑内可走；红：静态身体阻挡；灰：该层缺少支撑；黄：单位占用；
紫：目标格预约；橙：敌人占用。身体实际占位优先于预约，预约优先于静态状态。

UI 准备阶段从 Game 静态格引用、支撑和身体净空派生颜色缓存，以 world/navigation generation 和
查看高度为失效键；每帧从正式单位占格与有效预约更新动态颜色。缓存属于 UI，绘制只读，
异步 Scene 不持有 Game 或 UI 缓存指针。图例与命令卡解释颜色，关闭后跳过准备和绘制。

选择/编组的整池容量、重设与组间独立、身份失效、框选方向和阵营过滤，以及移动/停止/旗帜独立性进入逻辑回归。
本地玩家回归覆盖共享规划不推进玩法、挡墙路线、临时路点死区、最终目标、单次固定步、停止与 FPS
接管射击；连续 session 验证既有有限/无限备弹换弹、干匣和已在换弹状态不重复启动，以及 FPS 手动换弹。
命令回归覆盖首图倒地指挥、存活接收者移动与停止、倒地身体不动，以及失效身份、世界、联网、控制和失败拒绝。
`tools/rts_command_check.py` 通过目标窗口的 Win32 → SDL 输入，检查真实道路小组、点选、框选、编组重设、
召回、卡片单选、悬停不改选择、逐成员移动与停止，保存 GPU capture 和实际进程退出码。审计只读取状态，
不注入玩法命令；窗口必须取得前台且系统鼠标定位成功，权限不足或失焦时停止测试，不向其他窗口发送全局按键。
全屏验证使用实际 `--fullscreen` 或 F11，物理鼠标路线不补投鼠标消息；短手势检查同批按下/松开的保留。
原生操作与退出规则仍见 [Windows Native](../guides/windows-native.md)。
