# RTS 核心指挥

> 状态：当前
> 所有者：Game Runtime 选择与 HUD；session/Game 单位命令
> 事实入口：`rf_rts.h/.c`、`rf_rts_runtime.inc`、`rf_rts_ui.inc`、`rasterfall_session.c`

## 选择与编组

`rf_game_runtime.rts` 拥有选中集合、主选单位、悬停、拖框、分页与十个编组。成员使用 actor 槽位、
actor ID、combat generation 和世界代际共同验证；死亡或槽位复用剔除成员，world 重载清空所有选择和
编组。集合覆盖整个 Game actor 池，不另设小队人数上限。卡片分页只影响展示。

本地玩家和普通友方 AI 可选，敌人、基地核心与开发者展示角色不进入集合；倒地友军可查看，但不接收移动。
左键点选，空地取消；左键拖动矩形按屏幕中的身体中心选择，Shift 点选/框选追加。所有 UI 热区先消费输入，
框选必须从世界区域按下开始，鼠标释放完成；暂停、失焦、通讯焦点、视角切换或右键取消未完成拖动。
Windows 轮询保留本批第一次按下边沿和坐标，后续移动/松开不覆盖起点；最终指针和按住状态仍用于结束拖动。
因此按下、拖动和松开落在同一慢帧内时也能完成选择。UI 拦截按下起点，悬停使用当前指针。
失焦判断读取平台当前焦点快照，不能只等待启动界面可能已消费的首次焦点事件。

默认 `1…9、0` 召回对应编组，`Ctrl + 数字` 用当前选择完整重设该组，未选中的旧成员移出；空选择时清空该组。
编组条也支持左键召回、Ctrl 左键重设/清空。一个单位可以属于多个编组，重设不影响其他组。数字动作在 RTS 内优先消费，
FPS 武器槽仍使用原绑定。主选默认是集合中第一个有效单位；悬停只高亮并显示简略信息，不改变选择或移动对象。
编组条从左到右仍对应 `1…9、0`，格内仅显示有效人数，不显示组号。

## 权威移动

`RF_PLAYER_RTS_MOVE/STOP` 遍历身份仍有效的选中成员，交给 `rasterfall_session_rts_order_actor()`。
session 校验运行模式、存活、阵营、身份、剧情移动约束、目标地面支撑和碰撞。多选按稳定顺序分配小型方阵
落点，偏移落点不通行时尝试原点击点；结果报告实际接受指令的人数。`rts select N` 的 N 是 actor 槽位，
`-1` 清空，`0` 是本地玩家。

本地玩家目的地仍归 session；普通 AI 的 `command_destination_active/command_x/command_z` 是 Game
权威移动意图，在普通 AI 固定步内优先于出生部署和副官跟随，复用既有个体寻路、碰撞、持枪、索敌和开火。
到达后留在目标附近；停止把目标设为当前位置。选择、镜头和 UI 不推进第二次玩法或动画。FPS 切换不撤销
AI 已接受的命令，本地玩家在 FPS 期间由手操输入接管。RTS 指令目前仅在离线 session 开放。

旗帜保留物件、购买、携带和区域查询用途；旗帜搬动、携带、雇佣与初始 roster 不再给队友写入旗帜部署点。
正式 session 的 actor 没有旗帜 assignment，旧商店 assignment 请求拒绝；菜单该页解释 RTS 操作。
Hurd 状态查询按其 roster 身份统计人员，旗帜区域条件仍是该任务自己的只读条件，不控制单位路线。

## 只读展示

`rf_ui_layout_resolve()` 同时服务绘制和命中。底栏依次为单位信息、单位镜头、操作区，编组条位于信息框上方。
单选左侧为角色实际 body bind mesh 生成的线框，绿/黄/红对应当前生命比例，右侧按数据行显示名称、武器、
生命、回避、弹药与状态。`rf_rts_portrait.c` 首次读取对应模型生成小型只读网格遮罩后立即释放资源；
HUD 以 canvas run 绘制，不上传 CPU HUD 图像、不修改世界中的姿态。多选使用同一身体图标和独立生命条，
滚轮或翻页按钮浏览，点击卡片单选。增加属性可扩展信息行，增加角色沿正式 character profile/recipe 选择模型。

绿色脚底圈、目标菱形和连线由当前 actor 与真实命令目标投影到 HUD；连线表达移动意图，不承诺实际寻路路线。
标记和框选轮廓不会覆盖底栏及视频。地形与玩法支撑保持原来的分层。

单位镜头调用 `rf_story_actor_camera()` 复用剧情镜头参数和墙体光路检查，每次取当前主选单位的位置与高度；
不申请剧情 hold，也不强制演员转向。GPU WORLD 子视图读取与主视图同一份冻结世界，沿原 2:3 画幅和低频刷新
合同合成到信息框与操作区之间。RTS 单位镜头使用独立 AUX 槽，与剧情镜头同时显示，各自持有身份、刷新与失败状态。
原通讯/设备槽仍优先设备预览。收起底栏、取消选择、镜头失效或换世界只停止对应视频；CPU 后端显示
镜头不可用。来源身份变化先清除旧 live 状态，新画面成功后才显示实时视频。

## 原生验证

选择/编组的整池容量、重设与组间独立、身份失效、框选方向和阵营过滤，以及移动/停止/旗帜独立性进入逻辑回归。
`tools/rts_command_check.py` 通过目标窗口的 Win32 → SDL 输入，检查真实道路小组、点选、框选、编组重设、
召回、卡片单选、悬停不改选择、逐成员移动与停止，保存 GPU capture 和实际进程退出码。审计只读取状态，
不注入玩法命令；窗口必须取得前台且系统鼠标定位成功，权限不足或失焦时停止测试，不向其他窗口发送全局按键。
全屏验证使用实际 `--fullscreen` 或 F11，物理鼠标路线不补投鼠标消息；短手势检查同批按下/松开的保留。
原生操作与退出规则仍见 [Windows Native](../guides/windows-native.md)。
