# 私有角色分部件创作

> 状态：当前
> 所有者：Rasterfall 离线角色创作工具

本页拥有创作源、部件修订和组装的边界；运行时合同仍由
[角色资产](../reference/character-assets.md)拥有。操作入口见
[分部件工作流](../guides/character-parts.md)。

## 所有权与数据流

```text
独立部件源 + 单一骨架/动作 + 只读空间接口 + 固定审阅场景
                        ↓ assembly.json 锁定版本和哈希
                    分件角色 .blend
                        ↓ 一次性中性导出副本，按完整材质签名合批
                    GLB → RFCHAR → RFM2
```

`tools/blender/rf_character_parts.py` 是公共编排入口，`rf_parts/` 负责语义指纹、版本保存、
组装、审阅和导出。角色造型、配方及源资产留在本地 `private-assets`；公共工具不包含私有几何。
正常组装只加载清单锁定的部件，不执行生成器，也不读取历史 `design-v*` 目录。

RF-C01 的当前创作根为 `rasterfall/private-assets/source/characters/rf_c01/authoring/`。
`assembly.json` 是迁移后的初始组装；`assembly-<part>-<revision>.json` 表达局部修订候选，
下一轮显式选择所需清单继续。不会自动覆盖旧版本或把试验候选提升为默认。

## 部件与源真值

| 部件 ID | 拥有内容 | 编辑方式 |
| --- | --- | --- |
| `head` | 连续头脸、眼睑与嘴唇表面、颈部、耳朵子件 | 编辑冻结网格；保持连续表面，不按五官切断 |
| `eyes` | 眼球、虹膜、高光、眉毛、独立睫毛与下眼缘子件 | 编辑冻结网格；不写脸部表面 |
| `mouth` | 当前口腔暗面；后续口腔组件归属 | 编辑冻结网格 |
| `hair_base` | 覆盖头皮的底层 | 独立程序配方 |
| `hair_front` | 刘海及前侧发束 | 编辑冻结网格 |
| `hair_back` | 侧后发束 | 独立程序配方，逐束稳定 ID |
| `body` | 当前身体、服装、手套、靴子与随身小件 | 整体冻结，按后续需求再细分 |

每个对象有稳定 `part_id`、`object_id` 和 `part_revision`。显示名称、蒙皮 `weight_region`
及骨骼权重不定义部件归属。首次迁移可识别旧名称；正常流程不再通过名字或头颈权重切模型。

`editable_mesh` 部件以清单指定的 `.blend` 中网格、UV、权重和离线表情 key 为真值；先另存工作副本，
再发布新版本。旧控制网格留在历史目录，不作为当前源的隐式生成依赖。
`procedural` 部件保存独立生成器、参数入口及冻结网格；修订记录实际参数、代码哈希和上版哈希。
当前头发生成器只更新既有拓扑的坐标，保留 UV、材质和权重；拓扑不符时拒绝，需要显式迁移。

## 共享边界

- `interfaces.json` 拥有米制坐标、头部空间、眼部定位、头皮参数及颈部连接基线。改变头围、眼位、
  发际线或颈部连接需显式修订接口及依赖部件，不能通过一次普通局部发布隐式传播。
- `rig/` 唯一拥有骨架、rest、socket 与动作。部件文件不携带 Armature；保留顶点组，组装时统一绑定。
- 材质实例按部件隔离；脸部与身体即使同色也不共享可编辑实例。导出按 `export_id` 与完整已支持
  材质签名共同合并，不按名称后缀或显示颜色猜测相等。公共指纹器遇到未支持的嵌套 shader group
  或网格属性会拒绝，先补充合同再使用。
- 表情生成是显式操作，只可修订 `head`、`eyes` 或 `mouth`。头部闭眼采样读取冻结眼球表面，
  不写眼球；头发重建、组装及导出均不重建表情。RFCHAR 导出继续排除 morph。
- 离线审阅可使用 `<表情名>Mid` 表达强度 0.5 的独立姿态；审阅器在 Basis、Mid、终点之间分段插值，
  不把穿过眼球的端点直线插值当成正确中间态。该约定不增加运行时 morph 或部件驱动器合同。
- `review/` 拥有相机、灯光、地面、色彩管理和渲染设置。普通局部修订不能改变这些设置。

## 隔离验证

清单同时锁定文件 SHA-256 和逐对象语义记录：坐标、拓扑、法线、UV、网格属性、权重、材质、
变换、可见性、修改器及表情 key。骨架、动作关键帧和审阅场景另有记录。Blender 保存字节不同
不等于几何改变，因此同时保留文件锁与语义比较。

`verify --baseline ... --allow ...` 要求清单和组装一致，并检查未声明部件、骨架、审阅场景与
空间接口保持。`publish` 从完整角色工作副本提取部件时，也拒绝其中其他部件的修改。
它不把手工拓扑修改后的表情自动修复；修订者需要显式重建并审阅相关表情。

几何不变不能保证改发型后脸上的阴影、遮挡和整体观感不变。局部审阅同时检查完整角色与隐藏头发
的结构视图；换头围或眼位仍需检查接缝、穿插及表情。离线一致性不代表已完成游戏 GPU 接入。
