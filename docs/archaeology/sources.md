# 证据与方法

## 证据等级

按下列层次保存材料，不把不同性质的证据混写成确定事实：

1. **对象级证据**：提交对象、父提交、树、blob、tag、构建产物及可复现命令输出。
2. **仓库内陈述**：提交说明、README、CLAUDE.md、脚本注释和历史文档。
3. **外部同期材料**：GitHub 页面、issue、release、聊天记录、API 日志、账单和本地工作日志。
4. **作者回忆**：作者对动机、工具、过程和感受的口述。
5. **研究者推断**：由若干证据拼出的解释，必须注明推断过程和不确定性。

提交说明属于同期陈述，不等于其宣称的功能已经被独立复现。`Co-Authored-By` 只说明提交元数据
显式署名，不应用来计算某个工具生成了多少代码。

## 叙事约束

考古文档的目标不是为过去的项目追加评价，而是解释能力、决策和工作方式如何变化。综合性叙事遵守
以下约束：

- 每个成果都写明验证范围，不用提交数、工作时长或功能数量代替价值判断。
- 每个时期保留失败、workaround、误判或未解问题，并区分“当时如何理解”与“事后如何解释”。
- 区分代码继承、知识连续和因果影响；后续项目出现相似设计，不自动证明它来自早期经历。
- 分开团队能力、提交归属、个人实现和外部来源，不由最终提交者或后续项目所有者倒推功劳。
- 项目排名、“最强”、影响他人等评价，如无完整对照和外部证据，只作为作者观点保存，不用来论证历史价值。
- 综合文章应提炼对其他开发者仍有用的问题或方法；删去人名后若只剩个人成就陈列，就不应纳入专题叙事。

## 收集范围与停止条件

本计划首先服务于 Toyc 自身：保存 Tinylibc、ToyCCompiler、Toyc 之间的传承与演进，固定足以支撑
核心结论的 Git 记录，并记录 Git 之外容易随时间遗忘的动机、失败和工作方式。资料收集采用风险与
价值驱动，而不是尽可能保存全部原始文件；严格独立复现实验现场也不是完成条件。

SC7、赛事、课程、论文和上游参考实现只调查到能够约束 Toyc 主线结论、贡献边界或来源声明的程度。
当新增材料只会增加旁支细节，不会明显改变 Toyc 的谱系、关键阶段或工程解释时，可以明确记录缺口
后停止。未来自然出现重要材料时仍可修订，但缺少旁支档案本身不构成未完成状态。

## 常用复查命令

```sh
git clone --no-checkout https://github.com/WHU-SC7/SC7.git ../SC7
git -C ../SC7 log --all --reverse --date=iso-strict
git -C ../Tinylibc log --reverse --date=iso-strict
git -C ../ToyCCompiler log --reverse --date=iso-strict
git log --reverse --date=iso-strict
git show --stat --summary <commit>
git diff --no-index <old-tree-path> <new-tree-path>
git log --follow -- <path>
git blame <commit> -- <path>
```

克隆命令只用于说明如何建立可选缓存；执行前应确认目标目录不存在。已存在缓存时先核对 `remote -v`
和目标分支，不应假定它自动包含远端后来新增的对象。

跨仓库比较不能只看文件名。应先固定两端提交，再对目录树做 hash、相似度和语义对照，并记录
重命名、格式化、生成文件与二进制种子等干扰因素。
